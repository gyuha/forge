# Recovery branches — in-flight resume · parked-failure unpark · early-exit handoffs

> Loaded by `fg-run` **only when one of these conditions is actually met**. The normal start (promote → build → run) never reads this file.
> Split out of `SKILL.md` for token efficiency on the common path; **behavior is unchanged** from when it lived inline (the same arrangement as `./RUN-ALL.md`).
> **Section references**: `§N`, `step N`, and any "above" that names a section not present in this file all point to [`SKILL.md`](./SKILL.md)'s numbered sections — the numbering is unchanged by the split.

Enter this file when any of these holds — the entry conditions themselves stay in `SKILL.md`:

- `.forge/running.md` exists and `.forge/run.md` does not → **step 4a** below.
- The active slot is empty and some `.forge/executed/*/STATUS.md` carries `verified: failed` → **step 5** below.
- A branch is about to end the turn **without** handing off to the retro → **Early-exit handoffs** below.

**4a) In-flight resume — `running.md` present, `run.md` absent.** The **in-flight marker** `.forge/running.md` is written by §2 immediately before launch and deleted by §4 right after `run.md` lands; if it is still there without a `run.md`, a previous turn (or session) reached the launch boundary and never collected a durable result. This is **not** a normal start and **not** a re-run — nothing may be rebuilt silently. First compare its `forge-running:` slug with the active plan's slug. A mismatch is an orphaned marker: report it, delete it without confirmation, and return to the normal-start path for the active plan. Otherwise read `workflow:` (the host's resumable handle or handles when available, or `pending`) · `started:` · `session:`, then ask the matching host adapter to blocking-collect those handles and branch on the **first matching result**:

1. **Still running** → wait for it in this turn and continue at §3 when it completes.
2. **Completed** → collect the result and continue at §3 (cross-verify → `run.md` → STATUS → UAT). Do not launch anything new.
3. **Unknown, uncollectable, or collection error** — including another session, `workflow: pending`, an unavailable recorded handle, or a host with no resumable handle → show the marker's age from `started:` and say that the execution may still be running elsewhere and its side effects may or may not have landed. If it is younger than one hour, the default recommendation is to wait and inspect with fg-status rather than rebuild. Ask once whether to rebuild and re-run; **only an explicit yes** may take that path. On yes, delete `running.md` and enter §1 as a normal start; this is an explicitly approved re-run, not an aborted result. An unattended orchestrator (`fg-next all` or `fg-loop`) cannot answer this confirmation on the user's behalf and must stop at its uncollectable-execution wall.

If the user explicitly wants to stop a still-live execution in this session, use the adapter's cancellation operation on its recorded handle or handles, then follow the aborted-run procedure in §4: first write `run.md` with the slice where execution stopped and every observed side effect, write `STATUS.md` with `verified: failed (aborted — <reason>)`, then delete `running.md` and take §4's failed route. Never delete the marker alone for an actual cancellation. On a declined rebuild, leave everything in place and close with the handoff table (see "Early-exit handoffs" below). fg-drop remains the explicit discard path, and fg-doctor A10 flags stale or orphaned markers. Rationale: ADR `260909-150614`.

**5) Failed parked-task recovery (unpark).** fg-run is the **single owner** of returning a `failed` task to execution, because it is the only stage that runs work — fg-learn and fg-done both *block* `failed`, and fg-run otherwise reaches only the active slot/backlog, never `executed/`. So if a parked `.forge/executed/<slug>/STATUS.md` carries `verified: failed` (a task whose cleanup-time or learn-time recovery UAT recorded `failed` — Run-all itself never parks a failed task; it leaves it in the active slot, see RUN-ALL.md), **unpark it before working on it** — but only when the active slot is free. If the slot is occupied, do not unpark: tell the user the parked failed task waits in `executed/` until the active task's loop finishes (verify → learn → seal via fg-done), after which re-entering fg-run with an empty slot surfaces it automatically as the top recovery candidate (step 2) — close that report with the handoff table (see "Early-exit handoffs" below). When the slot is free, move `executed/<slug>/{plan,run,STATUS}` → `.forge/{plan,run,STATUS}.md`, then enter step 4 above (its `verified: failed` branch routes to fix-and-re-run, or re-grill via fg-ask). This is the documented exit from a parked failure; fg-learn/fg-done/fg-status point here for it.

**Early-exit handoffs.** Every branch above that ends the turn **without** handing off to the retro — 0 candidates, the verification-only resume, `verified: failed`, a blocked unpark, a duplicate run the user cancels — closes by **rendering the handoff table**, whose shape is defined once in [`../fg-next/HANDOFF.md`](../fg-next/HANDOFF.md) (or `${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/skills/fg-next/HANDOFF.md`); reference it, never restate the layout here. Fill the cells from that branch's own routing, render it in the user's language, and keep it **statement form** — it is text output, never an `AskUserQuestion`, and `Alternative` states that another route exists rather than asking which to take (ADR-0015). The step-2 selection of a backlog task (2+ candidates) is **not** a handoff — it is a deliberately retained menu and keeps its `AskUserQuestion`. Where the cells genuinely differ:

- **0 candidates (step 2) · cancelled duplicate run (step 4)** — nothing is in progress, so `Next step` is fg-ask (define the task, grill it, produce a plan); there is no second route, so omit `Alternative`.
- **Waiting or declined in-flight rebuild (step 4a)** — the marker and plan stay in place, so `Just did` = an uncollectable in-flight execution was found and left untouched, `Next step` = wait and inspect with fg-status (or re-enter fg-run when ready to make the rebuild decision), `Alternative` = discard the task with fg-drop. Never name fg-learn or sealing — nothing has run to completion.
- **Verification-only resume (step 4) — one table per outcome, never one table covering both.** On a **sealable** outcome (`yes`/`skipped`/`n/a`): `Just did` = the interrupted UAT was completed and `verified:` recorded (nothing was re-executed), `Next step` = fg-learn, and the divergence rule in "Next-flow handoff" fills `Alternative` unchanged. On a **`failed`** outcome: `Next step` = fix-and-re-run via fg-run, `Alternative` = re-grill via fg-ask — and **no cell may name fg-learn or sealing** (ADR-0009: `failed` never reaches the retro).
- **`verified: failed` found by the re-run guard (step 4)** — the same table as the resume's `failed` outcome.
- **Blocked unpark (step 5)** — informational, so the table must not instruct the user to do the thing that is blocked: `Just did` = a parked `failed` task was found in `executed/` and waits until the slot frees, `Next step` = finish the **active** task's loop (which step that is — verify, retro, or seal — comes from fg-status's state machine, per HANDOFF.md's material table), `Alternative` = re-enter fg-run once the slot is empty, where the parked task surfaces as the top recovery candidate.
