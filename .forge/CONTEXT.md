# forge

Claude Code 플러그인 forge의 도메인 글로서리. 루프 스킬들이 공유하는 용어를 정의한다.

## Language

**simple 모드 (simple mode)**:
`.forge/config.json`의 `simple: true`가 켜는 **자동 봉인 모드** — fg-run이 작업을 끝내면 검증(UAT) 후 회고를 무조건 skip(`retro: skipped (simple mode)`)하고 같은 턴에 봉인까지 잇는다. 사용자 체감은 ask → run 두 단계지만 verify·seal은 전부 돈다. 검증 게이트(ADR-0009)는 불가침 — `verified: pending|failed`는 자동 봉인하지 않는다.
_Avoid_: 단계 생략 모드 — done을 생략하면 활성 슬롯이 점유돼 루프가 닫히지 않으므로 생략이 아니라 자동화다, 경량 차선 — 그건 형식 산출물 자체를 안 만드는 fg-quick이다

**Visual Companion**:
그릴링·대화 중 mockup·다이어그램·시각 비교를 브라우저 탭으로 보여주는 선택적 표시 채널이자, 사용자의 클릭·텍스트 입력을 이벤트로 받는 **보조 답변 채널**. 두 채널(브라우저·터미널)의 답은 병합해 읽고 모순될 때만 되묻는다. **확정된 선택은 대화를 재개시킬 수 있다** — 사용자가 화면에서 선택을 확정하면 터미널 입력 없이 그 답이 도착한다(정착하지 않은 탐색 클릭은 아무것도 재개시키지 않는다). 그럼에도 브라우저는 **워크플로우의 런타임 입력이 아니며**, 그것이 기둥 1이 온전한 근거다.
_Avoid_: visual compose, 시각 브레인스토밍, 브라우저 모드, 표시 전용(입력도 받으므로), 터미널만이 대화를 재개시킨다(확정 선택도 재개시킨다)

**미봉인 잔여 (unsealed tail)**:
실행은 끝났는데 봉인되지 않아 루프가 닫히지 않은 작업. 활성 슬롯에 남은 `status: executed`가 이에 해당한다. **`executed/`의 park은 잔여가 아니라 의도된 대기**다 — 사람이 "나중에 회고하겠다"고 남긴 상태이므로, 잔여를 자동으로 닫는 경로는 park을 건드리지 않는다.
_Avoid_: 부채(debt) — 회계 은유가 "갚아야 할 의무"를 함의해 의도된 대기까지 싸잡는다, 미완 작업 — 백로그의 미실행 plan과 구별이 안 된다

**eco 요약 표 (eco summary table)**:
`eco: true`일 때 작업 종료 지점의 산문 핸드오프를 대신 차지하는 화면 출력 형태 — 헤더 한 줄(제목·검증·divergence) + `▸ 요청` + `▸ 수행`(슬라이스 표) + `▸ 다음`. 산문에 덧붙이는 게 아니라 **교체**한다.
_Avoid_: 요약 — 기존 **봉인 요약**과 섞여 "요약을 내지 마라"(위임 경로)와 "요약을 표로 내라"(eco)가 같은 단어로 충돌한다, 간결 출력 — 압축(ECO.md `Terse communication`)과 구별이 안 된다

**봉인 요약 (seal summary)**:
명시적 단일 `/fg-done`에서만 렌더하는 마감 요약(요구사항·처리 내용·조건부 회고·메타). 위임·배치 봉인 경로는 이를 내지 않는다(ADR-0032). [[eco 요약 표]]와 별개의 것 — eco on이면 이 요약이 표 형태로 렌더된다.
_Avoid_: 완료 알림(completion notice) — 그건 봉인 요약이 대체하는 더 짧은 종전 출력이다

**핸드오프 표 (handoff table)**:
스킬이 끝에서 다음 단계를 알릴 때 산문을 대신 차지하는 4행 표 — `방금 한 것` · `다음 단계` · `시작하는 법` · `대안`. 다음 단계 안내가 산문 사이에 묻혀 **찾기 어렵던** 문제를 형태로 해결한다(길이 문제가 아니라 위치 문제였다). **eco와 무관하게 항상** 적용되며, 적용 지점은 가리킬 다음 단계가 실재하는 13곳이다(토글·설정 3곳과 다음 단계가 없는 4곳은 산문 유지). eco on이면 `방금 한 것` 행을 빼고 3행 — 그 내용은 [[eco 요약 표]]의 `▸ 수행`이 이미 더 자세히 담기 때문이다. 표 셀에 안 들어가는 목록형(생성 문서 경로·후속 후보)은 표 **아래** 불릿으로 붙인다. 단일 정의는 `skills/fg-next/HANDOFF.md`.
_Avoid_: eco 요약 표 — 그건 eco 게이트 뒤의 **작업 종료 요약**(축이 슬라이스)이고 이것은 항상 적용되는 **다음 단계 안내**다(둘은 eco on에서 위아래로 함께 뜬다), 봉인 요약 — fg-done 명시적 단일 봉인에서만 렌더하는 마감 요약, **메뉴** — 표는 고르라고 내는 것이 아니라 알리고 멈추는 것이다(ADR-0015 진술형은 불변이며 `대안` 행도 질문이 아니다)

**의제 (agenda)**:
**아직 내리지 않은 결정**들의 대기열. 목적지 하나가 범위를 고정하고, 지금 답할 수 있는 열린 질문·아직 벼려지지 않은 안개·범위 밖을 함께 담는다. 결정만 소유하며 빌드 가능해지는 순간 그 줄은 백로그 plan이 된다. **캐내는 것은 에이전트, 답하는 것은 사람**이다. 길이 밝아지면 사라지고 영속 흔적은 그것이 낳은 ADR과 plan이다. `fg-agenda`가 만들고 [[fg-status]]가 한 줄 보고하며 `fg-ask`가 질문을 해소한다.
_Avoid_: 지도(map) — 그건 `fg-map`이 만드는 **코드베이스 지도**다, 차트(chart) — 한국어에서 도표·그래프로 읽혀 `fg-showme`의 영역과 섞인다(두 이름 모두 실제로 한 번씩 채택됐다가 이 충돌로 기각됐다 — ADR `260805-201313`), 백로그 — 그건 실행 대기 중인 **빌드** 계획이다

**문서 사이트 (docs site)**:
`docs/`의 Markdown을 VitePress가 빌드해 `/forge/docs/`에 서빙하는 사이트. 배포된 웹 표면은 둘이며 **랜딩 페이지**(`/forge/`, 손으로 쓴 이중언어 `docs/index.html` 한 장)와 역할·기술·언어가 모두 다르다 — 랜딩은 소개, 문서 사이트는 레퍼런스이고 v1은 한국어 단일이다. 둘은 한 GitHub Pages 아티팩트로 조립돼 함께 배포된다(ADR `260815-094725`).
_Avoid_: docs — 폴더(`docs/`)·Markdown 문서·배포된 사이트 셋을 한 단어가 가리켜 어느 것인지 알 수 없다, 랜딩 페이지 — 같은 아티팩트에 실려 나가지만 다른 것이다, 홈페이지 — 두 표면 중 어느 쪽인지 지시하지 못한다

**전진 체크 (forward check)**:
작업이 끝나면 참이 **되어야** 하는 DoD 항목. 작성·승격 시점에 이미 통과한다면 인코딩이 틀린 것이므로 다시 쓴다 — 슬라이스가 소유하지 않은 표면에 정확한 개수를 요구해 기존 매치가 예산을 먹은 경우가 전형이다. [[회귀 가드]]와 겉모습이 같고 판정만 반대다.
_Avoid_: 사전 상태 — 그건 체크의 *값*이지 종류가 아니다, 사전 점검 — 그건 명령을 돌리는 *행위*다, 신규 체크 — 회귀 가드도 새로 추가될 수 있다

**eval**:
루프의 학습(검증 실패·divergence·리뷰 발견)에서 승급되어, 작업이 봉인된 뒤에도 프로젝트 자신의 테스트 스위트(스위트가 없는 리포는 fg-doctor 검사 같은 상응하는 실행 착지점)에 살아남아 같은 실패의 재발을 막는 **기계 실행 가능한 영속 회귀 체크**. 승급 경로는 둘 — 판단 갈래(fg-learn의 네 번째 승급 목적지, 승급 바 3조건: 기계 확인 가능·재발이 그럴듯·실행이 저렴)와 기계 갈래(새로 작성되는 fix-forward plan의 DoD 형식 규칙 — 원래 실패의 red→green 증명). AI-native SDLC playbook의 "모든 인시던트가 영속 eval이 된다"를 forge 어휘로 옮긴 것.
_Avoid_: DoD 명령 — 봉인과 함께 아카이브로 죽는다(eval은 살아남는 것이 정의다), stop-check — fg-loop 드라이브 수명 동안만 사는 체크다, [[회귀 가드]] — 그건 plan 한 건의 DoD 항목이고 eval은 프로젝트에 남는 테스트/검사다

**회귀 가드 (regression guard)**:
작업 전후로 참이 **유지되어야** 하는 DoD 항목. 작성 시점에 이미 통과하는 것이 정상이므로 결함이 아니며, 그 이유를 항목 그 줄에 한 줄로 붙여 [[전진 체크]]의 오인코딩과 구별한다. 값이 변하지 않은 것이 통과다.
_Avoid_: 회귀 테스트 — 파일로 존재하는 테스트가 아니라 plan의 DoD 한 줄이다, 불변 조건(invariant) — 코드의 성질이 아니라 이 작업이 지키기로 한 관측값이다
