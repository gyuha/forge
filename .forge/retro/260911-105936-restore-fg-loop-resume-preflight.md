# 2026-09-11 — fg-loop 재개 preflight 도달성 복구, 그리고 같은 실패의 3연속

## 계획 vs 실제

- **계획대로 된 것**: 네 슬라이스 전부. `### Resume preflight`(2,934자)를 `INQUIRY.md`→`SKILL.md`로 **byte 동일** 환원(3개 렌즈 독립 대조), 스텁 거짓 서술 정정, dangling 포인터 `ALL-MODE.md`로 갱신, `CLAUDE.md` 규율 추가. DoD 10개 전부 통과. 수치 예측도 맞았다(48,502 예상 → 48,598).
- **차이**: run.md 기준 divergence는 낮았고 그 판정 자체는 방어 가능하다(추가된 것은 범위가 아니라 검증 한 단계였고 은폐 없이 기록됐다). **그러나 적대적 리뷰가 그 판정을 무의미하게 만들었다** — 계획대로 실행했는데 **계획이 놓친 것**이 9건(수정 필요 6건) 나왔다. 낮은 divergence는 "계획이 옳았다"를 뜻하지 않는다.

## 학습

### 1. 같은 실패를 하루에 세 번 반복했다 — 전부 "대리 지표를 진짜 검증으로 착각"

| # | 어디서 | 검사한 것 | 놓친 것 |
| --- | --- | --- | --- |
| 1 | task 152 분할 | 크기·총량·링크·frontmatter·doctor — **8개 전부 초록** | preflight 도달 불가로 v0.9.1 출하 |
| 2 | task 153 DoD 2 ("핵심 체크") | `###` 헤딩 + `Resume\|re-trigger` 키워드 | **S1 완료 즉시 도메인이 공집합**. 같은 부류 4건이 문단이라 전부 0점 통과 |
| 3 | task 153 CLAUDE.md 규율 | "하위 절 단위로 판정" | **"하위 절" 미정의**. `RECOVERY.md`는 `###` 0개인데 분기 3개를 굵은 문단으로 담음 — 규율이 자기 동기 사례에서 공허 |

2번과 3번이 특히 뼈아프다: **둘 다 1번을 고치려고 만든 것**이면서 같은 방식으로 실패했다. 그리고 3번은 plan의 Non-goals에서 `RECOVERY.md 하위 절 0개`를 **건전성의 근거로 인용**하기까지 했다 — 규율이 공허하게 통과한다는 바로 그 증거를 안전 신호로 읽었다.

**다음에 할 것**: DoD 항목을 쓸 때 **"이 술어의 도메인이 작업 완료 후에도 비어 있지 않은가"** 를 먼저 묻는다. DoD 2는 S1이 끝나는 순간 `###` 개수가 0이 되어 DoD 1의 재진술로 퇴화했다 — 작성 시점에는 보이지 않지만, "완료 후 이 체크는 무엇을 세는가"를 물으면 즉시 드러난다.

### 2. 틀린 단정은 애매함보다 나쁘다

152는 "skip this section entirely"라 **애매**해서 에이전트가 조심스레 companion을 열 여지가 있었다. 153에서 내가 그것을 **"do **not** read `INQUIRY.md`" + "The resume path is therefore complete from this file alone"** 으로 못박았고, 그 문장은 **거짓**이다(원장 `×N` 규칙·Reflexion 쓰기 규칙·`waiting` 회계·`/goal` 진입 규율이 여전히 `INQUIRY.md`에만 있다). 확신에 찬 거짓 보증은 다음 독자가 확인할 이유를 없앤다.

**다음에 할 것**: 문서에 **완결성 보증**("X만으로 충분하다", "complete from this file alone")을 쓸 때는, 그 문장 자체를 DoD 항목으로 만들어 검증하거나 쓰지 않는다. 보증은 관측이지 의도가 아니다.

### 3. "기계 검증 불가"를 성급히 단정했다 — 기각 사유를 정정한다

그릴링에서 기계 가드를 기각하며 "일반형이 기계 검증 불가"라고 적었다. 렌즈 6이 반박했고 검증 결과 맞다 — **극성 검사(polarity check)** 라는 부분 가드가 존재한다: 동반 파일 머리말의 선언된 로드 조건에서 상태 파일 토큰을 뽑고(`only when .forge/loop.md does not yet exist` → `loop.md`), 본문이 **반대 극성**을 주장하는 줄(`If .forge/loop.md exists, …`)을 찾는다. v0.9.1 결함을 **실제로 잡았을** 검사이며 ~20줄이다.

**내가 한 것은 값싼 대안을 비싼 대안(특정 제목 하드코딩)으로 바꿔치기해 기각한 것**이다. 올바른 기각 사유는 "불가능"이 아니라 **"부분 커버리지 + 비용"** 이다 — 실제로 이 검사는 C1의 네 항목(`loop.md`를 명시하지 않음)을 못 잡는다.

**다음에 할 것**: "기계로 못 한다"를 결론으로 쓰기 전에 **가장 값싼 부분 가드 하나**를 구체적으로 설계해 본다. 못 만들면 그때 단정한다.

### 4. 적대적 리뷰가 자기검증보다 강했다 — 그리고 그 이유가 구조적이다

나는 `run.md`에 "DoD 1·2는 대리 지표이지 증명이 아니다"라고 **스스로 적고**, 그래서 자기완결성 직접 확인을 추가했다. 그런데 그 추가 확인조차 **이미 아는 결함의 범위**(옮긴 절의 배치 순서·벽 리셋 지시 존재·소비자 도착점)만 봤고, 남은 4건을 놓쳤다. 6개 렌즈 중 4개가 **독립적으로** 같은 결함에 수렴했다.

**다음에 할 것**: 자기검증은 "내가 고친 것이 고쳐졌나"를 묻는 경향이 있다. 같은 부류가 더 있는지는 **적대적 자세**(결과가 틀렸다고 가정)에서만 나온다. 분할·이동처럼 **같은 실수가 복수로 존재할 수 있는** 작업은 봉인 전에 `fg-adversarial-review`를 기본으로 돌린다.

## 문서 갱신

- **CONTEXT.md 승급: `도달 가능성 (reachability)`** — 오늘 세 번 반복된 실패에 이름이 없어 매번 새로 발견했다. `전진 체크`·`회귀 가드`·`eval`과 같은 DoD 어휘 층위에 배치하고, 대리 술어(헤딩·키워드) 함정을 항목 안에 명시했다.
- **ADR 추가: 없음** — 세 조건 중 "되돌리기 어렵다" 미달. 검증 방식은 규율 한 줄이고 `RUN-ALL.md` 선례처럼 조정 가능하다.
- **eval 승급: 보류(재그릴로 이관)** — 극성 검사는 세 조건(기계 확인 가능·구조적 재발·저비용)을 넘지만 `fg-doctor` 트윈 2개 + behavior/parity 테스트가 필요해 인라인 불가다. 그리고 리뷰의 M2(DoD 술어)·M3(규율 단위)와 **같은 하나의 문제**("조건부 분할을 어떻게 검증하나")이므로 별도 백로그 계획을 만들지 않고 이어질 fg-ask 재그릴의 입력으로 넘긴다.

## 후속 (적대적 리뷰 findings — `.forge/review.md`)

수정 필요 6건이 미해결로 남는다. 재그릴에서 다룬다:
- **C1**(critical) 재개 경로가 여전히 `INQUIRY.md`에 의존 + 내가 넣은 거짓 완결성 문장
- **M1** 스텁의 두 번째 거짓 소유 주장(check-health probe)
- **M2·M3** DoD 술어와 CLAUDE.md 규율의 단위 — **설계 결함이라 fix-forward로 덧칠 불가**
- **M4** 옮긴 절 첫 문장이 자기가 속한 절을 건너뛰라고 지시 · **M5** `INQUIRY.md` 머리말이 여전히 preflight 우회 승인
- **m1** `SKILL.md:55` 조건부 dangling · **m2** `CLAUDE.md` 빈 줄(surgical changes 위반)

v0.9.1은 1·2번 학습의 결함을 **현재 출하된 상태로** 담고 있다(워킹 트리가 모든 실질 항목에서 더 낫다 — 유일한 예외가 내가 넣은 거짓 문장).
