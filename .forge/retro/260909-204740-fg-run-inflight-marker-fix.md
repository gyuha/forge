# 2026-09-09 — 실행 중 마커의 소비자 공백과 재진입 판정을 닫음

## 계획 대비 실제
- 계획대로 된 것: `running.md`의 봉인·회고·무인 주행·중단 소비자 계약을 연결했고, 셸/Node 트윈과 전체 20개 스크립트 스위트, doctor, release-check, 문서 빌드로 결과를 검증했다. 재발 가능한 결함은 봉인·SessionStart·doctor 회귀 픽스처로 남겼다.
- 차이: 계획은 Codex 위임 호출을 동기 대기로 가정했지만 실제 계약은 agent handle을 반환한 뒤 list/wait로 수집하는 방식이었다. 이에 호스트 어댑터 책임을 바로잡고, 재진입 벽을 다른 세션에 한정하지 않고 모든 unknown/uncollectable 상태로 넓혔다. 고아 marker 위험도도 실행이 계속될 수 있다는 점을 반영해 low에서 high로 교정했다. 실행 전 일부 구현이 이미 존재해 최초 red를 재현하지 못한 구간은 mutation 실패와 체크섬 복원으로 가드의 실재를 확인했다.

## 학습
- 다음에 다르게 할 것: 계획을 고정하기 전에 각 호스트의 실제 위임·수집 의미를 어댑터와 도구 동작으로 먼저 검증한다. 새 상태 마커를 도입할 때는 생성·수집뿐 아니라 봉인·삭제·회고·새 작업 시작·무인 오케스트레이터·영속 문서까지 소비자 목록을 작성한다. 경계 테스트에는 정상값뿐 아니라 잘못된 타입, JSON 이스케이프, 큰 epoch, 파일 교체 경쟁을 포함한다. 선행 partial 때문에 TDD red가 사라졌다면 그 한계를 명시하고 mutation으로 회귀 가드의 민감도를 증명한다.
