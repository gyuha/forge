# 2026-08-22 — /goal 없는 주행 연속성 part 1/2: Stop 훅 메커니즘 (#123)

## 계획 ↔ 실제

- **계획대로 된 것**: 6 슬라이스 전부. TDD로 exit-code 계약을 먼저 고정(red 0/10 확인 후 구현), 트윈 2개가 각각 10/10, parity 16/16 동일, `hooks.json`에 `Stop` 항목(기존 `SessionStart`·디스패처·테스트 전부 불변), ADR-0028 개정. DoD 11/11. **no-op 실증까지 계획대로** — 마커 없는 실제 리포에서 훅이 `exit 0` 무출력이므로 출하돼도 동작이 안 바뀐다.
- **차이 5건** (전부 실행 중 발견이며 계획 위반 없음):
  1. **bash 트윈이 stderr를 흘려 테스트가 잡았다.** `awk … > "$tmp" 2>/dev/null`에서 `>`는 셸의 리다이렉션이라 awk에 붙인 `2>/dev/null`이 "permission denied"를 못 잡는다. 읽기 전용 디렉터리에서 bash 자신의 에러가 새어 **exit 0인데 출력이 있는** 상태가 됐다. `{ …; } 2>/dev/null` 그룹으로 수정.
  2. **parity 케이스를 2 → 16으로 늘렸다.** 계획은 CRLF·다중자릿수만 명시했으나 상한이 부등호 방향에 민감해 **정확히 경계**를 추가했다 — 반복 49(허용)/50(차단), 시간 1800초(허용)/1801초(초과), 시계 역행, 중복 필드, 비-JSON 페이로드.
  3. **훅 본체의 stdin 읽기에 선례가 없었다** — 기존 `forge-hook-session-start.sh`는 stdin을 안 읽는다(`grep -c 'stdin' → 0`). 새 관례를 만들고 **tty일 때 매달리지 않도록** `[ -t 0 ] ||` 가드를 넣었다.
  4. 마커 `started`를 ISO가 아니라 **epoch 초**로 (그릴링 결정, 근거를 run.md에 기록).
  5. `run-hook.test.sh`를 `scripts/`에서 찾아 "깨졌다"고 오판 — 실제 위치는 `hooks/`이고 22/22 통과 중이었다.

## 학습

- **다음에 다르게 할 것 — 훅에서 stderr는 위생이 아니라 계약이다.** Stop 훅은 `exit 2`로 차단하고 **그 stderr가 곧 차단 메시지**가 되므로, "exit 0이면 무출력"은 스타일이 아니라 지켜야 하는 불변식이다. 이번에 그걸 **assertion으로 강제한 테스트가 결함을 잡았다** — 리뷰로는 못 봤을 종류다(`>` 리다이렉션의 stderr가 누구 것인지는 코드를 봐도 안 보인다). 부작용이 있는 스크립트를 쓸 때 "성공 시 무출력"을 테스트에 넣는 것이 값을 한다.
- **다음에 다르게 할 것 — 상한이 있는 계약의 parity는 *정확히 경계*를 넣어야 한다.** 안/밖만 테스트하면 `>`와 `>=`를 두 트윈이 다르게 써도 초록이 뜬다. 1800(허용)·1801(초과)·49(허용)·50(차단)처럼 경계 양쪽 한 칸을 넣어야 그 차이가 드러난다. ADR-0022의 parity 규약에 한 줄 추가할 후보다(아래 후속 후보).
- **확인된 것 — 세션 시작 시 로드되는 능력은 「출하」와 「배선」을 쪼개면 출하가 무해해진다.** 훅은 ADR-0024의 에이전트 카드와 같은 제약(세션 시작 로드)을 갖는다. part 1을 **마커를 쓰는 주체 없이** 출하하면 훅은 항상 exit 0이라 동작이 안 바뀌고, 사람이 재시작해 훅의 실재를 확인한 뒤 part 2가 *증명된* 훅 위에 배선한다. 이 분할이 실제로 값을 했다 — 검증할 수 없는 것 하나(훅이 정말 로드되나)만 남기고 나머지 전부를 이 세션에서 확인했다. **세션 경계에 걸린 능력을 만들 때 재사용할 패턴이다.**
- **안전 설계가 하네스와 결이 같으면 공짜로 강해진다.** 하네스는 exit 0을 진행, **exit 1도 비차단 오류로 진행**, 2만 차단으로 처리한다. 그래서 "모든 실패·모호 경로는 exit 0"이라는 불변식을 세우면 스크립트가 죽어도(1) 세션이 갇히지 않는다. 반대로 하네스는 **Stop 훅에 루프 보호를 전혀 주지 않으므로**(`stop_hook_active` 류 없음) 시간·반복 상한은 forge가 전부 져야 한다 — 위험과 해법이 같은 조회에서 나왔다.
- **기각된 대안을 다시 제안할 때는 기각 사유를 조항별로 반박해야 한다.** ADR-0028이 이미 "스킬이 settings.json에 Stop hook 자동 설치"를 기각해 뒀다. 그릴링에서 그걸 발견해 세 사유(settings.json 자동 설치 / 영속성 / 죽으면 멈춤 불가)에 각각 대응하는 표를 개정문에 넣었다. **안 했으면 미래 독자가 ADR과 모순되는 결정을 다리 없이 만난다** — ADR 기각 목록은 읽어야 하는 자료이고, 뒤집을 때는 새 ADR이 아니라 개정이다.
