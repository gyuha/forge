  - S1(루프 4스킬)+S2(14 유틸리티) 18개 description을 트리거 코어(무엇+언제+트리거 문구+형제 구분)만 남기고 살(ADR-NNNN 참조·상세 동작·근거·에세이) 절단. ADR-NNNN 참조 grep = 0(전부 본문으로 이동).
  - S3: 새 ADR `260716-22a-skill-description-dual-use-trigger-core.md`(시간ID dogfood)로 이중-용도 필드/트리거-코어 규약·메커니즘·트레이드오프 기록.
  - name 18/18·매니페스트·CLAUDE.md 무변경(Non-goals 준수), fg-doctor clean 0/0/0.
- Divergences:
  - **목표 길이 ~350자 → 실제 279–591자.** 한국어 트리거 문구(3바이트 문자)+형제 구분을 보존하면 ~350은 대부분 비현실적임을 트림 중 확인. 목표가 소프트였고 "was 325–1229 → 절반 이하, 완결·스캔 가능"은 달성 → 의도 범위 내 divergence.
  - **#83 lint 임계값 ~400 추정 → 실측 최대 591 기반 ~600으로 개정.** "A(트림)가 B(lint)의 임계값을 정한다"는 소프트 의존이 실제로 작동.
  - **적대적 리뷰 MAJOR 1건(제자리 수정):** ADR-260716-22a에 임계값이 `~500`으로 잘못 박혀 있었고(실측 591) 휘발 run.md엔 `~600`으로 옳게 있었음 → 지속 문서(ADR)를 실측(279–591)·임계값 ~600으로 정정해 ADR↔run.md 정합.

## Learnings
- Do differently next time:
  - **한국어 트리거를 보존하는 description의 실무 하한은 ~300자대가 아니라 ~500–600자다.** 앞으로 "메뉴 2줄 이내"류 char 목표를 세울 때 한국어 발화+형제 구분 보존 비용을 먼저 계산할 것. 고정 char 강제 대신 소프트 목표+lint 감지가 옳았다.
  - **같은 숫자가 지속 문서(ADR)와 휘발 문서(run.md) 양쪽에 있으면 어긋난다 — 그리고 하류 작업이 읽는 건 지속 문서다.** #83 lint는 ADR의 임계값을 읽지 run.md를 읽지 않으므로, ADR에 박힌 틀린 ~500이 방금 트림한 description 5개를 즉시 warning으로 flag할 뻔했다. 적대적 리뷰가 이 자기파괴 모순을 잡았다 — 숫자를 지속 문서에 쓸 때 휘발 근거와 반드시 동기화.
  - **자동-발동 정확도는 단발 테스트 불가한 "행동 베팅"이다.** 리뷰는 "트리거 코어 보존"까지만 담보하고 실효는 실사용 관측 — #83 lint가 미래 재-비대화를 기계 감지하는 가드로 남는다.
- 후속 작업 후보(회고 중 부상): **SKILL 본문에 밀어 넣은 ADR-NNNN 참조(169개)가 발동 시 로드될 때 AI 혼란/성능 저하를 유발하는가** — 별도 fg-ask 그릴링 예정(이 트림이 참조를 description→본문으로 옮긴 직접적 귀결).
