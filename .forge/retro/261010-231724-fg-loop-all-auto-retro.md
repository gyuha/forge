# 2026-10-10 — `fg-loop all`: 회고 로그 자동 작성 후 봉인 (#163)

## 계획과 실제
- 계획대로 된 것: S1~S4 모두. 봉인·상태 스크립트를 고치지 않고 기존 경로(회고 파일이 있으면 그 경로로 봉인)만으로 동작했다. 재현에서 계약 → 자동 회고 → 봉인 → STATUS 덧붙임 → 상태 표 → doctor가 모두 통과했다.
- 차이: (1) 문서 수정 목록에서 매니페스트 두 곳의 fg-loop 설명이 빠져 실행 중에 추가했다. `PLAN-FORMAT.md` 42행이 이미 "지점을 나열하거나 전부 찾는 명령을 써라 — 매니페스트 포함"을 요구하는데, 계획을 기억으로 썼다. 이 규칙에 기록된 세 번(`#115`·`#118`·`#119`) 다음 네 번째다(#162의 fg-merge 정합은 grep 102건으로 시작해 빠짐이 없었다). (2) INQUIRY.md 문장이 DoD의 대리 grep에 안 걸려 문구를 바꿨다. 의미 검토를 따로 해서 결과는 맞지만, 대리 지표에 산출물을 맞추는 방향이라 규칙 (e)의 역방향이다.

## 학습
- 다음엔 다르게: 여러 지점에 걸친 DoD는 목록을 기억으로 쓰지 말고 `git grep -l '<대상>'`을 먼저 돌려 그 결과로 목록을 만든다. 규칙은 이미 있으니 새 규칙이 아니라 실행의 문제다.
- 다음엔 다르게: 대리 grep이 안 맞으면 문구가 아니라 DoD를 의심한다. 이번엔 무해했지만, 문구를 grep에 맞추기 시작하면 grep이 실제 충족 여부를 말해 주지 않게 된다.
- 유지: 사용자 언어로 렌더되는 STATUS 문구가 아니라 회고 파일 첫 줄의 언어 독립 표시(`auto-retro`)로 판정하게 한 것. 판정이 언어에 따라 갈리지 않는다.
- 관찰: #160~#163 네 작업 모두 "스킬을 실제로 불렀을 때의 동작"을 이 세션에서 관찰하지 못하고 재현으로 검증했다. 현재 forge에는 스킬 호출 동작을 기계로 확인할 수단이 없다(Pi 로더 테스트가 로딩만 본다). 지금은 승급할 만큼 구체적이지 않다.
