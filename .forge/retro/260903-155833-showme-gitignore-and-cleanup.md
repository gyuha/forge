# 2026-09-03 — fg-showme 세션의 git 격리(중첩 .gitignore)와 완결 시 삭제·시작 시 sweep

## 계획 대비 실제

- **계획대로 된 것**: 세 슬라이스(S1 start-server 자체-ignore+sweep · S2 stop-server 삭제+통째 제거 · S3 문서 9곳+ADR 2건 개정) 전부 계획한 형태로 착지. DoD 12항목 전부 통과. **다음 날 검증 전용 재진입에서 12항목을 독립 재측정해도 전부 통과** — 임시 git 리포에서 서버를 실기동해 기능 1~5, grep으로 문서 6~12.
- **발산**: 사실상 없음. 즉석 결정 2건만 — (1) `/tmp` 전용 삭제 분기를 `cleanup_session_dir` 통합 경로로 흡수(동작 동일: `/tmp` 세션의 부모가 `showme`가 아니라 통째-제거 로직이 자연히 비활성), (2) `stale_pid` 경로에서 살아있는 PID여도 서버 신원 검증 실패면 폴더 삭제(계획의 "이미 죽은 세션"보다 넓지만 신원 미검증 세션은 회수 불가라 동일 취급이 맞다).

## 학습

- **다음에 다르게 할 것:**

  1. **실행 직후 `STATUS.md`를 쓰지 않고 세션이 끝났다 — 그리고 `fg-doctor`가 그 상태를 잡지 못했다.** `plan.md`+`run.md`는 있는데 동반 마커 `STATUS.md`가 없어 활성 슬롯이 "반쯤 실행된" 상태로 하루를 넘겼다. 발견은 세션 시작 훅(`verified: pending` 보고) 덕이었고, **같은 상태에서 `fg-doctor`는 0 errors를 냈다**(실측). 상태 계약상 fg-run은 run.md 직후 STATUS.md를 쓰므로 "활성 슬롯에 run.md가 있는데 STATUS.md가 없음"은 계약 위반이다 — A그룹 검사로 넣을 값이 있다. 훅이 우연히 메워 준 구멍이지 doctor가 막은 게 아니다.
  2. **runnable-DoD의 쌍 양성 체크도 정확한 문자열을 못 박아야 한다.** 이 계획은 부정 체크(→0)에는 grep 문구를 명시했지만 짝이 되는 양성 체크(≥1)는 *의미로만* 서술했다. 그래서 재측정 때 문구를 추측해야 했고 `survive`↔`survives`, `sweep`↔`swept`에서 **거짓 음성 2건**이 났다. 양성 체크의 거짓 음성은 fail-closed라 드러났지만, 같은 어미 차이가 **부정 체크**에서 나면 fail-open이라 조용히 통과한다. 쌍 체크는 양쪽 다 실행 가능한 정확 문자열로 적을 것.
  3. **서버 실기동 검증의 실무 형태**: `--open` 없이 `--background`로 돌린다(브라우저를 열지 않음). sweep 커버리지를 실증하려면 죽은 세션을 **3종 모두** 심어야 한다 — 정지 마커(`state/server-stopped`)·pid 파일 부재·죽은 PID. 계획은 마커 1종만 예시했고, 나머지 둘은 재측정에서 추가로 심어 확인했다.

- **관찰(DoD 밖, 결함 아님)**: 마지막 세션 종료로 `.forge/showme/`가 통째 제거된 뒤에도 **빈 `.forge/` 디렉터리는 남는다**. git은 빈 디렉터리를 추적하지 않아 `git status`는 깨끗하고 계획 범위도 아니지만, forge를 쓰지 않는 프로젝트에서는 빈 폴더가 남는다.
