# 2026-08-20 — forge를 에이전트 엔지니어링으로 규정 (#116·#117, fg-loop 주행 / 일괄 승급)

> 일괄 승급 모드로 사후 작성. `#116`(정본 5표면)과 `#117`(사이트 3표면)은 같은 목적지의 두 태스크이고 학습이 `#116`에 몰려 있어 한 파일에 담는다. `#117`은 divergence 0이라 별도 회고 파일을 만들지 않았다(검토했으나 승급할 것이 없음 — `retro: skipped` 유지).

## 계획 대 실제

- **계획대로 된 것**: 정지 체크 **8/8 통과**, 태스크 2건 봉인, 재계획 라운드 **0/3**(fix-forward 생성 0회). 8개 설명 표면 전부 A안 문구로 치환. Non-goals 전부 지켜짐 — 특히 `harness engineering(walkinglabs/learn-harness-engineering)` 출처 표기 불변(C8이 기계로 지킴), `docs/forge-vs-loop-engineering.md` 미변경, 버전 3곳 `0.6.9` 불변.
- **Divergences**: `#116` 3건, `#117` 0건.

## 학습

- **다음에 다르게: 정지 체크를 못 박을 때 각 명령의 exit code 계약을 실제로 확인하라 — 산문 의도와 인코딩이 어긋날 수 있다.** fork 벽 1회의 원인이 이것이었다. `loop.md` C6의 의도를 같은 줄에 "**0 errors**"라고 적었는데 인코딩은 `bash scripts/forge-doctor.sh` **exit 0**이었다. `fg-doctor`의 계약은 `0=clean / 1=warnings / 2=errors`이고 이 리포에는 무관한 사전 warning 1건(`fg-help/SKILL.md` description 768>600자)이 있어, **체크가 범위 밖 작업으로만 만족 가능**했다. §1 렌즈 4(범위 내 도달성)가 주행 *전에* 잡으라고 명시한 부류인데 놓쳤다 — 그리고 이 세션에서 `fg-doctor`가 warning에 exit 1을 낸다는 것을 이미 여러 번 봤음에도 그랬다. **체크를 적을 때 그 명령을 한 번 실행해 exit code를 확인하는 것이 비용 0의 예방이다.**

- **재확인: 드라이버가 자기 체크를 조용히 고치지 않는 것이 옳았다.** C6은 명백히 내 인코딩 실수였고 "고치고 계속"이 편했지만, 그것이 정확히 이 스킬이 금지하는 Goodhart 구멍이고 이번 세션 회고가 *"잘못된 테스트가 잘못을 사양으로 만든다"*로 기록한 병이다. fork 벽으로 넘겨 사람이 판정하고, 정정 근거를 `loop.md` C6 줄에 남겼다. **비용은 한 턴, 얻은 것은 감사 가능성이다.**

- **다음에 다르게: fg-loop 주행에서 파일을 고치기 전에 반드시 승격부터 한다.** `#116`에서 §2의 "`fg-run`에 멤버 slug를 넘겨 승격"을 건너뛰고 파일을 먼저 편집해, 한동안 "plan은 백로그 · 변경은 워킹 트리"라는 어긋난 상태였다(그 구간에 fg-status가 상태를 잘못 보고했을 것이다). `#117`에서 이 교훈을 적용해 승격을 먼저 했고 **divergence 0으로 끝났다** — 같은 주행 안에서 검증된 개선이다.

- **다음에 다르게(2회 반복): 여러 태스크로 쪼갠 작업의 이슈 마커는 마지막 태스크에만 둔다.** CLAUDE.md의 이슈 연동 규칙은 마커를 가진 plan이 봉인될 때 **확인 없이** 커밋·push·이슈 닫기를 한다. 그래서 8표면을 2태스크로 쪼갠 이번 작업에서 `#116`에 마커가 남아 있었으면 **사이트가 옛 문구인 채로 #14가 "해결됨"으로 닫혔을 것**이다. 직전 `#114`→`#115`에서도 같은 처리를 했으므로 **이번이 2회째**다. 두 기존 메커니즘(태스크 분할 + 이슈 자동 봉인)의 상호작용이라 한쪽만 읽으면 안 보인다.

- **전제 검증이 값을 했다.** 이슈 #14는 *"프로젝트 설명이 하네스 엔지니어링이라고 되어 있다"*로 시작했는데 grep해 보니 **그런 곳이 없었다** — 6곳 전부 외부 프로젝트를 출처로 인용한 문맥이었다. 전제를 확인하지 않았으면 (a) 실재하는 프로젝트를 오기하거나 (b) 엉뚱한 곳을 고쳤을 것이다. 요청 문구가 사실을 진술할 때는 그 사실을 먼저 재는 것이 그릴링의 일이다.
