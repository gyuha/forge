# 2026-09-06 — eval 승급(루프 학습을 영속 회귀 체크로) + 그 결과를 적대적 리뷰가 되받아친 한 바퀴

## 계획 대비 실제
- 계획대로 간 것: 5개 슬라이스가 전부 계획한 파일·형태로 착지했고, 비목표(매니페스트·fg-quick·`.forge/evals/` 원장·새 봉인 게이트)는 전부 무접촉. DoD 9항목 통과.
- 어긋난 것:
  - S4가 CLAUDE.md의 *회고 불릿*이 아니라 *검증 게이트 불릿*(:96)에 착지(내용상 더 맞는 자리라 유지). run.md가 이를 "divergence 없음"으로 보고했다가 사후 정정 — **DoD 9/9 통과가 divergence 0을 뜻하지 않는다**.
  - 실행 후 적대적 리뷰가 findings 9건(critical 1·major 2)을 냈고, 그중 **critical F1은 산출물의 결함이 아니라 ADR 전제의 결함**이었다. 즉 그릴링이 통과시킨 전제가 실행·검증을 모두 통과해 문서화까지 끝난 뒤에야 잡혔다.

## 학습
- **다음에 다르게 할 것 ①: "이미 X가 허용된 경로"라는 전제는 그릴링에서 원문을 열어 확인한다.** ADR 결정 2는 "fg-loop 제자리 수리는 이미 plan 편집이 허용된 경로"라는 전제 위에 섰는데, 실제 계약은 marker-only·슬라이스 보존이었다. 원문 한 줄을 안 읽어서, 규칙이 같은 계약에 "보존하라"와 "추가하라"를 동시에 명령하게 됐다. **산문 계약의 모순은 교착이 아니라 조용한 임의 해소를 낳는다** — 그래서 critical이다.
- **다음에 다르게 할 것 ②: "기존 게이트가 강제한다"류의 주장은 무엇을 강제하지 *못하는지* 함께 적는다.** ADR-0009는 plan에 **적혀 있는** DoD를 강제할 뿐, 슬라이스가 **누락된** plan은 아무도 못 잡는다. 강제 주장에는 항상 사정거리를 붙인다.
- **다음에 다르게 할 것 ③: 참조는 재진술하지 않는다.** fg-security 참조가 MUST를 "where feasible, should"로 약화 재진술해 단일 정의를 깨뜨렸다. 소비자 문서에는 규칙 문장을 옮기지 말고 가리키기만 한다.
- **다음에 다르게 할 것 ④(가장 값비쌌던 것): 리포팅 표면의 라벨은 파일 존재가 아니라 상태 계약에서 파생시킨다.** 이번 검토에서 같은 뿌리의 결함 6건이 나왔다 — fg-status 단계 열(`run.md` 있으면 무조건 `learn`), 회고 파일의 접미사 글로브(`*-<slug>.md`가 남의 회고와 매칭 → **회고 없이 봉인되는 fail-open**), statusline이 `verified: failed` park을 "회고 대기"로 계수, STATUS 값의 대소문자/공백 표기에 따라 표가 뒤집힘, done 디렉터리 폴백 상수가 구형식 기준. **가장 위험한 것은 되돌리기 어려운 액션(봉인)에 닿아 있으면서 조용히 통과하는 것**이었다.
- **다음에 다르게 할 것 ⑤: 스크립트가 기록하는 경로는 리포 상대경로로 정규화한다.** 봉인 스크립트가 절대 머신 경로를 STATUS에 35건 기록해 왔다(비-기본 브랜치는 git 추적이라 커밋된다). 해석된 루트가 절대라는 사실이 기록 값까지 절대로 만들었다.
