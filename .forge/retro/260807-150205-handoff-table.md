## 계획 대비 실제

**계획대로 된 것:** DoD는 충족했다 — 13곳 전부 `HANDOFF.md` 참조, 표 레이아웃 복붙 0, `fg-doctor` 0 errors 0 warnings. S2·S4·S5는 계획대로 실행됐다.

**발산:** `run.md`가 발산 5건(조건부가 고정 셀에 눌려 거짓이 됨 6건 · happy-path만 변환하고 종점 14곳 누락 · `HANDOFF.md`가 git에 없었음 · 오케스트레이터 자기 오류 5건 · 검증 지표가 구멍을 구조적으로 못 봄)을 기록했다. 그 위에 **후속 세션이 6번째 발산을 추가**했고, 이 회고의 핵심은 그것이다.

### 발산 6 — 영문 문서에 한글 shape을 박았다 (적대적 리뷰 3렌즈 전원 통과)

`HANDOFF.md`는 forge 규약대로 영문으로 작성됐고 line 7에 *"every skill renders the table in the user's language — translate the row labels"* 라는 **올바른 지시까지 담고 있었다.** 그런데 정작 `## The shape` 블록과 예시는 한글 라벨(`항목`·`방금 한 것`·`다음 단계`·`시작하는 법`·`대안`)이었다 — **지시와 예시가 서로 모순**이고, 모델은 산문 지시보다 제시된 예시를 따른다.

자매 형식 문서 셋은 전부 반대로 돼 있었다:

| 문서 | shape 라벨 | 언어 규율 문구 |
| --- | --- | --- |
| `fg-run/PLAN-FORMAT.md` | 영문 | "canonical English names — render them in the user's language" |
| `fg-learn/RETRO-FORMAT.md` | 영문 | 동일 |
| `fg-eco/ECO.md` (eco 요약 표) | 영문 (`▸ Request`·`▸ Done`·`Slice`·`Result`) | — |
| **`fg-next/HANDOFF.md`** | **한글** | line 7에 있으나 예시가 모순 |

그 한글 라벨은 13개 스킬 본문 **40여 지점**으로 퍼져 셀을 지칭하는 이름이 됐고, 덤으로 `HANDOFF.md` 이전부터 있던 **한글 트리거 하드코딩 16곳**(`Trigger: "작업 완료" / "봉인"` 등)이 함께 드러났다. `HANDOFF.md`가 트리거를 *"keep triggers verbatim"* 으로 뭉뚱그린 것도 틀렸다 — 슬래시 커맨드는 verbatim이 맞지만 자연어 트리거는 각 스킬 `description`에 한/영이 **모두** 등록돼 있어 사용자 언어에 맞는 것을 골라야 한다.

**근본 원인은 두 층위이고 서로 다르다(사람 진단):**

- **발생** — `run.md` S1이 ⚠ *"위임 실패로 오케스트레이터가 직접 작성"* 으로 기록한 그 지점. 전담 서브에이전트(`skill-author`)에 갔다면 형식 문서 컨벤션(`PLAN-FORMAT`/`RETRO-FORMAT`의 canonical 규율)을 대조했을 개연이 높다. 오케스트레이터는 자기가 설계 중인 shape에 몰입해 옆 문서를 안 봤다.
- **잔존** — 결함이 **현재 사용자 언어와 우연히 일치**해 그 세션 안에서 구조적으로 불가시였다. 리뷰어도 한국어 세션이라 한글 표가 "정상 출력"으로 보였고, 6렌즈는 논리 정합·구조·증거를 봤지 *"이 문서가 다른 언어 세션에서 어떻게 렌더되는가"* 를 보지 않았다. 결함 20건 이상을 잡아낸 리뷰가 이것만 통과시킨 이유다.

### run.md 기록 이후 상태가 바뀐 것

`run.md`는 **S6(README×2·`docs/skills.md` 동기화)을 미실행**으로 남겼으나, 후속 세션 시작 시점에 이미 세 파일이 수정된 상태였다(누가 언제 했는지 기록 없음). 커밋 `28e5eef`에 포함돼 해소됐다. run.md의 미완 목록을 정본으로 믿고 재작업했다면 중복 작업이 됐을 지점이다.

## 학습

**다음에 다르게 할 것:**

1. **형식·규율 문서를 새로 만들 때는 자매 문서를 먼저 나란히 놓고 대조한다.** `HANDOFF.md`는 `PLAN-FORMAT.md`·`RETRO-FORMAT.md`·`ECO.md`와 같은 계열인데 그 셋의 canonical 규율을 확인하지 않고 썼다. "단일 정의·복붙 금지"는 지켰으나 **형태의 일관성**은 놓쳤다 — 복붙 금지가 대조 금지는 아니다.
2. **지시와 예시가 어긋나면 예시가 이긴다.** 문서에 "X 하라"고 써도 바로 아래 예시가 X를 안 지키면 그 문서는 X를 지시하지 않는 것과 같다. 규율 문서를 쓸 때 **예시가 그 규율의 첫 번째 준수 사례인지** 확인할 것.
3. **이중언어 자산의 결함은 현재 언어와 일치할 때 안 보인다.** forge는 이중언어 플러그인이다(스킬 영문 / 출력 사용자 언어 / README 쌍 / `index.html`의 KO·EN span). 한국어 세션에서 한국어 결함, 영어 세션에서 영어 결함은 같은 방식으로 반복될 사각지대다. 적대적 리뷰에 **"반대 언어 세션에서 이 출력은 어떻게 보이는가"** 를 렌즈로 넣으면 기계적으로 잡힌다.
4. **위임 실패는 그 자리에서 되돌린다.** S1의 위임 실패를 오케스트레이터 직접 작성으로 메운 판단이 발산 6의 발생 원인이었다. 위임이 실패하면 직접 쓰기보다 재위임이 낫다 — 특히 그 산출물이 이후 13곳의 정본이 될 때.

**남은 사각지대(정직하게):** 표 렌더에는 여전히 기계 게이트가 없다(에이전트 판단 산문). ADR-0032·`260730-230321`이 남긴 cosmetic-on-forget 한계를 그대로 승계한다. 이번 수정도 `fg-doctor`가 검사하지 못하는 층이다.

## 문서 갱신

- CONTEXT.md 승급: 없음 — "언어 일치 사각지대"는 forge 도메인 용어가 아니라 일반 현상이라 글로서리 바 미달
- ADR 추가: 없음 — 유력 후보였던 "자연어 트리거는 verbatim이 아니다"는 세 조건 중 **되돌리기 어려움**과 **진짜 트레이드오프**가 약하다. 더 근본적으로, "형식 문서는 영문 canonical + 사용자 언어 렌더"는 **새 결정이 아니라 기존 규약**(CLAUDE.md 스킬 편집 규약)의 적용 누락을 고친 것이며, 정본은 `HANDOFF.md`의 "Language" 절과 CLAUDE.md 규약 개정으로 이미 명문화됐다
