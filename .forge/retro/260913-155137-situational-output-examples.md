# 2026-09-13 — 상황별 출력 예시의 적용 범위를 작성 참고 자료로 축소

## 계획과 실제
- 계획대로: 대화 재개·사용자 수행 절차·긴 보고의 세 전후 예시, 정보 보존, 한영 안내와 출처를 작성했다.
- 차이: 최초 계획의 22개 스킬 읽기 연결을 구현·검증한 뒤, 사용자가 전역 적용의 필요성을 문제 삼았다. 대화에서 실제 불편이 확인되지 않았고 효과도 실측하지 않았음을 재확인한 뒤, 사용자가 작성자용 참고 자료로 축소하는 안을 승인했다. 읽기 연결은 전부 제거했으며 22개 SKILL.md가 원본과 바이트 동일함을 검증했다.
- 최종 결과: 제품 변경은 CLAUDE.md·README 한영·OUTPUT-EXAMPLES.md 네 문서. 원래 계획은 보존하고 승인된 범위 변경과 새 완료 기준을 run.md에 기록했다. 수정 후 검증도 통과했고 미해결 설계 판단은 없다.

## 학습
- 다음에는 참고 자료 보강과 실행 규칙 추가를 처음부터 구분한다. “설치 환경에서도 읽힐 수 있어야 한다”는 사실만으로 모든 스킬에 읽기 의무를 줄 수 없다. 개선 필요가 확인된 지점과 예상 이점을 먼저 적고, 실익이 불확실하면 작성 참고 자료로 시작한다.
- 연결 검사는 참조 경로의 정확성을 증명할 뿐 적용 범위의 적절성이나 실제 응답 개선을 증명하지 않는다. 22/22 green을 채택 판단의 근거로 쓰지 않는다.
- 유지할 것: 같은 입력의 전후 비교, 보고 항목 6/6 보존, 기존 출력 계약과 원문 보존 검증. 단순히 짧아졌다는 이유로 개선으로 판단하지 않는다.
- 대화 근거: 사용자의 “불편하진 않았지만 개선 여지 검토”, “모든 스킬에 필요한가”, 범위 축소 승인과 이번 회고·마감 요청. 이미 논의한 판단을 다시 묻는 형식적 회고는 반복하지 않았다.

## 문서 갱신
- CONTEXT.md 승급: 없음 — 새로운 도메인 용어가 아니다.
- ADR 추가: 없음 — 되돌리기 쉬운 작성 참고 자료의 범위 조정이다. 사용자 승인 방향은 CLAUDE.md 안내와 run.md에 이미 남았다.
- eval 승급: 없음 — 필요한 적용 범위는 기계 판정할 수 없다. 경로 검사와 내용 보존 확인을 효과 평가로 오인하는 테스트를 추가하지 않는다.
- 회고 로그: 이 파일. 새 후속 작업은 만들지 않는다. 특정 스킬에서 실제 필요가 확인될 때 제한적으로 재검토한다.
