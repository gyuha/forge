# 2026-09-10 — opencode 설치 안내 문서 오류 수정 (6곳)

## 계획 vs 실제

- **계획대로 된 것**: 6개 파일(문서 2쌍 + 계약 2)의 오도 문장 교체, 파일별 서술 깊이 차등(docs=전체 절차 / README=요약+위임 / 계약 파일=한 문장), 이중언어 절 구조 1:1 유지, DoD 5개 전부 통과(전진 2 + 회귀 가드 3). 실행 방식은 워크플로우 없이 직접 실행 — 6개 중 4개가 번역 쌍이라 병렬 위임 시 한/영 드리프트 위험이 이득보다 컸다.
- **차이**: 실질 하나뿐. S3에서 README에 `opencode 가이드` 링크를 새로 걸지 않고 **바로 다음 문단의 기존 링크를 "아래 가이드"로 지시**했다(인접 문단 중복 링크 회피). 계획의 "절차는 복제하지 않고 가이드로 위임" 취지와 어긋나지 않는 표현 선택 수준.

## 학습

- **범위 밖으로 선언한 영역에 대해 단정문을 쓰지 말 것 — 이번 결함의 근본 원인이다.** 이 문장을 만든 선행 작업(#147)의 plan에는 `Non-goals: ... opencode 설치 경로 신설`이 **명시돼 있었다**. 그런데 산출물에는 "이미 `.claude/skills/`에 설치된 forge는 그대로 로드된다"가 들어갔다 — 설치 경로에 **의존하는 단정**이다. Non-goal은 "그 일을 하지 않는다"를 뜻하지 "그 영역에 대해 말해도 된다"가 아닌데, 그 구분이 없어서 업스트림 탐색 경로 문서에서 **추론한** 문장이 검증된 사실처럼 6곳에 실렸다. 다음에 할 것: plan의 Non-goals에 든 영역을 산출물에서 단정할 때는, 그 단정만 따로 검증하거나 조건절로 낮춘다.
- **문장이 참이어도 조건이 성립하지 않으면 오도한다.** "`.claude/skills/`에 있으면 로드된다"는 참이었다. 문제는 forge의 정상 설치가 거기 있지 않다는 것 — **참이지만 공허한 조건절**이었다. 이 리포의 `agenda.md`가 다루는 "도메인 없는 완전성 단정"과 같은 부류이며, 그쪽 논의(주장의 대상 집합을 문장 안에 명시)가 산문 일반으로 확장될 여지가 있다.
- **부정 체크의 fail-open을 또 밟았다(이번엔 그릴링 중 실측으로 잡음).** DoD 후보를 `$FILES` 변수로 돌렸더니 zsh 단어분할 미발생으로 `grep`이 파일명 하나를 못 찾고 **`0`(통과처럼 보임)** 을 냈다. 실제 값은 6. CLAUDE.md에 이미 경고가 있는데도 재발했다 — 대응으로 plan의 DoD에 "파일 목록을 변수 없이 직접 나열"을 명문화했고 실행 내내 그 형태를 유지했다. 다음에 할 것: 부정 체크(`→ 0`)를 쓸 때는 **먼저 일부러 실패시켜 0이 아닌 값이 나오는지 확인**하고 나서 목표값을 0으로 잡는다(측정 도구를 기준선으로 검증).
- **관측하지 않은 것은 조건부로 쓴다.** `~/.claude/skills/` 중복 등록은 실제로 확인하지 않았으므로 "중복으로 발견할 수 있다"로 남겼다. 반대로 플러그인 캐시의 버전 고정은 `installed_plugins.json`·캐시 디렉터리 목록으로 실측했으므로 "끊기지 않고 조용히 옛 버전을 가리킨다"고 단정했다 — 첫 학습의 규율을 같은 문서 안에서 양방향으로 적용한 사례.
