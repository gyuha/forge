# fg-eco — 세션 모델 전환 불가로 서브에이전트 모델 티어링만 도입한다

## Status
accepted

## 맥락
"단계별 모델 자동 전환"(설계=최강, 수행=일반, 완료=경량) 요구가 나왔다(가칭 fg-auto-model). 그러나 Claude Code에서 **스킬은 현재 세션의 모델을 바꿀 수 없다** — `/model`은 사용자 전용 interactive 명령이고, 스킬·도구·훅 어느 것도 세션 모델을 프로그램적으로 전환할 수단이 없다. forge의 설계(fg-ask 그릴링)와 완료(fg-done 봉인)는 메인 세션 대화로 돌므로(기둥 1), 이 두 단계의 모델은 강제 불가다. 반면 **서브에이전트/워크플로우 호출은 `model` 파라미터를 받는다**(Agent 도구·Workflow `agent()`).

## 결정
**`fg-eco`** — 위임 작업의 모델 티어링 토글(루프 밖 유틸리티)을 도입한다.

- **이름**: 실체가 "위임 작업에 최상위 모델을 낭비하지 않는 비용 효율 모드"이므로 세션 전환을 암시하는 `fg-auto-model` 대신 `fg-eco`로 명명.
- **설정**: `.forge/config.json`의 `eco` 키(boolean, 기본 `false`) — ADR-0008의 설정 표면 확장(전역 예외 경로, 다른 키 보존, lazy 생성).
- **인터페이스**: `fg-eco`(인자 없음) = 현재 상태 표시 + 켜기/끄기 선택 메뉴; `fg-eco on|off` = 즉시 토글.
- **enactment(범위 = fg-run만)**: eco가 켜져 있으면 fg-run의 Dynamic Workflow/실행 서브에이전트 모델을 **sonnet으로 캡**한다 — 세션 모델이 더 높은 티어일 때만 내리고, 이미 sonnet 이하면 상속 그대로(업그레이드 금지 — 절감 모드가 비용을 올리면 안 됨). 사용자가 명시적으로 모델을 지정하면 그 지시가 eco보다 우선한다.
- 결과 구조: **강력 = 메인 세션(설계·완료 — 사용자가 /model로 선택), 일반 = 위임 실행**의 2단 티어.

## 트레이드오프 / 결정 근거
- **fg-map은 범위 밖** — 매퍼 4개도 내릴 수 있으나, 지도는 fg-ask 그릴링의 연료라 품질 저하가 설계 품질로 직결된다. 절감 폭 대비 리스크가 커서 제외(가장 보수적 선택).
- **haiku 티어 없음** — 구상의 3단(강력/일반/경량) 중 경량 후보는 사실상 fg-map 매퍼뿐이었는데 그것이 범위 밖이 되어, 구현되는 티어는 2단이다.
- **메인 세션 단계엔 제안 멘트도 넣지 않음** — "지금 /model로 바꾸시죠" 한 줄은 강제력이 없고 매번 마찰만 더한다. 조용히 두는 쪽을 택했다.

## 고려한 대안
- **세션 모델 자동 전환(원 요구)** — 불가: 스킬이 세션 모델을 바꿀 API/수단이 없음.
- **settings.json `model` 편집** — 새 세션의 기본값만 바뀌고 현재 세션·단계별 전환이 아님. 침습적이라 거부.
- **fg-map 포함 / haiku 티어** — 지도 품질 리스크로 거부(위 트레이드오프).
- **advisory 한 줄(전환 제안)** — 소음 대비 효용 없음으로 거부.

## Consequences
- 향후 Claude Code가 세션 모델 전환 API를 제공하면 이 결정의 전제가 깨지므로 재검토한다(그때 "설계=최강" 절반을 진짜로 구현 가능).
- `.forge/config.json`의 키가 3개가 된다(`tdd`·`defaultBranch`·`eco`) — fg-tdd의 "preserve any other keys" 규칙이 fg-eco에도 동일 적용.
