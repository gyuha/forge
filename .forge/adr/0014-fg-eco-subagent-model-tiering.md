# fg-eco — 세션 모델 전환 불가로 서브에이전트 모델 티어링만 도입한다

## Status
accepted

## 맥락
"단계별 모델 자동 전환"(설계=최강, 수행=일반, 완료=경량) 요구가 나왔다(가칭 fg-auto-model). 그러나 Claude Code에서 **스킬은 현재 세션의 모델을 바꿀 수 없다** — `/model`은 사용자 전용 interactive 명령이고, 스킬·도구·훅 어느 것도 세션 모델을 프로그램적으로 전환할 수단이 없다. forge의 설계(fg-ask 그릴링)와 완료(fg-done 봉인)는 메인 세션 대화로 돌므로(기둥 1), 이 두 단계의 모델은 강제 불가다. 반면 **서브에이전트/워크플로우 호출은 `model` 파라미터를 받는다**(Agent 도구·Workflow `agent()`).

## 결정
**`fg-eco`** — 위임 작업의 모델 티어링 토글(루프 밖 유틸리티)을 도입한다. **(개정: eco 범위를 fg-run 모델 캡에서 루프 전체 절약 모드로 확장. 2차 개정 2026-06-23: ECO.md 규율에 출력 prose 압축(caveman 차용)을 추가 — 소통 토큰 절약)**

- **이름**: 실체가 "위임 작업에 최상위 모델을 낭비하지 않는 비용 효율 모드"이므로 세션 전환을 암시하는 `fg-auto-model` 대신 `fg-eco`로 명명.
- **설정**: `.forge/config.json`의 `eco` 키(boolean, 기본 `false`) — ADR-0008의 설정 표면 확장(전역 예외 경로, 다른 키 보존, lazy 생성).
- **인터페이스**: `fg-eco`(인자 없음) = 현재 상태 표시 + 켜기/끄기 선택 메뉴; `fg-eco on|off` = 즉시 토글.
- **enactment(범위 = fg-eco(현재 세션) + fg-ask + fg-run)**: eco가 켜져 있으면 다음 효율 동작이 활성화된다:
  1. **fg-run 모델 캡** — Dynamic Workflow/실행 서브에이전트 모델을 **sonnet으로 캡** (세션 모델이 더 높을 때만 내림, 이미 sonnet 이하면 상속 그대로, 사용자 명시 지시 우선).
  2. **fg-run Eco 주입** — 각 서브에이전트 프롬프트에 Eco YAGNI 6단계 사다리 + 핵심 제약을 주입 (YAGNI → stdlib → 네이티브 → 기존 의존성 → 한 줄 → 최소 코드; 불필요 추상화 금지; `// eco:` 주석 관행).
  3. **fg-ask YAGNI 렌즈** — fg-ask 그릴링 전반에 조용히 최소화 도전을 녹인다 ("이게 꼭 필요한가?", "최소 버전은?", "기존 메커니즘이 커버하나?") — 별도 질문 없이 그릴링 렌즈로 적용.
  4. **현재 세션 채택 (상태 기반)** — 메인 세션이 `eco: true`를 **관측할 때마다** `skills/fg-eco/ECO.md`를 읽어 그 대화 동안 규율(특히 출력 prose 압축)을 채택한다(`false`면 해제). **토글이 아니라 상태 기반**이라 `fg-eco on`뿐 아니라 no-arg가 on을 보고/유지할 때, 그리고 main-session 스킬이 작업 중 `eco: true`를 읽을 때(fg-run 빌드·핸드오프 — 직접 실행 경로 포함 —, fg-ask의 비-그릴링 핸드오프; 그릴링 질문은 ECO.md 경계로 명료 유지) 발동한다. behaviors 1-3은 config에서 **서브에이전트** 캡/주입과 그릴링 렌즈를 구동하고, **이 behavior만이 메인 세션 자체 출력을 규율 아래** 두므로 토글뿐 아니라 모든 main-session eco-read에서 발동해야 한다. **불가피한 한계**: eco가 이미 true인 새 세션에서 아직 어떤 forge 스킬도 안 돈 시점은 자가 채택 불가(스킬은 호출돼야 돌고 세션 시작 훅이 없음) — 처음 eco를 읽는 스킬이 집어간다. **세션 모델은 바꾸지 않는다**(전제 유지: 바꾸는 것은 모델이 아니라 행동 렌즈). `off`면 해제.
  5. **출력 prose 압축(2차 개정, caveman 차용)** — ECO.md 규율에 소통 prose 간결화(군더더기·헤지·인사치레 제거, 단편 허용, 결론 먼저; 언어 중립; 코드·명령·경로·에러는 verbatim)가 포함된다. 새 채널이 아니라 ECO.md 내용 확장이라, behaviors 2·4가 ECO.md를 운반하는 것만으로 fg-run 위임 서브에이전트·현 세션에 별도 배선 없이 적용된다. **적용 경계 = 실행·보고 prose뿐**; 그릴링 질문(기둥 1)·생성 영속문서(plan/run/retro/CONTEXT/ADR — 기둥 2)·명시 요청 설명·보안/불가역/다단계 경고는 압축 제외(ECO.md "Terse communication" 경계가 자기완결적으로 보장 — fg-ask엔 ECO.md를 주입하지 않고 YAGNI 렌즈만 적용하는 기존 배선과도 정합).
- 결과 구조: **강력 = 메인 세션(설계+그릴링 — 사용자가 /model로 선택), 효율 = 위임 실행**의 2단 티어. 이 티어는 **모델 비용** 기준이다 — behavior 4로 eco의 *규율*(모델 아님)은 메인 세션에도 적용되지만, 메인 세션 *모델*은 여전히 불변이라 티어 주장은 깨지지 않는다.

## 트레이드오프 / 결정 근거
- **fg-map은 범위 밖** — 매퍼 4개도 내릴 수 있으나, 지도는 fg-ask 그릴링의 연료라 품질 저하가 설계 품질로 직결된다. 절감 폭 대비 리스크가 커서 제외(가장 보수적 선택).
- **haiku 티어 없음** — 구상의 3단(강력/일반/경량) 중 경량 후보는 사실상 fg-map 매퍼뿐이었는데 그것이 범위 밖이 되어, 구현되는 티어는 2단이다.
- **메인 세션 단계엔 제안 멘트도 넣지 않음** — "지금 /model로 바꾸시죠" 한 줄은 강제력이 없고 매번 마찰만 더한다. 조용히 두는 쪽을 택했다.
- **fg-ask YAGNI 렌즈를 eco에 번들한 이유** — fg-ask는 메인 세션에서 돌므로 모델 캡은 불가능하다. 하지만 세션 Ponytail 훅이 없는 환경(CI, headless, 다른 사용자 세션)에서도 YAGNI 그릴링을 일관 적용하려면 SKILL.md 수준에 명시가 필요하다. eco와 묶은 이유: 둘 다 "forge 루프에서 낭비하지 않는다"는 같은 원칙의 다른 표현이기 때문이다 — 모델 비용 절약(eco) + 코드 복잡도 절약(ponytail) + 계획 범위 절약(YAGNI 렌즈). 별도 `ponytail` 키를 추가하지 않고 `eco` 하나로 번들한 것은 설정 표면을 최소화하기 위함이다.
- **별도 fg-ponytail 스킬 대신 eco 번들** — 외부 ponytail 플러그인 의존 없이 forge 자체에 Eco 철학을 임베드한다(구현: `skills/fg-eco/ECO.md` 형제 참조 파일 — 스킬로 자동탐색되지 않음; 원저자 DietrichGebert, <https://github.com/DietrichGebert/ponytail>에서 차용·각색, 출처는 README 크레딧에 명시). 독립 스킬로 분리하면 진입점이 늘어나고 eco/ponytail 조합 상태 관리가 필요해진다.
- **caveman(출력 압축)도 eco에 번들 — 별도 키·강도 레벨 없음 (2차 개정).** ponytail 번들과 동형 결정 — 같은 "낭비하지 않는다" 원칙의 세 번째 표현(모델 비용 + 코드 복잡도 + **소통 토큰**)이라 `eco` 하나에 묶고 새 config 키를 안 만든다. caveman의 강도 레벨(lite/full/ultra)·wenyan 변형은 미도입(eco는 binary, 읽히는 단일 수준). 적용 경계로 그릴링·생성문서를 제외해 기둥 1·2를 보존한다. 차용·각색 출처는 JuliusBrussee(<https://github.com/JuliusBrussee/caveman>), 크레딧은 README에 명시.

## 고려한 대안
- **세션 모델 자동 전환(원 요구)** — 불가: 스킬이 세션 모델을 바꿀 API/수단이 없음.
- **settings.json `model` 편집** — 새 세션의 기본값만 바뀌고 현재 세션·단계별 전환이 아님. 침습적이라 거부.
- **fg-map 포함 / haiku 티어** — 지도 품질 리스크로 거부(위 트레이드오프).
- **advisory 한 줄(전환 제안)** — 소음 대비 효용 없음으로 거부.

## Consequences
- 향후 Claude Code가 세션 모델 전환 API를 제공하면 이 결정의 전제가 깨지므로 재검토한다(그때 "설계=최강" 절반을 진짜로 구현 가능).
- `.forge/config.json`의 키가 3개가 된다(`tdd`·`defaultBranch`·`eco`) — fg-tdd의 "preserve any other keys" 규칙이 fg-eco에도 동일 적용.
