# 백그라운드 실행 중인 활성 슬롯을 `running.md` 마커로 표시해 fg-run 이중 실행을 막는다

## 맥락

fg-run은 워크플로우(Dynamic Workflow·백그라운드 서브에이전트)를 **항상 백그라운드**로 돈다 — 도구가 즉시 반환하고 완료는 알림으로 온다. 그 사이 `.forge/` 상태는 "plan.md만 있음"이고, 이 상태는 상태 계약에서 **"승격됐지만 미실행"**과 구별되지 않는다. 그래서 실행이 도는 동안 상태바·fg-status·fg-next·세션 시작 훅이 전부 "다음: fg-run(실행)"을 내고, 사용자가 그 안내대로 fg-run을 다시 치면 재실행 가드(`run.md` 존재만 봄)가 잡지 못해 **워크플로우를 두 번 세운다**. 사용자 보고("fg-run을 했는데 또 fg-run을 하라고 한다")의 실체이며, 잦은 업데이트와는 무관한 계약 공백이다. 실행 중이라는 상태가 forge에 없었다.

## 결정

1. **턴을 끊지 않는 것이 주경로다.** fg-run은 워크플로우를 시작한 뒤 완료를 같은 턴에서 기다린다(`TaskOutput` block 대기를 완료까지 반복) — 결과 회수·run.md·STATUS·UAT까지 한 턴에 잇는다. 대부분의 경우 실행 중 상태는 사용자 눈에 보이지 않는다.
2. **`<forge-root>/running.md` 마커가 안전망이다.** 실행 위임을 시작한 직후 쓰고(`forge-running: <slug>` · `workflow:` 실행 식별자 · `started:` epoch · `session:` 세션 id), `run.md`를 쓴 직후(및 취소·중단 시) 지운다. `drive.md`(ADR-0028)·`ask.md`와 같은 **별도 파일**이며 STATUS.md에 `status: running`을 넣지 않는다 — STATUS.md는 "실행이 끝난 뒤" 생기는 동반 마커이고 fg-doctor A2·상태 스크립트 트윈·통계 열이 `executed|done` 두 값만 알아, 값을 추가하면 소비자 전부가 흔들린다.
3. **소비자는 넷.** fg-run 재진입(plan+running.md, run.md 없음 → 재실행이 아니라 **회수·대기**: 같은 세션이고 실행이 살아 있으면 대기, 끝났으면 회수, 다른 세션이거나 실행이 사라졌으면 재개 불가를 알리고 **확인 후에만** 재구축), fg-status 상태 머신(새 분기 "실행 중 — 기다리라; 재진입은 회수"), 세션 시작 훅(이전 세션의 실행 중 마커를 한 줄 보고), fg-doctor(A10 — 고아·낡은 마커 경고), fg-drop(활성 슬롯 항목에 포함). 상태바는 손대지 않는다(이미 `run` 단계 표시).

## 고려한 대안

- **A. 턴 유지만(마커 없음)** — 새 상태 없이 프롬프트만 고친다. 기각: 모델이 그래도 턴을 놓치거나 세션이 죽으면 정확히 오늘의 상태(plan만 남음)로 돌아가 이중 실행 위험이 그대로다. 산문만으로는 보장이 안 된다는 것이 DRIVE.md Part 1의 "정직한 한계"이고 여기도 같다.
- **B. 마커만(턴 유지 없음)** — 모든 표면이 "실행 중"을 내고 재진입은 멱등해진다. 기각: 사용자가 완료 알림까지 기다려야 하고, 세션이 바뀌면 워크플로우 재개가 불가(같은 세션 한정)라 결국 재실행 확인이 자주 뜬다. 주경로가 되기엔 체감이 나쁘다. 안전망으로만 채택.
- **STATUS.md에 `status: running`** — 파일을 안 늘린다. 기각: 위 결정 2의 이유(소비자 ripple). fg-loop이 `waiting`을 기존 원장에 흡수한 규율은 "자연스러운 집이 있을 때"의 규율이고, STATUS.md는 실행 종료 뒤에 생기는 파일이라 집이 아니다.
- **Stop 훅으로 실행 중 턴 종료 차단** — drive.md 기제 재사용. 기각: 워크플로우 완료는 하네스가 알림으로 재진입시키므로 턴 종료 자체는 문제가 아니다. 문제는 그 사이 **다른 표면의 안내와 재진입의 비멱등**이고, 훅은 그것을 고치지 못한다. 리포에서 가장 위험한 물건의 적용 범위를 넓히지 않는다.

## 결과

- 이중 실행 경로가 닫힌다: 재진입은 회수·대기·확인 세 갈래 중 하나이고 "조용히 다시 세우기"는 없다.
- 상태 계약에 파일 하나가 늘고(`docs/state-contract.md`·CLAUDE.md 표), fg-doctor 검사 하나(A10)와 훅 출력 한 줄이 늘어난다. 스크립트 트윈 4개(hook·doctor sh/js)에 픽스처가 붙는다.
- 마커가 남는 경우(세션 사망)는 fg-doctor A10과 세션 시작 훅이 잡고, fg-run 재진입이 확인을 거쳐 정리한다 — 어느 경로도 마커를 근거로 자동 재실행하지 않는다.
