# 큰 작업은 순서 힌트를 가진 독립 part-plan들로 분할한다

## Status
accepted

## 맥락과 결정
기존 분할 규칙(PLAN-FORMAT)은 "한 워크플로우로 끝까지 돌릴 수 있으면 — 크더라도 — 쪼개지 마라"였고, 분할 트리거는 *중간 사람 확인 지점*뿐이었다. 또 "백로그 plan들 사이엔 의존/순서가 없다"고 못 박았다. 그러나 grilling에서 작업량이 큰 작업을 fg-run으로 하나씩 완성하고 싶다는 요구가 나왔다.

그래서 분할 규칙을 확장한다:
- **크기/분해 기반 트리거 추가** — 합의된 작업이 *각각 독립적으로 배포·검증·봉인해도 의미 있는 덩어리*로 자연히 나뉘면, 하나의 거대 plan 대신 여러 **part-plan**으로 백로그에 적재한다(판단 기반, 고정 숫자 임계값 아님). 기존 체크포인트 트리거는 그대로 유지.
- **소프트 순서 힌트** — 각 part는 `<!-- part: N/M -->` 마커와 `<base>-1of3` 식 슬러그를 가진다. fg-run은 이 순서대로 메뉴에 보여주고 "하나씩 순서대로 완성"을 권장한다.

## 불변식은 어떻게 지키나 (핵심)
- **각 part는 여전히 자체 완결·봉인 가능한 독립 plan이다** — 한 part = 한 plan = 한 워크플로우 = 한 run = 한 봉인. 즉 "한 plan은 한 워크플로우로 돌 수 있어야 한다"는 불변식은 깨지 않는다.
- **순서는 강제 의존이 아니라 권장 힌트다.** `part: N/M`은 fg-run의 표시·권장 순서만 바꾸며, 선행 part 미완료를 *차단하지 않는다*. 강한 하드 의존이 필요하다면 그건 애초에 한 plan이어야 한다는 기존 원칙은 유효하다.

## 고려한 대안
- 강제 순차 의존(`<!-- after: <slug> -->`, 선행 미봉인 시 차단) — 거부: "백로그 plan은 독립" 불변식을 정면 위반하고, 부분 실패 시 큐가 잠긴다. 각 part가 독립 봉인 가능하다는 안전성을 잃는다.
- 순서 개념 없이 독립 조각만 — 거부: 사용자의 "하나씩 순서대로 완성" 요구를 충족 못 함.
- 슬라이스 개수 임계값으로 자동 분할 — 거부: 임의의 숫자라 크기 신호로 부정확(작은 슬라이스 다수 vs 큰 슬라이스 소수).
