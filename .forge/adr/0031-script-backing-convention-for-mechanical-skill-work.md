# forge 스킬의 스크립트 백킹 컨벤션 — 기계적인 것은 결정론 스크립트, 판단은 산문

## 맥락

세 스킬이 같은 문제를 같은 방식으로 풀면서 하나의 패턴이 굳었다:

- **fg-status**(ADR-0020) — `.forge/` survey + 표 렌더링이 LLM 산문 해석 + 다중 도구 왕복으로 느렸다 → `forge-status.sh`.
- **fg-statusline**(ADR-0029, method 2) — daleseo식 시스템 정보 + forge 진행 렌더링 → `forge-statusline-full.sh`.
- **fg-done**(ADR-0030) — 봉인(사전점검·게이트 강제·STATUS 마감·아카이브)이 LLM 손 bash 5~6회 + 토큰 가드 추론으로 느렸다(게다가 파괴적) → `forge-done.sh`.

세 번 반복됐고 ADR-0030이 이미 "forge의 세 번째 스크립트 백킹 스킬"이라 적었다. 흩어진 원칙(0020의 "기계적은 스크립트/판단은 산문", 0022의 트윈 parity, 0030의 게이트-우선-비파괴)을 **새 스킬 작성자가 참조할 단일 정본 컨벤션**으로 승격한다 — "이게 패턴인가? 내 스킬도 스크립트화해야 하나?"에 답하기 위함.

## 결정

forge 스킬에서 **기계적·결정론적 작업은 결정론 스크립트로, 판단은 SKILL.md 산문으로** 가른다. 이는 강제 규칙이 아니라 **기본 지향**이다.

**스크립트로 옮길 것 (해당하면):**
- 순수 기계적·결정론적: 파일 조사·상태 전이·필드 추출·아카이브 이동처럼 같은 입력이면 같은 출력.
- LLM이 하면 느린 것: 긴 산문 해석 + 다중 도구 왕복 + 토큰 추론(비용·지연).
- 자주 도는 경로: statusline처럼 매 렌더, 봉인처럼 매 작업.

**산문에 남길 것 (스크립트로 옮기지 말 것):**
- 판단·라우팅: 게이트 실패 시 어디로 보낼지, offer할지, 어떤 학습을 승급할지 — LLM의 몫.
- next-step 도출: fg-status의 우선순위 머신은 산문 정본(ADR-0020) — 스크립트로 이중화 금지(drift).
- 대화(그릴링·회고): 기둥 1 — Dynamic Workflow/스크립트 안에 넣지 않는다.

**스크립트를 쓸 때의 필수 조건:**
1. **트윈 + parity (ADR-0022)**: `.sh`(bash 우선) + `.js`(node 폴백) 트윈, `*.parity.test.sh`로 동일 출력 보장, dual dispatch로 호출.
2. **behavior 테스트**: fixture 기반 `*.test.sh`. `.js` 트윈도 같은 테스트로 green(예: `FGDONE_IMPL`/`FGSL_FULL_IMPL` 인자 오버라이드).
3. **파괴적 스크립트는 게이트-우선-비파괴 (ADR-0030)**: 파일을 옮기는 스크립트는 게이트 통과 전 아무것도 안 건드리고 사유+exit code로 refuse. 라우팅은 산문이 exit code로.
4. **SKILL.md는 스크립트 출력·계약을 문서화하고 동기 유지 (ADR-0020 귀결)**: 형식이 스크립트↔SKILL.md 양쪽에 존재 → 함께 고친다.
5. **브랜치 루트 해석 재사용 (ADR-0011)**: `resolve-forge-root.sh`/`.js`.

## 고려한 대안

- **컨벤션을 명문화하지 않고 사례별로 둔다** — 기각(사용자 "승격" 요청). 패턴이 0020/0029/0030에 흩어져 새 스킬 작성자가 "스크립트화해야 하나"를 매번 재추론한다.
- **모든 스킬을 스크립트화** — 기각. 판단·대화·next-step은 스크립트화하면 drift·경직·기둥 1 위반. 경계(기계/판단)가 이 컨벤션의 핵심.
- **스크립트가 판단·라우팅까지** — 기각(ADR-0020·0030이 이미 기각). 이중화 drift + 파괴적 자동 라우팅 위험.

## 결과

- 새 스킬/기능이 "이 부분을 스크립트화할까"를 물을 때 참조할 단일 정본이 생겼다. 답: 기계적·결정론·hot·LLM-느림이면 예(위 필수 조건과 함께), 판단·대화·next-step이면 아니오.
- 이 컨벤션은 **기존 스킬 대개조를 요구하지 않는다** — 소급이 아니라, 앞으로의 지향이자 이미 벌어진 3사례의 사후 명문화다.
- 기둥 1(그릴링은 워크플로 밖)·기둥 2(문서=연료)와 충돌하지 않는다 — 오히려 "기계적인 것만 스크립트"로 기둥 1의 대화 영역을 보호한다.
- 참조: ADR-0020(fg-status)·0022(트윈 parity)·0029(fg-statusline)·0030(fg-done, 게이트-우선-비파괴)·0011(브랜치 루트).
