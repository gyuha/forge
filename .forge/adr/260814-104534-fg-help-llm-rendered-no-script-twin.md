# fg-help는 결정론 스크립트 트윈 없이 LLM 실행으로 렌더한다

## Status
accepted

## 맥락

GitHub 이슈 #11로 forge 스킬 사용법 도움말 스킬(`fg-help`)을 신설한다. `/forge:fg-help`는 개요를, `/forge:fg-help <명령>`은 개별 스킬 상세를 낸다. 두 가지 제약이 충돌한다:

1. **사용자 언어 출력.** forge의 모든 스킬은 사용자 언어로 출력한다(한국어 입력 → 한국어). fg-help도 예외가 아니다.
2. **단일 정의·복붙 금지.** forge의 최상위 규율(`FORGE-ROOT.md`·`HANDOFF.md`·`DRIVE.md` 선례). 스킬 사용법은 이미 각 `skills/*/SKILL.md`의 frontmatter `description`에 단일 정의로 존재한다 — 사람이 읽는 요약 + 한/영 트리거를 담도록 설계돼 있다.

문제는 이 `description` 본문이 **영문 canonical**이라는 것이다(한글은 끝의 트리거 예시에만 존재). 그래서 사용법을 그대로 읽어 출력하면 한국어 사용자에게 영문 도움말이 나간다.

한편 forge의 다른 읽기 전용 리포터는 **전부 결정론 스크립트 트윈**이다 — fg-status(`forge-status.sh`/`.js`, ADR-0020), fg-doctor(`forge-doctor.sh`/`.js`, ADR-0019), fg-done 봉인(`forge-done.sh`/`.js`, ADR-0030), 이중 디스패치 규약(ADR-0022). 속도·byte-identical 테스트·AI 없는 CI 게이트가 목적이다. fg-help도 이 패턴을 따라야 하는가?

## 결정

**fg-help는 결정론 스크립트 트윈을 두지 않고 LLM 실행 스킬로 만든다.** 근거:

- **번역은 스크립트로 불가능하다.** 제약 1(사용자 언어)과 제약 2(영문 단일 정의)를 동시에 만족하는 유일한 방법은 "영문 소스를 읽어 **출력 시점에 사용자 언어로 렌더**"이고, 이 렌더는 LLM만 할 수 있다. 스크립트로 하려면 각 스킬의 사용법을 한/영 두 벌로 미리 저장해야 하는데, 그것이 곧 제약 2가 금지하는 **5번째 동기화 표면**(SKILL.md·plugin.json·README 쌍·docs/skills.md에 이어)이다.
- **이것은 일탈이 아니라 forge의 보편 패턴이다.** 모든 forge 스킬이 "영문 authoring, 사용자 언어 출력"이며 그 번역을 런타임 LLM이 한다. fg-help는 스크립트 리포터가 아니라 그 보편 패턴의 리포터일 뿐이다. 사용자 언어는 **저장 문제가 아니라 렌더링 문제**다.

## 고려한 대안

- **스크립트 트윈 + 사용법 사본 저장**: fg-status와 대칭이 맞고 빠르지만, 한/영 사본이 5번째 동기화 표면이 되어 단일 정의 규율을 정면 위반한다 — 기각.
- **fg-status의 알리아스로**: 이슈 #11의 `/fg-help <명령>`(개별 명령 상세)을 fg-status가 구조적으로 만족할 수 없고(상태 조사기라 "명령 사용법" 개념 없음), 의미도 다르다(상태 vs 문서). `/fg-help`를 친 사용자에게 "활성 슬롯 비었음"이 나가 오히려 헷갈린다. 읽기 전용이라는 성질은 병합 이유가 아니다(fg-status/fg-doctor가 둘 다 읽기 전용인데도 분리된 선례) — 기각.
- **description 영문을 그대로 출력**: 사용자 언어 규율 위반 — 기각.

## 결과

- forge 리포터에 **처음으로 스크립트 트윈 없는** 읽기 전용 스킬이 생긴다. "왜 fg-help만 스크립트가 없지?"라는 질문의 답이 이 ADR이다.
- **트레이드오프**: 스크립트가 주던 것(속도·byte-identical 출력·AI 없는 CI 게이트 가능)을 fg-help는 못 얻는다. 대신 사용자 언어 렌더링과 사본 0을 얻는다.
- **테스트 방식이 바뀐다.** 출력이 매 실행 byte-identical이 아니므로 정확성은 **구조**로 검증한다 — 모든 스킬이 개요에 나오는가, `fg-help <명령>`이 지목한 스킬을 찾아 트리거·다음 단계를 내는가. fg-doctor의 parity 테스트 같은 스크립트 대조는 적용 불가.
- **불변**: fg-status·fg-doctor·fg-done의 스크립트 백킹은 그대로다. 이 결정은 fg-help 하나에만 적용되며, 그 이유(번역 필요)가 다른 리포터에는 없다.
