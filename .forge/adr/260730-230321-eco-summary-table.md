# eco 요약 표 — 작업 종료 출력을 요약+표로 교체, eco 게이트 뒤에 둠

## Status
accepted

## 맥락과 결정
작업을 수행하고 나면 출력 문장이 너무 많아 전체를 파악하기 어렵다는 요구(GitHub 이슈 #7)가 왔다. 이슈는 `요청 내용 / 수행 내용(표) / 다음 해야 할 일` 3챕터 형식을 제안했다.

**압축 규율은 이미 있었고, 부족했다.** `skills/fg-eco/ECO.md`의 `Terse communication`(군더더기 제거·답부터·짧은 단어)이 정확히 이 문제를 겨냥하지만, 사용자가 eco를 켜본 뒤에도 "느낌은 비슷했다"고 보고했다. 원인은 그것이 **스타일 지시**라는 점이다 — 지켰는지 여부가 눈에 보이지 않아, ADR-0032가 자기 강제력을 스스로 진단한 표현 그대로 **cosmetic-on-forget**이다(회고 `2026-07-06-fg-done-seal-summary`의 같은 부류 학습). 반면 **표는 형태(shape)라서 지켰는지가 눈에 보인다.** 그래서 압축 규율에 **구조화**를 더한다 — 스타일 지시를 반복하는 대신, 지킴 여부가 관측 가능한 형태를 못 박는다.

**결정: 작업 하나가 끝나는 지점의 산문 핸드오프를 "eco 요약 표"로 교체한다. 활성화 조건은 `eco: true` 하나뿐이다.**

- **교체이지 추가가 아니다.** 산문에 표를 덧붙이면 글이 더 늘어 목적에 정면으로 반한다.
- **eco 게이트 뒤에 둔다.** 기본값(eco off)에서는 CLAUDE.md의 "핸드오프는 자연스러운 대화체로 전한다 — 정해진 양식을 사무적으로 출력하지 않는다" 규약(ADR-0015 계열)이 그대로 유지되고, 고정 양식 출력은 **옵트인**이 된다. 이로써 규약과의 관계가 정면충돌에서 "모드 안의 경계 있는 예외"로 내려간다 — fg-quick이 기둥 2를, fg-loop이 기둥 1을 의도적·경계 있게 완화한 것과 같은 계열이다.
- **새 config 키를 만들지 않는다.** eco가 유일한 활성화 경로이므로 `eco` 키 하나가 계속 유일한 스위치다(ADR-0014의 활성화 경로 단일성 유지).
- **적용 지점은 "끝난 뒤"뿐이고, 실행 *중*은 건드리지 않는다.** 실행 중 narration도 줄이는 안을 검토했으나 실시간 가시성(어디서 막혔는지)을 잃는 대가가 커서 제외했다.
- **표의 축은 슬라이스다.** plan의 `## Work slices`가 `S1`/`S2` + 완료 기준을 이미 규정하므로 축이 이미 존재한다. 변경 파일 축은 `git diff`가 이미 답하고 "무엇을 했나"에는 답하지 않는다.
- **배치·무인 경로는 작업당 1행 표로 포함한다** — 아래 ADR-0032와의 관계 참조.
- **제외: fg-ask 그릴링 · fg-learn 회고 · 생성되는 영속 문서(plan/run/retro/CONTEXT/ADR).** 대화를 표로 바꾸면 대화가 아니게 되고(기둥 1), 영속 문서는 나중에 통독하는 루프의 연료다(기둥 2). 이 경계는 ECO.md가 이미 압축 예외로 정의한 것과 동일하다 — 새 경계를 발명하지 않았다.
- **fg-quick 제외.** 슬라이스 개념이 없고 이미 `LOG.md` 한 줄뿐인 초경량 차선이라 표가 과하다.
- **슬라이스가 1개면 표 없이 한 줄.** PLAN-FORMAT이 *"A small task may legitimately be a single slice"*를 명시하므로 1행 표는 의례다.

## ADR-0032와의 관계 (개정을 부른다)
ADR-0032는 **배치/무인 경로에 요약 금지**를 명시하고 *"나중에 '일관성 수정'으로 되돌리지 말 것 — 그게 이 ADR을 남기는 이유"*라고 못 박았다. 그 금지의 **이유는 "작업마다 요약이면 wall of text"** 였다.

그런데 **작업당 1행 표는 현행 산문 notice보다 짧다.** 즉 1행 표를 허용하는 것은 ADR-0032의 *취지*(momentum·장문 방지)를 위반하는 게 아니라 **이행**하면서, *문구*("요약 챕터 금지")만 어기는 형태다. 그래서 이것은 ADR-0032가 경고한 "일관성 수정"이 아니다 — 되돌리는 게 아니라, 금지의 근거였던 장문 문제를 더 짧은 형태로 해소하는 것이다. 이 구분을 ADR-0032 개정에 명시해, 다음 읽는 사람이 "금지를 깼다"고 오해하지 않게 한다.

**단, eco off에서는 ADR-0032가 문구 그대로 유효하다** — 배치/무인 경로는 종전대로 간결 notice만 내고 요약을 내지 않는다. 개정은 eco on 경로만 추가한다.

## 재료 보장 (run.md 형식 신설)
표를 지시하면서 재료를 보장하지 않으면 같은 실패를 반복한다. ADR-0032의 기존 요약이 이미 `run.md → {3-5 lines — result per slice}`를 지시하는데, **run.md는 형식 규정이 없는 자유 산문**(`RUN-FORMAT.md`가 존재하지 않음)이라 슬라이스별 결과가 보장되지 않는 **약한 고리**가 이미 있었다. 회고 `2026-07-06-fg-done-seal-summary` F1의 교훈이 정확히 이것이다 — *"지시 prose는 실제 기계 계약과 일치해야 한다."*

그래서 **run.md에 슬라이스별 한 줄 결과를 규정한다**(`S1 ✅ 계획대로` / `S2 ⚠ 경로 변경`). 이유:
- **fg-run 종료 시점**은 방금 실행했으니 결과를 알고 있어 표를 낼 수 있지만, **fg-done 봉인 시점은 다른 세션일 수 있고** run.md 산문만 남는다 — 재료 없이는 봉인 표가 반쯤 빈 표가 된다.
- 부수 이득: ADR-0032의 기존 약한 고리도 같이 메워지고, fg-learn의 divergence 판단이 더 정확해진다.

규정은 `fg-run/SKILL.md` step 4에 둔다 — `RUN-FORMAT.md`를 신설하지 않는다(규정이 한 줄인데 파일 하나는 과하다).

## 단일 정의 위치
정의는 **`skills/fg-eco/ECO.md`의 새 섹션** 하나뿐이고, fg-run·fg-done·fg-next(DRIVE.md)가 이를 **참조**한다(복붙 금지 — FORGE-ROOT.md·DRIVE.md와 같은 관례). `*-FORMAT.md`를 신설하지 않는 이유: 그 관례는 **파일로 생성되는 문서**(plan·retro·CONTEXT·ADR)의 형식용이고, eco 요약 표는 **화면 출력 전용**이라 대상이 아니다(ADR-0032: 요약은 파일로 영속화하지 않음 — 아카이브가 영속 흔적).

## 고려한 대안
- **eco를 켜서 확인만 하고 끝낸다(기능 추가 없음)** — 거부. 사용자가 이미 켜봤고 부족했다. 스타일 지시의 한계가 실증된 것이 이 ADR의 출발점이다.
- **압축을 eco 게이트에서 떼어내 항상 적용** — 거부. `fg-eco`의 존재 이유 절반이 사라져 ADR-0014를 무너뜨리고, 기본값에서 CLAUDE.md 대화체 규약과 정면충돌한다.
- **eco와 별개의 새 config 키/새 모드** — 거부. 같은 일(출력 절약)을 하는 스위치가 두 벌 생긴다.
- **실행 *중* narration까지 표로 압축** — 거부. 실시간 가시성 상실(어디서 막혔는지)의 대가가 이득보다 크다.
- **이슈가 제안한 `##` 헤딩 3챕터를 그대로 채택** — 거부. `##` 3개는 터미널에서 오히려 공간을 먹고, ADR-0032가 확립한 `▸` 챕터 형태와 어긋난다. 또 검증 상태(`verified:` — ADR-0009의 봉인 게이트)가 3챕터에 자리가 없어 **봉인 가능 여부를 알 수 없게 된다.** 메타(제목·검증·divergence)를 헤더 한 줄로 접고 `▸` 챕터를 쓰는 형태로 개선했다.
- **봉인 시점 표를 작업 축으로(슬라이스 축 포기)해 run.md 규정을 피한다** — 거부. fg-run 종료와 봉인의 표 형태가 달라지고, ADR-0032의 기존 약한 고리가 그대로 남는다.
- **`fg-done` 봉인 요약만 표로 바꾸고 끝낸다** — 거부. 이슈 #4가 이미 봉인 요약을 낳았는데도 같은 불만이 재보고됐다 — 남은 통증은 봉인이 아닌 다른 지점이라는 증거다.

## 결과
- **강제력은 ADR-0032보다 강하지만 여전히 완전하지 않다.** 표는 형태라서 누락이 눈에 보이므로 스타일 지시보다 낫지만, 렌더는 여전히 에이전트의 판단 산문이라 기계 게이트가 없다(스크립트가 내는 출력이 아니다). ADR-0032가 자기 한계를 정직히 남긴 것과 같은 종류의 트레이드오프이며, 완화책도 같다 — 전 경로 prose 커버 + 방어적 기본값.
- **eco off 경로의 동작은 무엇도 바뀌지 않는다.** 상태 계약·검증 게이트(ADR-0009)·봉인 스크립트(ADR-0030)·회고 게이트(ADR-0002)는 전부 불변이다. 이 결정은 순수하게 **화면 출력 계층**이다.
- ADR-0032는 개정되고(eco on 배치 경로에 1행 표 허용 + 왜 되돌림이 아닌지), ADR-0014의 "eco가 활성화하는 것" 목록은 둘에서 셋으로 늘어난다.

## 개정 (2026-08-05) — "고정 양식 출력을 eco 게이트 뒤에 둔다"는 판단만 대체됨 (ADR `260805-231104`)

위 `## 맥락과 결정`의 **"eco 게이트 뒤에 둔다"** 항목 — 그리고 `## 고려한 대안`에서 항상-적용안을 *"기본값에서 CLAUDE.md 대화체 규약과 정면충돌"* 이라며 거부한 근거 — 은 **고정 양식 출력을 옵트인으로 남겨 기본값에서 대화체 규약을 지킨다**는 판단이었다. 이 판단은 [ADR `260805-231104`](./260805-231104-handoff-table.md)(핸드오프 표)로 **대체된다**: 다음 단계 안내는 고정 4행 표로 **eco 게이트 없이 항상** 렌더되고, CLAUDE.md의 해당 규약이 그에 맞춰 개정됐다(유지=진술형, 폐기="대화체·고정 양식 금지"). 이유는 통증의 축이 달라서다 — 이 ADR이 겨냥한 **길이**는 모드로 옵트인해도 되지만, **찾기 어려움**은 모드와 무관한 상시 통증이라 eco를 켜야 해결되는 것은 해결이 아니다.

**대체 범위는 그 판단 하나뿐이다.** eco 요약 표 자체와 그 형태(단일 정의는 `skills/fg-eco/ECO.md`), 교체이지 추가가 아니라는 원칙, 적용 지점이 작업이 끝나는 곳뿐이라는 경계와 실행 *중* narration 불변, 제외(그릴링·회고·영속 문서·fg-quick), 슬라이스 축, 새 config 키 없음(`eco`가 유일한 활성화 경로 — ADR-0014), run.md 슬라이스별 한 줄 재료 보장(eco 무관 항상), ADR-0032와의 관계, `## 결과`의 강제력 한계 진단은 **전부 그대로 유효하다.** eco on의 작업 종료 지점에서 두 표는 우선순위를 다투지 않고 역할을 나눈다 — eco 요약 표를 먼저 내고, 핸드오프 표가 `방금 한 것` 행을 뺀 3행으로 뒤따른다(`260805-231104`).
