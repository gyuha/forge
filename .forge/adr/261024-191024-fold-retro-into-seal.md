# 회고를 봉인(fg-done)의 판정으로 흡수한다 — 루프는 ask → run → done 3단계

## Status
accepted (supersedes ADR-0002의 "건너뛰기는 사람이 고른다", ADR-0026 전체, ADR `261010-230950`의 `retro: auto` 모드 구분. 세 ADR의 다른 결정 — 차이가 크면 건너뛰지 않는다, 승급은 사람과 함께, 자동 회고 표시와 "승급 미검토" 약속 — 은 그대로 산다)

## 맥락
루프의 ③ 회고(fg-learn)는 매 작업마다 사용자가 직접 부르는 별도 단계였다. 실제로는 대부분 차이가 작아 건너뛰었고, 단계를 줄이려는 우회로가 따로따로 생겼다 — fg-next의 회고→봉인 자동 연쇄(ADR-0026), `simple` 모드, `fg-done all`, `fg-loop all`의 자동 회고. 경로마다 회고 규칙이 달라졌고, 무인 경로는 "무조건 건너뜀"이라 "나중에 승급"하겠다는 약속이 사람 기억에만 의존했다. 사용자는 회고를 별도 단계로 두지 말고, 봉인할 때 배울 게 있으면 알아서 처리하기를 원했다.

## 결정
1. **fg-done이 회고 필요 여부를 판정한다.** 기계 신호 중 하나라도 있으면 회고 로그를 반드시 쓴다 — `run.md` 슬라이스 결과의 `⚠`(계획과 다름), `## Failed attempts` 줄 또는 STATUS `fix-rounds` ≥ 1, `review.md`의 수용했지만 고치지 않은 지적, `run.md`의 `## Rulings`. 신호가 없으면 에이전트가 `run.md` 산문을 읽고 판단하되 기본은 건너뛰기(`retro: skipped (<사유>)`)다.
2. **승급은 여전히 사람이 확인한다.** 로그를 쓴 경우에만, CONTEXT·ADR·eval 기준을 넘는 후보가 있으면 한 번에 보여 주고 **한 번** 묻는다. 후보가 없으면 질문이 없다.
3. **모든 봉인 경로가 같은 판정을 쓴다.** 다른 점은 "물을 수 있느냐" 하나다. 대화형 봉인(직접 호출·fg-next one-shot)은 승급 질문을 하고, 무인 봉인(fg-next all·fg-loop·simple·fg-done all·fg-ask STEP 0 자동 마감)은 로그에 `<!-- auto-retro -->` 표시와 STATUS `(자동, 승급 미검토)`를 남기고 승급을 fg-learn 일괄 승급으로 미룬다.
4. **fg-learn은 루프에서 빠져 일괄 승급 전용 유틸리티로 남는다.** 형식 문서(`RETRO-FORMAT.md`·`FOLLOWUPS-FORMAT.md`)는 자리를 옮기지 않는다.
5. **봉인 대기 단계의 이름은 `seal`이다.** 표·statusline·모니터에서 `learn`이 사라지고, 봉인 완료 `done`과 구분된다.

## 고려한 대안
- **승급까지 전부 자동** — 거부: 사람 판단 없는 정답 문서 변경은 루프의 연료를 추측으로 오염시킨다(ADR `261010-230950`이 이미 기각한 이유).
- **대화형 회고를 fg-done 안에서 매번 진행** — 거부: 명령은 줄지만 대화가 매번 남아 사용자가 원한 "알아서"가 아니다.
- **fg-learn 완전 삭제(일괄 승급을 `fg-done` 인자로)** — 거부: 봉인하는 스킬이 이미 봉인된 작업을 다시 여는 역할까지 맡아 의미가 흐려지고, 형식 문서 이동으로 참조 수정이 늘어난다.
- **신호가 없어도 항상 짧은 로그** — 거부: ADR-0002가 기각한 빈 스텁 회고와 같은 잡음.
- **무인 경로는 지금처럼 무조건 건너뜀** — 거부: 경로마다 규칙이 다른 상태가 남고 승급 약속이 사람 기억에 계속 의존한다.

## 결과
- 사용자가 체감하는 루프는 ask → run → done 3단계다. 대부분의 작업에서 회고 질문은 0개다.
- 무인 주행에서도 신호가 있는 작업은 로그가 남는다. 대가로 작업당 로그 작성 비용이 조금 는다.
- `retro:` STATUS 필드와 회고 파일 짝 맞춤은 바뀌지 않는다 — 기존 봉인 기록과 호환된다.
- fg-next의 회고→봉인 연쇄 예외(ADR-0026)가 없어져 fg-next one-shot은 다시 "한 스텝 = 한 스킬 호출"이다.

## 개정 (2026-10-24, 적대적 리뷰 반영)
- **결정 3의 STATUS 표시는 폐기한다.** 무인 회고의 판별자는 회고 파일 첫 줄 `<!-- auto-retro: … -->` 표식 **하나뿐**이다 — STATUS 산문 표시는 사용자 언어로 쓰여 기계가 읽을 수 없고 누락될 수 있다. 대화형 봉인에서 채택했으나 아직 반영 안 된 승급은 첫 줄 `<!-- promotion-pending -->`으로 표시한다.
- **건너뛰기는 `retro: skipped (judged: <사유>)`로 기록한다.** 봉인 스크립트가 기계 신호가 있을 때 `--skip-retro`를 거부(exit 4)하므로 "신호가 있으면 반드시 로그"가 산문이 아니라 강제된다. fg-learn 후보는 날짜가 아니라 `judged:` 유무로 가른다.
- **기계 신호는 하한(floor)이지 재현율 보장이 아니다.** 신호가 없어도 배울 것이 있을 수 있고 그 판단은 여전히 에이전트 몫이다. 신호 (c)는 `review.md`의 `disposition: accepted` 줄이며, `## Failed attempts`·`## Rulings` 헤딩은 영문 그대로 둔다.
- **결정 5를 뒤집는다 — 단계 이름은 `done`(완료)이다.** 사용자에게 익숙한 단계 이름은 원래 "완료"였고, "봉인"은 그 단계에서 하는 동작(아카이브해 재실행을 막는 것)의 이름이다. 그래서 루프 표기는 ask → run → done(질의·계획 → 실행 → 완료), statusline은 `ask → run → done`, 대기 묶음은 "완료 대기"(`awaiting done`)로 쓴다. 상태 표는 검증을 마치고 fg-done만 남은 작업을 `done`, 이미 끝난 작업을 `done ✔`로 구분한다. "봉인"은 동작 이름으로 계속 쓴다(봉인 요약·미봉인 잔여 등).
