# 봉인 단계를 fg-done으로 개명하고, fg-cleanup을 ADR 은퇴 유틸리티로 재배치

## Status
accepted

## 맥락
forge의 영속 문서 모델에서 ADR은 git 추적되는 "루프의 연료"다(기둥 2). 그런데 ADR이 누적되면 두 가지 고통이 생긴다: (1) **낡은 결정이 헷갈림** — 후속 결정에 의해 의미가 바뀐 ADR이 여전히 fg-ask의 "정답 소스"로 읽혀 그릴링을 오염시킨다, (2) **디렉터리가 쌓여 거슬림** — 현역과 은퇴 결정이 한 폴더에 섞여 시야를 가린다. 한편 봉인 ④단계의 이름 `fg-cleanup`은 "정리"라는 일상어를 점유하고 있어, "ADR을 정리(치운다)"는 새 기능에 가장 자연스러운 이름을 빼앗고 있었다. (`fg-cleanup`은 본래 `fg-complete`에서 "완료 선언이 아니라 정리"임을 강조하려 개명된 이름이다 — 이 ADR은 그 결정을 부분 역전한다.)

## 결정
**봉인 ④단계를 `fg-done`으로 개명하고, 비어난 `fg-cleanup` 이름에 "오래된 ADR 은퇴" 루프-밖 유틸리티를 새로 만든다.**

- **fg-done (봉인 ④단계, 기존 fg-cleanup의 동작 그대로).** 휘발 상태를 비우고 `status: done`을 찍어 `.forge/done/`으로 봉인하는 재실행 가드. 동작·계약은 불변, 이름만 바뀐다. 세 "done"(`fg-done` 스킬 / `.forge/done/` 폴더 / `status: done`)이 정렬되어 의미가 명료해진다. 트리거: `작업 완료`·`봉인` + 옛 `작업 정리`·`forge complete`를 alias로 흡수(`forge cleanup`은 fg-done이 아니라 신규 fg-cleanup에 넘긴다 — 아래 트레이드오프 참조).
- **신규 fg-cleanup (ADR 은퇴, 루프 밖 유틸리티).** fg-map·fg-merge처럼 루프 4단계에 속하지 않는 별도 유틸리티. 동작:
  - **A+ 후보 제시 → 사람 승인.** 스킬이 supersede 관계로 보이는 은퇴 후보를 근거와 함께 한 줄씩 제시하고, 최종 은퇴 결정은 사람이 승인한다(자동 은퇴 금지). fg-merge의 "기계적 자동 / 진짜 충돌 시 대화"와 같은 안전 원칙.
  - **`.forge/adr/retired/<NNNN>-slug.md`로 이동 + 상단 supersede 사유 마킹.** 활성 `adr/`는 현역만 남고, 은퇴분은 git에 살아 있다. `Superseded by ADR-NNNN`뿐 아니라 후속 ADR 없는 `Retired (사유)`("더 이상 안 맞음")도 허용.
  - **번호 불변·재사용 금지.** 0003은 retired/로 가도 0003. 새 ADR은 은퇴 번호를 재사용하지 않고 구멍을 둔다(ADR-0005 단조번호 원칙과 동일).
  - **fg-ask는 `retired/`를 정답 소스로 읽지 않는다.** fg-ask가 읽는 범위를 `.forge/adr/*.md`(최상위)로 한정 → 은퇴분이 그릴링 연료에서 빠진다(고통 1 해소). 사람은 `retired/`에서 "왜 그때 그랬나"를 여전히 찾을 수 있다.
  - 트리거: `forge cleanup`·`ADR 정리`·`ADR 은퇴`·`오래된 ADR 치워`. 첫 줄 핸드오프로 "이건 ADR 은퇴 유틸리티(작업 봉인은 fg-done)"를 한 번 확인해 근육기억 역전 사고를 막는다.

## 결정 근거 / 트레이드오프
- **은퇴 ≠ 삭제.** 삭제는 "왜"의 기록을 파괴해 기둥 2를 깬다. 이동+마킹은 활성 집합에서 빼면서(고통 1·2 해소) 역사를 보존한다. ADR 업계 관행(supersede)과 일치.
- **`forge cleanup` 트리거를 신규에 넘김(근육기억 역전 감수).** 개명의 목적이 "cleanup이라는 말을 봉인에서 떼어 은퇴에 붙이는 것"이므로, alias로 봉인에 남기면(대안 ㄴ) 개명 의미가 반감된다. 명확한 핸드오프 확인으로 오발동 위험을 상쇄.
- **루프 밖 유틸리티로 분리(봉인에 합치지 않음).** 은퇴를 fg-done에 넣으면 매 작업 봉인마다 ADR 은퇴 판단이 끼어들어, 본래 경계한 "cleanup마다 ADR 건드림"이 뒷문으로 부활한다. 은퇴는 사람이 가끔 의도적으로 도는 별도 행위여야 한다.
- **개명 sweep은 살아있는 기능 문서만.** 스킬 본문·CLAUDE.md·README·매니페스트는 갱신하되, 역사 기록(retro·done 아카이브·CHANGELOG 과거 항목·기존 ADR 0002/0003/0009의 언급)은 불변으로 둔다 — 그것들은 "그때 fg-cleanup이었다"는 사실의 기록이라 고치면 역사가 왜곡된다. 옛 ADR이 언급하는 "fg-cleanup(봉인)"은 곧 현재의 fg-done임을 이 ADR이 다리로 잇는다. codebase 지도는 fg-map 재생성 산출물이라 수작업 갱신 대상이 아니다.
- **교차참조 재작성 불필요.** 다른 문서가 ADR을 *번호*로 인용하므로(`ADR-0003`), 파일이 `retired/`로 가도 인용은 안 깨진다. fg-merge식 경로 재작성은 과잉.

## 고려한 대안
- **(A) 매 cleanup마다 ADR 전체 삭제** — 최초 요청. 거부: 한 바퀴마다 모든 아키텍처 결정의 기억을 증발시켜 fg-ask 정답소스를 파괴한다(forge가 forge가 아니게 됨).
- **(C) 제자리 마킹만(이동 없음)** — `Status: Retired` 추가만. 거부: 디렉터리가 여전히 11개라 "쌓여서 거슬림"(고통 2) 미해소.
- **(B-자동) 스킬이 staleness를 자동 탐지·자동 은퇴** — 거부: ADR이 안 맞는지는 의미 판단이라 LLM 오추정 시 살아있는 결정을 죽인다. 후보 제시까지만 자동, 판단은 사람.
- **봉인에 은퇴 기능 병합(별도 스킬 없음)** — 거부: 위 "루프 밖 분리" 근거.
- **트리거 ㄴ(`forge cleanup`을 fg-done alias로 유지)** — 거부: 개명 의미 반감.

## 개정 (2026-06-09) — 루프 ④단계의 "단어"도 done/완료로
처음 적용 때는 스킬명만 `fg-cleanup → fg-done`으로 바꾸고 루프 ④단계를 가리키는 *단어*는 "cleanup/정리"로 두었다("스킬 ≠ 단계" 구분 유지). 그러나 신규 `fg-cleanup`(ADR 은퇴)이 "cleanup"이라는 단어를 정체성으로 차지하면서, ④단계까지 "cleanup"이라 부르면 **같은 단어가 두 뜻(봉인 단계 / 퇴출 스킬)으로 충돌**했다. 그래서 루프 ④단계의 단어도 **`done`(완료)**로 통일한다 — 흐름 표기는 `ask·plan → execute → retro → done`. "cleanup"은 이제 `fg-cleanup`(퇴출) 전용 단어다.
- 적용 범위: 태그라인·텍스트/Mermaid 흐름도·스킬 카탈로그 ④ stage 셀·loop-order(`run → verify → learn → done`)·`fg-done` 제목의 단계 라벨, 그리고 ④단계를 "정리(tidy-up)·완료 선언 아님"으로 *규정*하던 framing(fg-done SKILL.md·CLAUDE.md)을 "④ done(완료) 단계"로 재서술. README 양 언어·CLAUDE·매니페스트(metadata 포함)·관련 스킬 흐름도 일괄.
- 불변: `fg-done`의 내부 *동작* 서술(tidy-up/seal/archive/empty/재실행 가드)은 그대로 — 단계 *이름*만 done. `fg-cleanup` 퇴출 스킬과 그 트리거(`forge cleanup`·`ADR 정리` 등)는 손대지 않음.
