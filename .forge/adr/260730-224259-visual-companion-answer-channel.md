# Visual Companion을 표시 전용에서 보조 답변 채널로 확장한다 (제안 발동 경화 포함)

`fg-ask/SKILL.md:117`과 `VISUAL.md:88·93`은 컴패니언을 **표시 전용**으로 정의하고 *"the browser only **shows**"* 를 **기둥 1이 온전한 근거**로 인용해 왔다. 두 가지가 드러났다. ① 제안이 실제로 발동한 적이 없다 — 이 리포에 `.forge/visual/`이 존재한 적이 없는데(fg-ask 제안 경로는 `--project-dir <repo root>`를 하드코딩하므로 수락됐다면 남는다), 2026-07-28의 `fg-visual-card-image-mockup-collapse`(목업 폭 붕괴·세로 잘림)는 "말하기보다 보여주기가 나은" 질문의 교과서적 사례였다. 원인은 규칙 텍스트가 7개 절 중 **5개가 금지**이고 **긍정 예시가 0개**여서 모호할 때 침묵으로 수렴하는 것, 그리고 판단이 긴 목록의 세 번째 불릿에 있어 STEP 0 같은 **구조적 체크포인트가 없는** 것이다. ② 수락해도 브라우저에서 B를 클릭한 뒤 터미널에 **B를 또 타이핑**해야 했다.

**결정.** 브라우저를 **보조 답변 채널**로 승격한다 — 선택형 질문에서 **클릭을 답으로 인정**하고, 화면이 명시적 전송 버튼을 갖춘 텍스트 입력 위젯을 담을 수 있다(기존 `window.brainstorm.send()`로 전송 — **vendored 파일 무변경**).

> **정정(2026-07-30, 실행 중 실측).** 이 결정을 내릴 때 근거로 삼은 "`handleMessage`가 타입 무관하게 append한다"는 **오독이었다.** `server.cjs`는 `if (event && event.choice)` 가드 아래에서만 `state_dir/events`에 기록하므로, `choice` 없는 `{"type":"text",…}`는 서버 stdout에만 남고 **파일에 도달하지 않는다**(WebSocket 프로브로 확정: `choice` 있으면 기록, 없으면 소실). 따라서 텍스트 이벤트는 `choice:"text:<field>"`를 **함께 실어야** 한다. 결론(vendored 무변경)은 유지되지만 그 이유가 다르다 — "가드가 없어서"가 아니라 "가드를 만족시키는 키를 함께 보내서"다. 상세는 `skills/fg-visual/VISUAL.md`의 Ask input 절. 두 채널의 답은 **병합**하고, 실질적으로 **모순될 때만 한 줄로 되묻는다**(자동 판정 없음). 별도로 제안의 **판단 시점**을 앞당긴다 — 작업 도메인에 UI·시각 표면이 포함되면 첫 질문 전에 컴패니언 여부를 판단하는 구조적 체크포인트를 두되, **제안 시점은 여전히 just-in-time**(첫 시각 질문)이고 `VISUAL.md:27`의 질문별 브라우저/터미널 라우팅은 **불변**이다.

**기둥 1이 여전히 온전한 이유.** 답은 여전히 **터미널이 깨운 턴**으로 도착한다. 브라우저는 Dynamic Workflow의 런타임 입력이 아니라, 터미널이 주행하는 대화에 얹힌 추가 표면일 뿐이다. 그릴링은 한 번에 한 질문씩, 워크플로우 밖에 그대로 남는다.

## Considered Options

- **(iii) 전면 브라우저 진행 — 에이전트가 이벤트를 기다리고 터미널을 아예 안 씀 (기각).** 기술적으로는 가능하다: `events`가 채워질 때 종료하는 백그라운드 대기 프로세스를 띄우면 Claude Code가 에이전트를 재호출하며, forge는 이미 Claude Code 전용이라(ADR-0025) 하니스 의존이 규약 위반도 아니다. **기각 근거는 실현 가능성이 아니라 비용/편익이다** — 편익은 질문당 키 입력 한 번인데, 비용은 새 스크립트 트윈 + parity 테스트(ADR-0022) · 사용자가 터미널에도 입력했을 때의 이중 wake 경합 처리 · 방치 타임아웃 · 그리고 **fg-ask의 턴 구조 변경**(forge에서 가장 설계 민감한 영역)이다. 기둥 1의 *문자*를 위반하지는 않지만 *취지*(살아 있는 대화)와 마찰한다.
- **자유 텍스트 위젯 자체를 넣지 않음 (사용자가 기각).** 터미널이 이미 텍스트 채널이고 브라우저 textarea는 편집·히스토리·붙여넣기가 열등하다는 반대가 제기됐으나, 목업 옆에서 맥락과 함께 답하는 값을 우선해 사용자가 도입을 선택했다.
- **터미널 우선 / 최신 타임스탬프 우선 충돌 해소 (기각).** 터미널 우선은 브라우저 입력을 **조용히 버리는데**, 그건 이 리포가 다른 곳에서 제거한 패턴이다(ADR `260727-201115` — 새 요청을 버리지 않는다). 최신 타임스탬프 우선은 터미널 메시지가 **항상 턴을 깨우므로 늘 나중**이어서 터미널 우선과 동일해 무용하다.
- **"단독 메시지" 제안 규율 완화 (기각).** 불만은 **가시성**("안 뜬다")이므로, 제안을 긴 그릴링 메시지에 실으면 실패 모드가 "떴지만 못 봤다"로 바뀔 뿐이다. 게다가 이 규율이 비발동의 원인이라는 증거를 댈 수 없다(에이전트 내부 추론은 관측 불가). ADR `260719-224442` 절 3이 상속한 규율(1회·단독 메시지·거절 존중·질문 단위 라우팅)은 **그대로 유지**한다.

## Consequences

- **ADR `260719-224442` 절 3이 좁혀진다.** 제안 규율(1회·단독 메시지·거절 존중·질문 단위 라우팅)은 상속한 그대로 유지되지만, 같은 ADR이 함께 상속한 **"표시 전용"** 성격은 더 이상 성립하지 않는다.
- **`.forge/CONTEXT.md`의 `Visual Companion` 항목이 개정된다** — "표시 채널 / 답변의 주 채널은 터미널"이라는 정의가 결정과 어긋나므로.
- **새 입력 위젯은 `.mock-input`을 재사용하지 않는다.** 그 클래스는 와이어프레임 **소품**(목업 안에 "입력칸이 있다"를 그리는 장식, 이벤트 미전송)이므로, 살아 있는 입력에 같은 이름을 쓰면 두 개념이 한 이름을 공유한다.
- **vendored 5파일은 무변경이므로 업스트림 재-vendoring 시 충돌면이 늘지 않는다.**
- 소비자 문서 정합 대상: `README.md`+`README.ko.md`(이중언어 쌍), `docs/skills.md`(표 행 + 섹션), `CLAUDE.md`의 fg-visual 단락. `docs/index.html`은 fg-visual을 언급하지 않아 대상이 아니다.
