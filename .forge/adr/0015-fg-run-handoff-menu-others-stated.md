# fg-run 핸드오프는 3지 메뉴, 나머지 루프 핸드오프는 진술형 — 체이닝은 fg-next 전담

## Status
accepted

## 맥락
"상태를 너무 자주 묻는다"는 피드백. 한 작업을 수동 루프로 돌리면 단계 경계마다 "다음 단계로 진행할까요?" 확인이 4회(fg-ask "실행?"·fg-run "회고?"·fg-learn "봉인?"·fg-done "후속?") 발생한다. 이게 체감 부담의 본체다. 그런데:

- **CLAUDE.md 핸드오프 규약은 이미 "전한다(state)"** — "각 스킬은 끝에서 '방금 한 것/다음 단계/시작하는 법'을 대화체로 **전한다**"(CLAUDE.md). 실제 스킬 핸드오프 텍스트가 "ask whether to continue + invoke next skill"로 드리프트했을 뿐이다.
- **fg-next가 이미 "행동하는 형제"** — 다음 단계를 도출해 별도 go-ahead 없이 실행한다(one-shot), `fg-next all`은 무인 주행하며 회고를 자동 skip(ADR-0010).

즉 전환 허락 질문은 규약과 어긋난 드리프트이고, 체이닝 욕구는 fg-next가 이미 흡수한다.

## 결정
**전환 허락 질문("진행할까요?")은 핸드오프에서 걷어내되, 분기가 가장 많은 fg-run 종료만 명시 메뉴로 둔다. 체이닝은 fg-next 전담.**

- **fg-run 단일작업 핸드오프 = 3지 명시 메뉴**(UAT로 `verified:` 기록한 *뒤*):
  1. **회고** → fg-learn (기본)
  2. **바로 종료** → 회고 skip(`retro: skipped (사유)` 기록) 후 **fg-done을 인라인 호출해 봉인까지** = 루프 닫기
  3. **프롬프트로 나가기** → 실행만 둔 채 정지(검증값은 기록됨, 회고·봉인은 사용자가 나중에)
  - **회고 skip 가드(ADR-0002) 유지**: "바로 종료"는 **저-divergence일 때만** 제시한다. divergence가 크면 "바로 종료"를 빼고 회고를 권한다(그때야말로 배울 게 있으므로).
- **fg-ask·fg-learn·fg-done 핸드오프 = 진술형**: 다음 단계와 트리거를 알리고 **정지**한다("진행할까요?"를 묻지 않는다). fg-ask의 실행모드 질문(워크플로우 vs 직접)도 제거 — fg-run이 "Estimate cost first"로 자체 결정하므로 중복. fg-status의 "may ask whether to continue"도 진술로 통일.
- **체이닝(동의 시 다음 스킬 자동 호출)은 fg-next 전담**. 예외는 fg-run "바로 종료"의 fg-done 인라인 호출뿐 — 이건 나그가 아니라 **사용자가 명시 선택한 종료의 이행**이다.
- **fg-next 불변**: `fg-next all`은 fg-run 메뉴를 자동 해소(회고 skip+seal, ADR-0010), `fg-next`(one-shot)는 메뉴를 노출한다("한 걸음만" 원칙 — 호출된 스킬의 핸드오프가 이후를 이어받음).

## 트레이드오프 / 결정 근거
- **왜 fg-run만 메뉴이고 나머지는 진술인가** — fg-run 종료는 분기가 셋(회고/skip+봉인/중단)으로 루프 최대 분기점이라, 한 번의 명시 메뉴가 군더더기보다 명료함을 준다. 나머지 경계는 다음 단계가 하나로 자명해(ask→run, learn→done, done→새 ask) 진술이면 충분하고 질문은 나그가 된다.
- **"fg-next면 자동"의 구현** — 스킬은 마크다운 지시문이라 *호출자를 런타임에 감지할 수 없다*. 따라서 "fg-next가 부르면 자동, 사람이 부르면 묻기"를 스킬 내 분기로 만들 수 없고, 대신 fg-next가 오케스트레이터로서 흐름을 쥔다는 기존 사실(`all`은 자동 주행)에 기댄다. 새 메커니즘 0.
- **수동 인라인 체이닝 편의 일부 포기** — 이제 단계 이어가기는 fg-next로. 단 입력 횟수는 사실상 동일(핸드오프에서 "네" 한 번 ↔ `forge next`/`fg-next all` 한 번)이라 회귀가 아니다.

## 고려한 대안
- **전 핸드오프 진술 통일(메뉴 없음)** — 거부: fg-run 종료 분기가 많아 사용자가 매번 fg-learn/fg-done을 수동으로 골라 쳐야 해 오히려 불편.
- **전 핸드오프 메뉴화** — 거부: 나머지 경계는 분기가 단순해 메뉴가 과하고, 원래 "너무 자주 묻는다" 불만을 악화.
- **호출자 감지로 자동/수동 분기** — 거부: 스킬은 호출자 감지 불가.
- **현행 유지** — 거부: 피드백의 실제 고통이고, 스킬이 자기 규약(CLAUDE.md "전한다")과 어긋나 있다.

## Consequences
- README 양쪽 "Overall flow"의 "asks whether to continue right away, and invokes the next skill on agreement" 서술이 부정확해지므로 함께 갱신해야 한다(체이닝은 fg-next로).
- CLAUDE.md 핸드오프 규약에 "전환은 진술, fg-run만 3지 메뉴, 체이닝은 fg-next, '진행할까요?'를 핸드오프에 재추가 금지"를 명문화해 드리프트 재발을 막는다.
- TDD 매작업 질문(ADR-0008)은 이번 범위 밖 — 별도 결정으로 둔다.
