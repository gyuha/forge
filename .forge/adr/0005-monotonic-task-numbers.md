# 작업에 단조증가 고정 번호(#N)를 부여한다

## Status
accepted

## 맥락과 결정
status에 작업 번호가 나오고 fg-run에서 그 번호로 지목하고 싶다는 요구가 나왔다. 직전 0.2.7은 **위치 기반 표시 행 번호**(섹션마다 1부터, 정렬 바뀌면 번호도 바뀜)였는데, "작업마다 번호를 매기고 fg-run에서 사용"하려면 **고정된 식별 번호**가 필요하다 — 위치 번호는 안정적이지 않아 지목용으로 못 쓴다.

그래서 **단조증가 고정 작업 번호(#N, 이슈 번호처럼)**를 도입한다:
- **fg-ask가 plan 생성 시 부여** — 기존 모든 작업의 `<!-- task: N -->` 마커 중 최댓값 + 1(없으면 1). `<!-- task: N -->` 마커로 plan에 박혀 backlog→active→done 동안 불변(forge-slug와 동일 영속).
- **status**의 No. 컬럼이 이 고정 번호를 표시(0.2.7의 위치 행번호를 **대체**). 번호 없는 과거 작업은 `—`.
- **fg-run**은 메뉴 라벨에 `#N`을 보이고 그 번호로 지목·선택하게 한다. 정렬은 여전히 `priority`가 담당하고, 번호는 정체성(선택 키)일 뿐 순서가 아니다.

## 결정 근거 / 트레이드오프
- **별도 카운터 파일 없이 max+1 도출** — forge의 "상태의 원천은 파일"이라는 원칙과 일치. done/이 git 미추적이라 클린 클론에선 번호 시퀀스가 로컬 한정이지만, 번호는 done/ 아카이브처럼 로컬 작업 참조용이라 수용 가능.
- **앞으로 생성분만(소급 없음)** — 봉인된 done/ 아카이브를 사후 편집하지 않는다(churn 회피). 기존 9건은 `—`.
- **0.2.7 위치 번호를 1버전 만에 대체** — 위치 번호와 고정 번호를 둘 다 두면 숫자 컬럼이 둘이라 혼란. 지목 가능한 고정 번호가 사용자의 실제 요구라 위치 번호는 폐기.
- 범위: 정식 루프 작업(plan 기반)만. fg-quick의 `.forge/quick/LOG.md` 항목은 별도 경량 차선이라 번호 대상 아님.

## 고려한 대안
- 위치 표시 번호 유지(0.2.7) — 거부: 정렬 따라 바뀌어 fg-run 지목에 못 씀.
- 전용 카운터 파일(.forge/seq) — 거부: 새 상태 파일 추가. max+1 도출이 더 forge답고 충분.
- 기존 9건 소급 넘버링 — 거부: 봉인 아카이브 사후 편집 churn.
