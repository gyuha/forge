# fg-adversarial-review — 회고 전 선택적 적대적 리뷰 (루프 밖 유틸리티)

## Status
accepted

## 맥락
ADR-0007은 "run↔learn 사이 새 루프 단계(fg-review)"를 4단계 루프·상태 계약·전 문서를 건드리는 큰 변경이라 거부하고, 대신 **fg-run 워크플로우 안의 조건부 코드 리뷰**(위험/크기 게이트, 자동 실행)를 택했다. 그러나 그 코드 리뷰는 자세(코드 품질 체크)·범위(버그·보안·구조)·발동(자동)·위치(워크플로우 내부)가 고정돼 있다.

사용자가 원한 것은 다르다 — **"이 결과물이 틀렸다고 가정하고 증거를 찾는" 적대적 자세**로, 코드뿐 아니라 ① 실패 지점 ② 숨은 가정 ③ 요구사항 오해 ④ 보안·성능·데이터 손실 ⑤ 예상 못한 오용 ⑥ 약하거나 미검증된 근거까지 반증하며, **사용자가 선택적으로 발동**하고 **run 후 회고 전**에 도는 검토다. 자세·범위·발동·위치가 모두 0007과 달라 0007의 단순 반복이 아니다.

## 결정
**`fg-adversarial-review`를 루프 밖 on-demand 유틸리티 스킬로 도입한다**(fg-map·fg-status와 동류) — 정식 단계가 아니므로 4단계 루프 모양은 보존된다(ADR-0007의 거부 근거를 우회).

- **워크플로우로 실행**: 적대적 리뷰는 사용자 입력이 필요 없는 자동 분석이라 기둥 1("그릴링만 워크플로우 밖")에 걸리지 않는다. 6개 렌즈를 **dynamic workflow의 렌즈별 서브에이전트로 병렬 팬아웃**(Workflow의 dimensions→find→adversarially-verify 패턴)해 한 패스보다 철저히 검토한다. 단 워크플로우 실행 중 사람 입력 불가 → findings 판단·수정 승인은 워크플로우 후 핸드오프에서(ADR-0007과 동일 제약).
- **입력**: `plan.md`(의도·요구사항·설계), `run.md`(계획↔실제), **현재 작업 트리의 uncommitted 변경**(`git diff` + untracked — forge는 커밋을 강제하지 않아 fg-run 직후엔 보통 미커밋), 정답 기준(`CONTEXT.md`·관련 ADR — 요구사항 오해 판정 근거).
- **검증과 별개·비-게이트**: 순서는 `run → verify(UAT) → [적대적 리뷰(선택)] → learn → done`. UAT(`verified:`)는 봉인 필수 게이트로 불변, 적대적 리뷰는 순수 선택이라 봉인을 막지 않는다.
- **findings 처리**: 휘발 `.forge/review.md`(활성 슬롯 동반)에 구조화 기록. STATUS.md에 기록용 `reviewed:` 필드(`<경로> (N findings, M→fix-forward)` / `skipped` / 없음) — 봉인 게이트 아님. 학습 가치는 fg-learn이 retro로 승급, fg-done이 봉인 시 review.md를 done/으로 아카이브.
- **수정 라우팅**: findings가 수정을 요구하면 fg-loop(ADR-0016) fix-forward와 동형으로 **새 backlog plan**(`<!-- generated-by: fg-adversarial-review -->` 마커, 단조 task 번호)을 사람 승인 후 생성 → fg-run이 실행. 원 작업은 그대로 봉인 가능, 수정은 별도 사이클.
- **발동**: fg-run 핸드오프의 진술형 포인터 한 줄 + 사용자 명시 호출(ADR-0015의 4지 메뉴는 불변 — 메뉴 항목 아님).
- **자동 모드 skip**: fg-next all·fg-loop 무인 주행에선 회고처럼 항상 자동 skip(findings 진위·수정 판단은 사람 몫).
- **이식성**: 코어 Agent/Workflow로 구성, 외부 스킬(code-review 등) 하드 의존 금지 — 가용 시 선택적 보강(ADR-0007 정신).

## ADR-0007과의 관계
보완 관계다. **0007 = 위험 변경에 대한 자동 품질 리뷰(워크플로우 내부, 게이트)**, **0018 = 사람이 발동하는 선택적 심층 적대 반증(run 후, 비-게이트)**. 둘은 공존하며 어느 쪽도 다른 쪽을 대체하지 않는다.

## 고려한 대안
- **정식 5번째 루프 단계 fg-review** — 거부: ADR-0007이 이미 기각한 안. 4단계 루프·상태 계약·전 문서를 건드리는 큰 변경.
- **ADR-0007 워크플로우 내 리뷰를 적대적으로 확장** — 거부: "선택적·run 후·설계/요구사항 비판"이라는 위치·발동과 안 맞고, 자동이라 선택성을 잃는다.
- **포인터만(자동 라우팅 없음)** — 거부: "수정 시 다시 fg-run"이라는 핵심 흐름이 끊긴다. fix-forward plan 생성으로 수정 사이클을 명시적으로 잇는다.
- **봉인 게이트에 `reviewed:` 추가** — 거부: 선택적인데 게이트로 두면 모순(안 하면 봉인 못 함). 기록용 필드로만 둔다.

## Consequences
- 루프 밖 스킬이 11개로 늘어난다(루프 4 + 밖 11 = 총 15 스킬).
- 휘발 상태에 `.forge/review.md`가 추가된다(활성 슬롯 동반, 봉인 시 done/ 아카이브).
- STATUS.md에 기록용 `reviewed:` 필드가 추가된다(봉인 게이트는 아님 — `verified:`/`retro:`만 게이트).
- fg-run(핸드오프 포인터)·fg-learn(review.md retro 승급)·fg-done(review.md 아카이브)·fg-next/fg-loop(자동 skip)가 이 스킬을 인지해야 한다 — 상태 계약면이 하나 늘어난다.
