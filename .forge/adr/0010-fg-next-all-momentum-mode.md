# fg-next `all` — 대화의 벽까지 자동 주행하는 모멘텀 모드

## 맥락
forge는 사람-게이팅이 핵심 철학이다: fg-status는 다음 단계를 보고만 하고 절대 자동 실행하지 않으며(ADR 없음, 설계상 read-only), fg-next 본체는 one-shot + confirm-then-delegate(한 단계마다 한 번 확인 후 위임)다. 하지만 저-divergence 문서 작업을 여러 건 연달아 돌릴 때는 단계마다·작업마다 확인을 받는 것이 마찰이 된다. `fg-next all`은 "다음 작업이 없을 때까지 추천값으로 알아서 진행"하는 모멘텀 모드 요청이다.

## 결정
`fg-next all`(인자 `all`)은 백로그가 빌 때까지 루프를 자동 주행하되, **선형 기계적 단계만 추천값으로 자동 진행하고 환원 불가능한 지점에서는 멈춰 사람에게 돌려준다.** 구체적으로 forge의 두 게이트를 의도적으로 완화한다:
1. **confirm-then-delegate → 시작 1회 확인.** 진입 시 동결된 백로그 순서 + 각 작업의 자동 처리/멈춤 조건을 한 번 요약·확인받고, 이후 작업당 확인 없이 주행(fg-run "Run all"의 "순서 1회 확인" 패턴과 동형).
2. **retro-default → 저-div 자동 skip.** divergence가 낮은 작업은 회고를 자동 skip(`retro: skipped (fg-next all 자동 진행 — 저-divergence)`)하고 봉인해 계속 진행하며, divergence가 큰 작업은 멈춰 사람에게 회고+재그릴을 위임한다.

**halt(멈춤) 조건** — 다음에 닿으면 주행을 멈추고 현황·이유·해당 트리거를 보고한다: `verified: failed` / 봉인 가능 값(`yes`·`n/a`)에 도달 못 한 미검증 / 진짜 fork(failed→fix|re-grill 등) / 고-divergence 회고 / 빈 상태(새 작업 그릴링은 사람이 내용 공급). 봉인 전 UAT는 **공격적으로 자동 시도**한다 — 에이전트가 돌릴 수 있는 검증(테스트·grep·빌드)으로 `yes (증거)`/`n/a`를 기록하고, 봉인 가능 값에 못 닿으면 멈춘다. halt 후 재개는 별도 상태 없이 사람이 벽을 해소한 뒤 `fg-next all`을 다시 치면 된다.

## 고려한 대안
- **항상 회고에서 멈춤**: 가장 안전하나 fg-run "Run all"과 거의 같아져(회고까지 못 감) "계속 진행"의 가치가 없다.
- **항상 회고 자동 skip**: 가장 빠르나 고-divergence의 진짜 학습을 조용히 잃고 기둥 #1(회고는 대화)을 정면 위반.
- 채택안은 둘 사이 — "가치 낮은(저-div) 회고는 버려 모멘텀, 가치 높은(고-div) 회고는 멈춰 보존".

## 결과
- 기둥 #1(그릴링·회고는 대화)은 유지된다: all-mode는 회고 대화를 자동으로 *치지* 않는다. 저-div에서 비대화적 결정인 *skip*만 자동화하고, 대화가 필요한 고-div에서는 멈춘다.
- 재실행-방지는 유지된다: 봉인이 활성 상태를 비우는 메커니즘은 그대로이고, all-mode는 시작 1회 확인으로 무인 진입을 게이팅한다.
- fg-run "Run all"과의 관계: Run all은 execute-only(검증 후 `executed/` 파킹, 회고에서 멈춤)인 반면, all-mode는 그 상위집합으로 verify→(저-div skip)→cleanup→다음 작업 승격까지 몬다. 두 기능은 공존한다.
