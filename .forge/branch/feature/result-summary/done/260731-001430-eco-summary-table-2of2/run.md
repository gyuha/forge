## 계획대로 진행된 것

- 배치·무인 경로 전부에 eco 1행 표 분기가 걸렸다: RUN-ALL.md(Run all) · fg-done `all` · DRIVE.md(fg-next all·fg-loop 공유) · fg-next SKILL §2 위임 봉인 · fg-next autochain.
- **단일 정의 유지**: 표 스켈레톤을 가진 파일은 여전히 `skills/fg-eco/ECO.md` 하나뿐(grep 확인). 소비자 5곳은 전부 참조만 한다.
- **fg-loop을 건드리지 않은 것이 정답이었다.** S4의 완료 기준대로 실제로 읽어 확인했다 — fg-loop은 `DRIVE.md` Part 1을 참조(L83)하고 봉인 간결/요약 규칙을 자체 서술하지 않으므로 상속으로 충분하다. 여기에 중복 정의를 넣었다면 단일 정의 규율 위반이었다.
- 검증 게이트(ADR-0009)·회고 skip 규율(ADR-0010)·봉인 스크립트(ADR-0030)·`all` 모드 업프론트 확인 게이트 불변.
- `fg-doctor` 0/0/0, 매니페스트 JSON 유효.

## 계획과 실제의 차이 (divergences)

1. **(중, S6) 감사가 계획서에 없던 위임 봉인 경로를 하나 찾아냈다 — `fg-ask` STEP 0 자동 마감.** plan의 6슬라이스는 Run all·`fg-done all`·DRIVE·fg-next만 열거했으나, `skills/fg-ask/SKILL.md`의 STEP 0 미봉인-잔여 자동 마감도 ADR-0032를 인용하는 **위임 봉인 경로**다(ADR `260727-201115`). 정확히 회고 `2026-07-06` F2가 경고한 실패 유형 — *"뻔한 위임 경로만 커버하고 상태머신이 그 스킬로 가는 다른 길을 놓쳤다"* — 의 재발이며, 이번엔 **S6 감사 슬라이스가 그 재발을 잡았다**(감사를 슬라이스로 둔 것의 값이 실증됨).
   - 처리: eco 분기를 추가하지 않고 **명시적 제외**를 달았다. 이유는 그쪽이 옳기 때문이다 — STEP 0은 한 줄로 보고하고 곧바로 그릴링을 잇는데, 한 줄은 이미 어떤 표보다 짧으므로 표를 넣으면 **더 길어져** 이 기능의 목적에 반한다. "누락이 아니라 의도된 제외"임을 파일에 적어 다음 감사자가 다시 의심하지 않게 했다.

2. **(중, S1) ADR-0032 개정이 계획서가 요구한 "왜 되돌림이 아닌지"를 넘어 판별 *기준*을 세웠다.** plan은 근거 서술만 요구했으나, 위 1번의 fg-ask 케이스가 "그럼 어디까지 표를 넣어도 되나"를 강제로 물었다. 답은 **길이 테스트**다 — *위임 경로에 더 **긴** 것을 넣는 변경은 여전히 ADR-0032가 금지하는 되돌림이고, 더 **짧은** 형태로 바꾸는 것은 아니다.* 이 기준을 개정 (c)에 명문화했다. 계획보다 강한 산출물이며, 없었다면 fg-ask 케이스를 일관성 논리로 잘못 처리했을 것이다.

3. **(저) README×2는 part 2에서 추가 변경이 필요 없었다.** S6이 README 동기를 열거했으나, part 1에서 이미 "batch/unattended paths"를 포함해 서술했으므로 이미 정확했다. 억지로 손대지 않았다.

4. **(저) `docs/state-contract.md`에 run.md 슬라이스 한 줄 규정을 추가했다.** part 1이 만든 규정인데 상태 계약 문서에 반영이 없었다 — S6의 "필요하면"에 해당해 이번에 넣었다(재료 보장의 근거와 `RUN-FORMAT.md` 부재 이유까지).
