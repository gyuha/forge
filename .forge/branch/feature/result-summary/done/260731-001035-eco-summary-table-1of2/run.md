## 계획과 실제의 차이 (divergences)

1. **(S5, 저) 열거 개수가 "둘→셋"이 아니라 "넷→다섯"이었다.** plan은 CLAUDE.md의 "켜면 두 가지를 활성화" 문구를 근거로 삼았으나, `skills/fg-eco/SKILL.md`는 더 세분화된 **네 가지** 행동을 열거하고 있었다(모델 캡 / 서브에이전트 주입 / fg-ask YAGNI 렌즈 / 현 세션 채택). 두 문서가 서로 다른 입도로 세는 것이 정상이므로 각각 맞게 갱신했다 — SKILL.md는 5번 행동 추가, CLAUDE.md는 "세 가지". plan의 전제가 틀린 게 아니라 한쪽 문서만 보고 개수를 적은 것이다.

2. **(저) ECO.md 도입부 활성화 목록에 "(4)"를 추가하지 않고 문장을 덧붙였다.** 그 목록 `(1)(2)(3)`은 규율이 주입되는 **채널**(fg-ask 그릴링 / 서브에이전트 프롬프트 / 메인 세션)을 세는 것이고, 요약 표는 채널이 아니라 채널 (3)을 타고 전달되는 **내용**이다. `(4)`로 넣으면 채널과 내용을 섞게 되므로 "그 세 번째 채널을 통해 작업 종료 출력도 재구성한다"는 문장으로 처리했다. plan에 명시되지 않은 판단.

3. **(중, 주목) §3의 조건부 리뷰 단계를 서브에이전트 팬아웃이 아니라 수동 자기검증으로 수행했다.** 이 세션은 에이전트 위임이 허용되지 않아(사용자 지시) `fg-adversarial-review`식 6렌즈 병렬 팬아웃을 돌릴 수 없었다. 대신 완료 기준을 grep으로 기계 확인했다 — 표 스켈레톤 유일성, ECO.md 섹션 존재, 행동 열거 개수, readers 목록, docs 번호 목록 렌더링, 매니페스트 JSON 유효성, fg-doctor. **이것은 적대적 리뷰의 대체물이 아니다.** 같은 영역 회고(`2026-07-06`)가 *"'사소해 보이는' doc/지시 변경에도 적대적 리뷰가 실제 결함을 캔다 — 이번에 5건"*을 명시적으로 남겼으므로, 이 작업도 봉인 전 `fg-adversarial-review`를 돌릴 값이 있다. 미수행 상태를 그대로 기록한다.

4. **(저) 매니페스트를 python json 라운드트립으로 수정했다.** 문자열 치환이 아니라 파싱→수정→재직렬화라 전체 리포맷 위험이 있었으므로 `git diff --stat`으로 **파일당 1행만** 바뀐 것을 확인했다(기존 포맷이 이미 `indent=2`와 일치).

## 남은 관찰

- **`docs/skills.md`와 `CLAUDE.md`는 챕터·열 이름을 서술한다.** 형태의 약한 중복이지만 "단일 정의" 규율은 **에이전트가 읽고 행동하는 스킬 지시문**을 규율하는 것이고, 이 둘은 사람이 읽는 카탈로그 문서다(CLAUDE.md는 다른 모든 스킬을 이미 이런 밀도로 서술한다). 위반으로 보지 않았으나, ECO.md의 열 구성을 나중에 바꾸면 이 두 곳도 손대야 한다는 유지보수 부담은 실재한다.
- **part 2/2 미실행** — 배치·무인 경로(Run all·`fg-done all`·DRIVE.md·fg-next)와 ADR-0032 개정은 아직 종전 상태다. 이것은 part 분할의 **의도된 중간 상태**이며, 그 사이 eco on으로 `fg-next all`을 돌리면 배치 경로는 종전 산문으로 보고된다.
