# 적대적 리뷰 — fg-rules 변경 사항

판정: 확정 지적 0건 · 수정 필요 0건 · critical 0 / major 0 / minor 0.

검토일: 2026-10-20. 활성 작업의 plan.md·run.md·CONTEXT.md와 관련 계약, 추적 파일의 git diff 및 미추적 `skills/fg-rules/`를 검토했다. 여섯 관점을 독립 에이전트로 나누고 가용 슬롯에 맞춰 순차적으로 합류했다. 구현 파일·계획·실행 기록은 변경하지 않았다.

## 1. 실패 지점

확정 지적 없음. 일부 후보 채택, 마지막 규칙 삭제, 수동 수정, 주제 한정 갱신, 충돌 지침, 브랜치 경로, 부모 디렉터리 ignore 사례를 대입했다.

`skills/fg-rules/SKILL.md`의 선택 후 종속 변경 재계산·삭제 승인·재읽기 절차와 `CONNECTIONS.md`의 연결 및 추적 확인이 해당 경계를 명시한다.

## 2. 숨은 전제

확정 지적 없음. 프로젝트 루트 해석, 호스트 지침 탐색, override·중첩 지침, 크기 제한, 승인 순서, 동시 수정, 지도 노후화를 검토했다.

호스트 로딩은 공식 문서 또는 실제 로더 근거를 확인하고, 확인할 수 없으면 수동 읽기 및 미검증 상태로 보고하도록 되어 있다. 스킬 로딩과 일반 프로젝트 지침 로딩을 같은 것으로 취급하지 않는다.

## 3. 요구사항 오해

확정 지적 없음. 사용자가 확정한 일곱 결정이 구현 계약에 반영되어 있다.

한영 README 및 스킬 카탈로그의 집합을 실제 23개 스킬과 교차 확인했다. 매니페스트 세 파일에 명령 설명이 반영됐고, fg-help의 동적 탐색과 호환된다. fg-map의 사실 기록과 채택된 규칙의 권위가 구분된다.

## 4. 보안·성능·데이터 손실

확정 지적 없음. 정확히 검토한 패치만 적용하고, 부분 채택 후 새로 필요한 변경은 다시 검토하며, 적용 직전에 현 파일을 읽도록 되어 있다. 수동 내용·중첩 정책·관련 없는 파일을 보존한다.

비밀 값·생성물·vendor 분석 제외, 대표 소스와 관련 지도만 읽기, 전역 설정 및 자동 git 게시 금지를 확인했다. 가정만으로 취약점이나 무한 탐색 결함을 보고하지 않았다.

## 5. 예상 밖 사용

확정 지적 없음. 실행 명령처럼 보이는 주제 인자, 기존 INDEX의 다른 용도, 지침 파일 부재·독립·위임·중첩, 거절 및 일부 채택을 검토했다.

### 반증한 후보: 규칙 본문이 그대로인 연결 복구

기존 규칙은 올바르지만 새 호스트의 읽기 연결만 없는 경우, “후보 없음이면 종료”가 연결 복구를 막는지 의심했다.

- SKILL.md의 후보 정의는 작업 종류와 제안 지침을 요구하며 규칙 본문 변경만으로 한정하지 않는다.
- 전체 검토 패치에 프로젝트 지침 연결을 명시적으로 포함한다.
- CONNECTIONS.md는 대상 호스트에 필요한 누락된 진입점을 제안하도록 명시한다.

따라서 연결 추가 자체를 후보로 검토·채택하는 경로가 존재한다. “실제 변경 없음”은 연결 변경까지 포함하며, 이 사례에서 필수 종료로 이어진다고 입증하지 못했다. 문구를 더 명료하게 할 여지는 있지만, 관측된 오동작 없이 수정 필수 결함으로 올리지 않았다.

## 6. 약하거나 미검증된 결정

확정 지적 없음. 실행 기록과 임시 fixture 보고서 및 Codex/Claude 원시 이벤트를 대조했다. 두 호스트에서 INDEX.md와 testing.md를 실제 읽는 도구 호출이 있어 결과 문구만으로 로딩을 추정한 것이 아니다.

다음 한계는 실행 기록에 이미 구분되어 있으며 이번 리뷰도 해소한 것으로 주장하지 않는다:

- 합성 fixture는 가능한 모든 프로젝트·재실행 상황을 포괄하지 않는다.
- Pi/opencode의 일반 새 세션 규칙 로딩은 관측하지 않았다.
- 기존 정책을 명시적으로 뒤집는 분기와 동시 외부 수정 감지는 계약 검토 수준이다.
- 브라우저 스크린샷 캡처는 실패했고 DOM·자산·테마·계산된 명암비로 확인했다.

## 검토 범위와 처리

이번 리뷰는 계약·변경 파일·기존 검증 증거를 공격적으로 검토한 것이다. 빌드나 실제 호스트 세션을 다시 실행하지 않았으며, 결함 부재나 미래 AI 준수를 보증하지 않는다.

수정 계획을 만들 근거가 없어 fix-forward 백로그를 생성하지 않았다. STATUS에는 기록용 reviewed만 추가하고 verified·retro는 유지한다. 다음 단계는 기존 작업의 fg-learn 회고다.
