# fg-rules: 프로젝트 규칙 제안·검토·저장과 일반 AI 작업 연결

## 목표 / 비목표

- 목표: `/forge:fg-rules [주제]`로 현재 프로젝트를 분석하고, 근거와 적용 범위를 가진 규칙 후보를 제안한다. 사용자가 채택한 규칙만 저장하고 일반 AI 코딩 작업에서도 읽도록 프로젝트 지침에 연결한다.
- 목표: 재실행 시 기존 규칙과 직접 수정을 보존하며 추가·수정·삭제 후보를 검토한 뒤 선택한 변경만 반영한다.
- 비목표: fg-map 대체·자동 실행, 코드 자동 리팩터링, 린터/포매터 재구현, 작업마다 자동 재분석, 새로운 훅·데몬, AI 준수의 강제 보장, 사용자 전역 설정 수정, 모든 외부 AI 도구용 포맷 동시 생성, 이번 계획 작성 중 구현·배포.
- 루프 밖 유틸리티로 구현한다. 사용자가 대상 프로젝트에서 fg-rules를 호출해도 활성 plan/run/STATUS/backlog를 변경하지 않는다.

## 합의된 동작

사용자가 일곱 번의 선택으로 확정한 내용:

1. 분석 후 후보를 검토하여 채택한 규칙만 저장한다.
2. TDD off. 구현 후 시나리오와 기존 검사로 검증한다.
3. forge 명령 밖의 일반 AI 작업에서도 적용되도록 프로젝트 지침과 연결한다.
4. 본문은 `.forge/rules/`에 주제별로 저장하고 AGENTS.md·CLAUDE.md 등의 지침에는 읽기 연결을 둔다.
5. 기존 지침이 우선이다. 충돌 후보는 알리고 보류하며, 명시적으로 선택한 변경만 기존 지침과 함께 수정한다.
6. 재실행은 추가·수정·삭제 제안 방식이다. 기존 내용과 사용자의 직접 수정은 자동 덮어쓰기하지 않는다.
7. 기본은 프로젝트 고유 규칙 전반이다. 네이밍·파일 배치·의존 경계·에러 처리·테스트 등을 살피며 린터/포매터가 이미 강제하는 내용은 중복하지 않는다. 주제를 지정하면 범위를 좁힌다.

구현 시 적용할 기본 설계:

- `.forge/rules/`는 프로젝트 루트 기준의 공통 영속 경로다. `.forge/branch/<branch>/rules/`로 옮기지 않는다. git 브랜치의 파일 버전 관리는 그대로 적용되며, 다른 worktree까지 공유하는 외부 저장소를 만들지 않는다.
- 짧은 색인과 필요한 주제 파일만 생성한다. 색인에는 적용 조건과 경로를 두고, 지침에는 공통 규칙과 현재 작업에 해당하는 주제를 읽으라는 명시적 지시를 둔다. 링크만 추가하고 자동 로드가 보장된다고 보고하지 않는다.
- 규칙마다 적용 범위, 행동 지침, 실제 근거 경로를 남긴다. 필요한 경우만 예외·짧은 예시를 넣는다. 채택 전 후보는 대화에서 제안하며 영속 규칙처럼 취급하지 않는다.
- 기존 AGENTS.md/CLAUDE.md와 중첩 지침, 기존 rules, 설정을 먼저 읽는다. 기존 파일 간 위임 관계와 더 좁은 경로 지침의 효력을 보존한다. 본문 복제 없이 기존 읽기 경로를 재사용하고 새 연결은 최소한으로 추가한다.
- 호스트별 읽기 방식은 실행 시 공식 문서 또는 실제 로딩 증거로 확인한다. 검증된 대상에만 자동 적용을 주장한다. 미확인 호스트에서는 파일 생성과 수동 읽기 안내를 구분하고 한계를 보고한다.
- 지도가 있으면 관련 문서만 참고하고 현재 코드와 대조한다. 지도 부재·노후화가 작업을 막지 않으며 자동 fg-map 실행이나 지도 변경도 하지 않는다.
- 혼용·근거 부족·기존 지침과의 충돌은 명시적으로 보류한다. 단순 다수 패턴만으로 올바른 규칙이라고 확정하지 않는다.
- 승인 대상에는 규칙뿐 아니라 지침 연결 및 필요한 gitignore 변경도 포함해 구체적 변경안을 보여준다. 하나도 채택하지 않으면 규칙 디렉터리·지침 연결을 만들지 않는다.
- 재실행은 현 파일을 기준으로 차이를 제시한다. 미채택 변경은 적용하지 않고, 수동 수정과 삭제도 승인 없이 되돌리지 않는다. 변경 없음이면 중복 연결·재작성 없이 종료한다. 주제 한정 호출은 다른 주제를 수정하지 않는다.
- 영속 규칙이 gitignore에서 제외되지 않도록 필요한 최소 예외를 제안한다. 상위 디렉터리 제외 때문에 예외가 무효가 되는 경우도 검증한다. 자동 stage/commit/push는 하지 않는다.

## 완료 정의 및 사전 상태

### 기계 검사

1. `test -s skills/fg-rules/SKILL.md` — 전진 체크. 사전 exit 1: 아직 스킬이 없다. 생성 확인일 뿐 행동 검증은 아래 시나리오가 담당한다.
2. `npm run release:check` — 회귀 가드. 사전 exit 0, forge 0.9.6의 매니페스트·공유 스킬·호스트 계약이 통과한다. 새 명령 추가 후에도 기존 패키징 계약을 유지해야 하므로 미리 통과하는 것이 정상이다.
3. `npm run docs:build` — 문서 회귀 가드. 사전 exit 127, `vitepress: command not found`. 작업 트리에 문서 의존성이 없어 실행이 막힌 상태다. 구현 단계에서 lockfile에 맞게 의존성을 설치한 뒤 빌드하고, 실패를 기존 문제라는 이유로 통과 처리하지 않는다.

### 동작 시나리오

각 시나리오는 임시 프로젝트에서 새 스킬을 따라 수행한다. 검토 전후 파일 diff와 선택 내용을 증거로 남긴다. 사전 상태는 새 스킬 부재로 모두 미구현이다. 이 작업 자체가 실제 프로젝트 규칙을 임의로 채택하는 일이 되지 않도록 검증용 후보만 사용한다.

- A. 신규 프로젝트: 반복되는 패턴·예외·린터 강제 항목이 함께 있는 fixture에서 근거 있는 후보와 보류를 구분한다. 일부만 채택하면 선택한 규칙과 유효한 읽기 연결만 생성되고 미채택 후보는 저장되지 않는다.
- B. 기존 지침 충돌: 코드의 다수 패턴이 명시 지침과 다를 때 후보가 보류되고 원문은 유지된다. 명시적으로 변경을 선택한 경우에만 관련 지침과 규칙이 함께 바뀐다. 전부 거절하면 파일 변경이 없다.
- C. 재실행·수동 편집: 생성 규칙을 직접 수정한 뒤 다시 실행한다. 수정·삭제 후보는 표시되지만 승인 전에는 반영되지 않는다. 일부만 승인했을 때 다른 수동 수정은 바이트 단위로 보존된다. 동일 입력 재실행은 중복 연결을 만들지 않는다.
- D. 주제 한정: 테스트 규칙만 요청하면 다른 주제 파일과 지침 내용은 유지된다. 관련 주제가 없으면 무관한 규칙을 만들어 채우지 않는다.
- E. 지도 독립: 지도 없는 경우와 오래된/코드와 다른 지도가 있는 경우 모두 현재 코드 근거로 후보를 만든다. fg-map 자동 실행 및 지도 덮어쓰기가 없다.
- F. 지침 연결: 지침 없는 프로젝트, AGENTS.md→CLAUDE.md 위임이 있는 프로젝트, 두 파일이 독립적으로 있는 프로젝트, 중첩 지침이 있는 프로젝트를 확인한다. 기존 원문·우선순위를 유지하고 연결이 순환하거나 같은 본문을 복제하지 않는다.
- G. 일반 작업에서 읽힘: 기본/feature 브랜치에서 모두 최상위 `.forge/rules/`를 참조하고 git의 실제 ignore 판정상 영속 규칙 추적이 가능하다. 지원한다고 명시한 호스트의 새 일반 코딩 세션에서 forge 명령 없이 관련 규칙을 읽는 증거를 확인한다. 파일 링크 존재만으로 이 시나리오를 통과시키지 않는다. 실행 환경이 없는 호스트는 미검증으로 기록하고 지원 보장 문구를 제한한다.

문서 검토에서는 fg-map과 fg-rules의 차이, 채택 전 쓰기 금지, 삭제 포함 재검토, 수동 수정 보존, 일반 작업 읽기 연결을 각각 읽어 확인한다. 키워드 개수로 의미 검토를 대신하지 않는다. 문서 사이트를 실제 렌더해 검사할 때에는 CLAUDE.md의 다크모드·자산 요청·외부 링크 규약을 적용한다.
