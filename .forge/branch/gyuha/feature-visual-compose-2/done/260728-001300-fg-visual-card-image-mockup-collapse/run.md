## 계획대로 된 것

- **S1** — `skills/fg-visual/scripts/frame-template.html:147`의 `.card-image` 규칙을 계획에 적힌 그대로 교체했다. `aspect-ratio: 16/10` → `min-height: 180px`, 그리고 `.card-image > :only-child { width: 100% }` 추가. 파일 헤더 주석의 `forge modifications:` 목록에도 이 변경을 한 항목으로 추가해 upstream 대비 diff를 그 자리에서 설명하게 했다.
- **S2** — `skills/fg-visual/VISUAL.md`의 "Cards (visual designs)" 섹션에 안내 한 문단을 추가했다. 계획대로 `width:100%` 지시는 넣지 않고(그 필요가 CSS 수정으로 사라졌으므로) 남은 함정인 "단일 루트 요소로 감싸라"만 적었다.
- **S3** — 두 파일만 커밋했다 (`3309f91`). 활성 슬롯의 forge 상태(`plan.md`)는 커밋 경로에서 제외해 코드 변경과 섞이지 않게 했다.

## 계획과 달랐던 것

- **워크플로우를 쓰지 않고 직접 실행했다.** 계획에 실행 방식은 명시돼 있지 않았고, fg-run의 비용 추정 규율("단일 에이전트로 충분한 규모면 워크플로우를 건너뛴다")에 따라 판단했다. 실제 작업량은 CSS 2줄 + 문서 한 문단 + 커밋이었고, 수정안 자체는 그릴링 단계에서 이미 실측으로 확정돼 있어 탐색 여지가 없었다.
- **검증 폭을 3개에서 4개로 늘렸다.** 계획의 완료 기준은 1600/1200/900px였는데 700px(카드 1열로 떨어지는 지점)을 추가로 넣었다. 기준을 좁힌 게 아니라 넓힌 것이라 완료 판정에는 영향 없다.

## 중간에 내린 결정

- CSS 변경 위에 3줄 주석을 달았다. 계획에 없던 항목이지만, vendored 파일에서 upstream과 갈라지는 지점은 이유가 코드 옆에 있어야 나중에 upstream 동기화 때 "이건 왜 다르지"로 헤매지 않는다고 판단했다.

## 검증 증거

수정된 실제 파일로 프레임을 조립해 headless Chrome에서 계측했다. 대상은 이번 버그를 처음 드러낸 그 목업(카드 3개: 좁은 중앙 모달 / 넓은 2열 모달 / 우측 사이드 시트).

| 창 폭 | 슬롯 폭 × 높이 | 자식 폭 | 자식 높이 | 폭 일치 | 잘림 |
| --- | --- | --- | --- | --- | --- |
| 1600px | 499 × 280 | 499 | 280 | ✓ | 없음 |
| 1200px | 366 × 280 | 366 | 280 | ✓ | 없음 |
| 900px | 401 × 280 | 401 | 280 | ✓ | 없음 |
| 700px | 301 × 280 | 301 | 280 | ✓ | 없음 |

4개 폭 × 카드 3개 = 12개 케이스 전부 `자식 폭 == 슬롯 폭`, `슬롯 높이 >= 자식 높이`. 수정 전 같은 측정은 자식 폭 24px(슬롯 499px), 1200px에서 51px 잘림이었다.

계측에 쓴 임시 파일은 세션 스크래치패드에만 있고 리포에는 들어가지 않았다(계획의 "회고 없음 / 테스트 파일 미추가" 결정대로).
