# CONVENTIONS

이 문서는 **구현 사실만** 다룬다. 도메인 용어 정의는 `.forge/CONTEXT.md` 소관이다. 모든 경로·규칙은 이 커밋의 작업 트리에서 실제 파일로 검증했다.

## 0. 이 리포에서 "코드"란 무엇인가

**플러그인 본체에는 여전히 빌드·린트·테스트 시스템이 없다**(Makefile 없음). 산출물은 다섯 층이다:

1. **산문 스킬** — `skills/<name>/SKILL.md` **22개**(실측) + 동반 형식/규율 문서(`*-FORMAT.md`, `HANDOFF.md`, `DRIVE.md`, `FORGE-ROOT.md`, `ECO.md`, `RUN-ALL.md`, `VISUAL.md`, `DIAGNOSE.md` 등). **개수는 22로 같지만 구성원이 바뀌었다** — `skills/fg-eco/`·`skills/fg-tdd/`가 삭제되고 `skills/fg-config/`(config.json 여섯 키의 단일 진입점) 하나로 합쳐졌으며, `skills/fg-debug/`가 신설됐다(−2 +2). `ECO.md`는 삭제된 스킬과 함께 사라지지 않고 `skills/fg-eco/ECO.md` → **`skills/fg-config/ECO.md`로 이동**(R100, 내용 무변경)했고, 25개 파일이 이 새 경로를 참조한다 — **스킬 디렉터리를 없앨 때 그 안의 공유 규율 문서를 함께 지우지 말고 인수자에게 옮기는 것**이 여기서 나온 규약이다.
2. **결정론 스크립트 트윈** — `scripts/*.sh` + 동일 출력의 `.js`(ADR-0022). 이름이 전부 `forge-*`는 아니다 — 신규 `scripts/release-check.{sh,js}`가 접두 없는 첫 트윈이다(§2).
3. **매니페스트/훅** — `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, **`.codex-plugin/plugin.json`(신규, ADR `260903-080713`)**, `hooks/hooks.json`, `hooks/run-hook.cmd`. Codex 매니페스트의 `"skills": "./skills/"`가 Claude와 **같은 스킬 트리**를 로드한다(스킬 사본 없음).
4. **호스트 계약(신규, ADR `260903-080713`)** — `core/HOST.md`(57줄)·`core/EXECUTION.md`(9줄)·`core/INTERACTION.md`(6줄) + `hosts/claude/`·`hosts/codex/` 각 3파일(`capabilities.json`·`execution.md`·`interaction.md`). 산문이지만 **스킬이 아니다**(`skills/` 밖이라 자동 탐색되지 않는다) — 스킬이 참조하는 호스트-중립 계약 층이다(§7).
5. **문서 사이트 도구** — 루트 `package.json`(VitePress, `name: forge-docs`)·`package-lock.json`·`.github/workflows/docs.yml`. **대체로 문서 전용이지 플러그인 빌드가 아니다** — `docs/`의 Markdown을 `gyuha.com/forge/docs/`로 빌드·배포한다(ADR `260815-094725`). 단 **예외 하나**: `scripts` 첫 항목이 `"release:check": "node scripts/release-check.js"`로, 문서와 무관한 **플러그인 릴리스 게이트**가 이 `package.json`에 얹혀 있다(§5). **GitHub Actions 워크플로는 이제 둘이다** — `docs.yml`과 신규 `.github/workflows/release-check.yml`(`name: Release gate`)이고, 후자가 release:check 트윈 둘 + 그 parity 테스트를 실제로 돌린다(TESTING.md §8). 여전히 **나머지 20개 테스트 파일과 fg-doctor는 어떤 워크플로도 돌리지 않는다**(실측: `.github/workflows/`에 `fg-doctor`·`forge-doctor` 참조 0건).

> **루트 `package.json`에 `"type"` 필드 금지**(실파일 확인 — 없음). `scripts/*.js` 트윈이 전부 CommonJS(`require`)라 `"type": "module"`이면 리포 전체 `.js`가 ESM으로 해석돼 트윈이 죽는다. VitePress 설정은 `.mts` 확장자만으로 이미 ESM이다(ADR `260815-094725`).

## 1. 스킬 문서 작성 규약 (`CLAUDE.md` "스킬 편집 규약" — 실파일 검증됨)

- **`**Explaining forge**` 상시 규율(신규, ADR `260824-134246`).** `**Language**` 규칙 바로 옆에 같은 문단이 **22개 `skills/*/SKILL.md` 전부**에 박혀 있다(실측: 22/22 verbatim 포함). canonical 본문의 **단일 정의는 `scripts/explaining-forge.rule.txt` 한 파일**이고, 각 SKILL.md에는 그 텍스트를 **그대로 복사**한다 — 이 리포에서 유일하게 *의도된 인라인 중복*이며, 드리프트 가드로 fg-doctor **B17**이 그 canonical 본문을 **containment(부분문자열)로 verbatim 대조**한다(마커만 대조하면 문단을 지우거나 뒤집은 파일이 통과한다). containment라서 예외 목록이 필요 없다 — `skills/fg-ask/SKILL.md`는 canonical + 문장 1개를 덧댄 **superset**이라 그대로 통과한다. 심각도는 **warning**(설치·릴리스를 깨지 않는 산문 드리프트 — B12/B13/B15/B16/B18과 같은 등급), 범위는 **최상위 매니페스트 `name`이 `forge`일 때만**(사용자 프로젝트의 `skills/*/SKILL.md`에 forge 내부 규칙을 요구하지 않기 위한 스코프 가드, 중첩 `"name"`은 문서 순서 첫 항목만 읽어 회피).
- **본문은 영문, 출력은 사용자 언어.** `SKILL.md`·`*-FORMAT.md`는 영문으로 작성하고, 스킬이 화면에 내는 텍스트·산출 문서(plan/회고/ADR)는 사용자 언어를 따른다. "user's language" 지시가 실제로 박힌 파일: `skills/fg-run/SKILL.md`, `skills/fg-run/PLAN-FORMAT.md`, `skills/fg-next/SKILL.md`, `skills/fg-next/HANDOFF.md`, `skills/fg-agenda/SKILL.md`, `skills/fg-config/SKILL.md`, `skills/fg-showme/SKILL.md`, `skills/fg-run/RUN-ALL.md` 등.
- **canonical 영문 이름 + 사용자 언어 렌더.** 핸드오프 표의 행 라벨(`Just did`·`Next step`·`How to start`·`Alternative`, 헤더 `Item`·`Detail`)은 영문이 canonical이고 화면 렌더만 번역한다 — 단일 정의는 `skills/fg-next/HANDOFF.md` 하나이며 다음 단계가 실재하는 **15곳**(14 → 15: 신규 `fg-debug` 편입 — 루프 4 + fg-status·fg-next·fg-loop·fg-quick·fg-map·fg-doctor·fg-agenda·fg-adversarial-review·fg-agents·fg-security·fg-debug)이 참조만 하고 복붙하지 않는다. 나머지 **7곳**(fg-config·fg-statusline·fg-cleanup·fg-drop·fg-merge·fg-showme·fg-help)은 종전 산문 유지 — `skills/fg-help/SKILL.md`가 `HANDOFF.md`를 언급하는 것은 단일 정의 *선례*로서일 뿐 표를 쓰지 않는다.
- **그 두 개수는 이제 기계가 지킨다 — fg-doctor `B18`(신규, ADR `260907-140655`).** `HANDOFF.md`의 `**Applies (15)**`·`**Does NOT apply (7)**` 선언 숫자가 같은 절에서 백틱으로 **열거된** 고유 `fg-*` 스킬 수와 일치하는지, 그리고 `.forge/CONTEXT.md`의 핸드오프 용어 개수가 Applies 열거와 일치하는지를 warning으로 대조한다. 선언과 열거를 따로 고치면 걸리므로, 스킬을 표에 편입·제외할 때 **숫자·열거·글로서리 세 곳을 같은 편집에서** 손대야 한다.
- **B18은 개수를 넘어 *산문 계약의 정합*까지 본다 — 이 리포의 검사 중 처음이다.** 일곱 갈래이며 셋은 위의 개수 검사(`handoff applies count`·`handoff excluded count`·`CONTEXT handoff count`), 넷은 `skills/fg-debug/SKILL.md`가 자기 ADR과 어긋나지 않는지 확인한다 — 활성 `verified: failed`를 fg-run의 기존 fix-and-re-run으로 되돌린다고 진술하는지(`fg-debug active-failure route`), Phase 1 명령을 영속/일회성으로 분류하고 PLAN-FORMAT에 위임하며 **자동 eval 준수를 과대 진술하지 않는지**(`fg-debug persistent eval`), 모든 종료 경로에서 임시 산출물 정리를 요구하는지(`fg-debug cleanup`), 불확정 종료 경로를 정의하는지(`fg-debug inconclusive route`). 네 신호는 파일 전체가 아니라 각각을 소유한 H2 절(`Route by invocation state`·`Phase 1 artifacts`·`The boundary`) 안에서만 찾으므로, 서로 무관한 절에 흩어진 키워드가 빠진 계약을 대신 만족시키지 못한다. 전부 **warning**이고 B17과 같이 최상위 매니페스트 `name == forge`로 스코프를 좁힌다(사용자 프로젝트에 forge 내부 규칙을 요구하지 않기 위함). **선례로서 중요한 점**: 산문 계약이 두 파일에 걸쳐 어긋나는 것은 종전까지 사람 리뷰만 잡을 수 있었는데, "선언한 숫자 = 열거한 개수" 같은 **자기검증 형태로 계약을 쓰면 기계가 잡는다** — 새 계약을 쓸 때 이 형태를 노릴 것.
- **단일 정의·복붙 금지(shared discipline docs).** `skills/fg-run/FORGE-ROOT.md`(forge 루트 해석, ADR-0011)·`skills/fg-next/DRIVE.md`(무인 주행 규율, ADR-0028)·`skills/fg-next/HANDOFF.md`(핸드오프 표)·`skills/fg-config/ECO.md`(eco 규율)가 그 예이고, **신규로 `core/HOST.md`·`core/EXECUTION.md`·`core/INTERACTION.md`가 같은 가족에 합류했다**(호스트-중립 계약 — §7). 다른 스킬은 `${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}/skills/<소유 스킬>/<파일>` 또는 상대경로(`../fg-ask/ADR-FORMAT.md`)로 참조한다. 루트 `references/` 디렉터리는 폐지됐다(존재하지 않음 — 확인).
- **플러그인 루트 참조 형식은 하나가 아니라 둘이고, 순서가 서로 반대다(중요 정정 — 이전 지도가 틀렸다).** 이전 판은 `${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}` 하나로 통일됐다고 적었으나, `core/HOST.md` L34–43이 **두 메커니즘을 구분**하고 각자 반대 순서를 못 박는다("Do not "fix" one to match the other" — 명문 금지):
  - **텍스트 치환(스킬 본문)** — `${PLUGIN_ROOT:-${CLAUDE_PLUGIN_ROOT}}`(Codex 우선). 호스트가 **정확히 그 리터럴 토큰만** 치환하므로 여기서 순서를 뒤집으면 미치환 표현식이 에이전트에게 그대로 읽힌다. 실측: 소스 트리(`skills/`·`hooks/`·`core/`·`hosts/`)에 **23개 파일 61곳**.
  - **셸 확장(훅 command·셸 스니펫)** — `${CLAUDE_PLUGIN_ROOT:-${PLUGIN_ROOT}}`(**호스트 자신의 변수 우선**). shell-form 훅 command(`args` 없음)는 셸에 그대로 넘겨지고 `CLAUDE_PLUGIN_ROOT`가 훅 프로세스 *환경*에 있으므로 셸이 확장한다 → `PLUGIN_ROOT`(남이 export할 수 있는 흔한 이름)가 이기게 두면 이미 옳게 해석되는 경로를 무관한 도구가 가로챈다. 실측: `hooks/hooks.json` **2곳**(두 훅 command)뿐이고, `core/HOST.md`의 스니펫도 `FORGE_PLUGIN_ROOT="${CLAUDE_PLUGIN_ROOT:-${PLUGIN_ROOT:-}}"`로 **함께 뒤집혔다**(이전 지도가 적은 순서와 반대).
  - **어댑터 *선택*은 별개 질문이다** — 선택 순서는 여전히 `PLUGIN_ROOT`를 Codex 신호로 취급한다(§7). "경로를 해석하는 것"과 "호스트를 판정하는 것"을 같은 규칙으로 묶지 말 것.
  - 맨 `${CLAUDE_PLUGIN_ROOT}`는 **경로 참조로는 0건**이다(실측 2건은 `core/HOST.md`·`hooks/run-hook.test.sh`의 메커니즘 설명 산문·주석). 세는 범위는 **소스 트리로 고정**한다 — 리포 전체로 세면 `.forge/codebase/` 문서 자신과 `docs/.vitepress/dist/` 빌드 산출물이 잡혀 **자기참조적으로 부풀고**(지도를 다시 쓸 때마다 값이 바뀐다) 실제로 그렇게 틀린 수치가 한 번 적혔다. 스킬 저작 에이전트 카드 `.claude/agents/skill-author.md`도 갱신됐다.
- **frontmatter `description`은 한 줄로 유지한다(신규 — 회귀에서 배운 규약).** 5개 스킬의 `description`이 내용 변경 0으로 YAML folded scalar(`>-`)로 바뀐 적이 있는데, fg-doctor **B16**의 리더가 `sed -n 's/^description:[[:space:]]*//p' | head -1`로 **줄 단위**라 값이 `>-`(2자)로 읽혀 600자 상한 린트가 **조용히 눈이 멀었다**. 전부 한 줄로 복원됐다(실측: `skills/*/SKILL.md`에 `^description: >-` **0건**). B16이 줄 단위 리더인 한 이 규약은 계약이다.
- **형식 문서는 소유 스킬 디렉터리에 한 벌만**: `skills/fg-ask/{CONTEXT,ADR}-FORMAT.md`, `skills/fg-run/PLAN-FORMAT.md`, `skills/fg-learn/RETRO-FORMAT.md`.
- **흐름도는 Mermaid 금지, 영문 텍스트 흐름도**(`A → B → C`) — 스킬 문서 한정 규약. 사용자 프로젝트 산출 문서에는 비적용.
- **frontmatter `name`이 스킬 식별자**(디렉터리명 아님). 각 `description`에 영문+한글 트리거를 모두 등록(예: `skills/fg-ask/SKILL.md` frontmatter — `"start a new task"`, `'새 작업 시작'` 병기; ADR `260716-22a`). 스킬 본문에 한쪽 언어 트리거를 하드코딩하지 않고, verbatim 유지 대상은 경로·`.forge/` 필드·`/명령`뿐이다.
- **핸드오프는 진술형** — "진행할까요?"로 묻지 않는다. 체이닝은 fg-next 전담(ADR-0015, ADR `260805-231104`).
- **verbatim 영역**: `skills/fg-ask/SKILL.md` 본문은 grill-with-docs 원문 영문 verbatim이고, forge 연결은 맨 아래 "Forge integration (minimal)" 섹션에만 둔다(`CLAUDE.md` "알려진 불일치" 절).
- **vendoring 규약 — 이제 사례가 둘이라 패턴으로 굳었다.** 외부 방법론은 **byte-for-byte 유지**하고 forge 글루만 `SKILL.md`에 둔다. 공통 형태 네 가지: ① 업스트림 파일 편집 금지(원형 유지 → 장차 업스트림 diff가 싸다), ② **진입 파일만 개명**(forge 스킬 자동 탐색 충돌·중첩 오탐 회피), ③ `LICENSE` 원문 동봉 + `SKILL.md` 도입부에 출처·라이선스 명시, ④ `SKILL.md`가 방법론 파일을 **파일 참조로만** 쓰고 재진술하지 않음(`../fg-config/ECO.md`·`../fg-showme/VISUAL.md`와 같은 관례).
  - `skills/fg-security/` — [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill), MIT. `AUDIT.md`(진입, 개명됨)+공격유형 플레이북 9종+`report-schema.json`·`validate-findings.cjs`·`LICENSE`(총 13파일).
  - `skills/fg-debug/`(신규) — [mattpocock/skills](https://github.com/mattpocock/skills) `diagnosing-bugs`, MIT(`LICENSE` 21줄, Copyright Matt Pocock). 편집 금지 3파일은 `DIAGNOSE.md`(138줄, 진입 — 업스트림 `SKILL.md`에서 개명)·`scripts/hitl-loop.template.sh`(44줄)·`LICENSE`이고, forge 글루는 `SKILL.md`(112줄) 하나다. **`## Credits` 절을 명시적 헤딩으로 두는 것은 fg-debug가 처음**이다(fg-security는 도입부 문단으로만 귀속) — 새 vendoring은 이 형태를 따르는 게 낫다.
  - **vendoring된 스크립트는 `scripts/` 트윈 규약 밖이다** — `skills/fg-debug/scripts/hitl-loop.template.sh`는 `.js` 짝이 없고 exec 비트가 서 있는데, fg-doctor B15가 훑는 범위는 최상위 `scripts/`뿐이라 걸리지 않는다(의도된 경계). 단 루트 `.gitattributes`의 `*.sh text eol=lf`는 경로 무관하게 적용된다.

## 2. 스크립트 규약 (ADR-0022, `.forge/adr/0022-*.md`)

- **sh/js 트윈**: 운영 스크립트마다 `.sh`(bash, 1차) + `.js`(node, 폴백) 쌍 — `scripts/`에 **11쌍** 존재(forge-doctor·forge-done·forge-hook-session-start·forge-hook-stop·forge-loop-spend·forge-merge·forge-status·forge-statusline·forge-statusline-full·**release-check**·resolve-forge-root; `forge-statusline-wrapper.sh`만 bash 전용 예외로, fg-doctor B15 검사도 `*-wrapper.sh`를 제외). B15는 `scripts/*.sh`·`scripts/*.js` 전체를 훑으므로 `forge-` 접두가 없는 `release-check`도 트윈 검사 대상이다.
- **"트윈"은 두 개의 실제 구현을 뜻한다 — shim은 트윈이 아니다(규약, 실사례).** `scripts/release-check.sh`는 처음 `exec node …`로 js를 호출하는 shim이었는데, 그러면 ADR-0022의 존재 이유(**node 없는 bash-only 환경**)가 정확히 무력화된다 — 파일은 두 개지만 런타임 의존은 하나다. 현재는 **83줄**(37 → 83)의 실제 bash 구현이고(`grep -oE '"version"…' | sed`로 문서 순서대로 버전을 뽑는 — fg-doctor B8과 **같은 리더**), `scripts/release-check.parity.test.sh`가 sh↔js 동치를 강제한다(TESTING.md §2·§3).
- **bash 트윈은 JSON 파서 없이 계약을 검증한다(신규 idiom).** `release-check.sh`가 `hosts/*/capabilities.json`을 검사할 때 node를 부르지 않는다 — `tr -d ' \t\n\r`로 압축한 뒤 정규식 `^\{("[a-z_]+":(true|false),)*"[a-z_]+":(true|false)\}$` 하나로 "**불리언 값만 담긴 평면 객체**"라는 좁은 계약을 확인한다. 임의 JSON을 파싱하는 게 아니라 **계약을 그 정규식이 표현할 수 있을 만큼 좁게 정의한 것**이 요점이고, 그래서 bash 트윈이 node-free로 남으면서 `.js` 트윈과 정확히 같은 판정을 낸다(스크립트 주석에 근거 명시). 새 트윈에서 JSON을 읽어야 하면 이 순서로 생각할 것 — 파서를 들이지 말고 계약을 좁힐 수 있는지 먼저 본다.
- **`.js` 트윈은 CommonJS**(`require`) — 루트 `package.json`의 `"type"` 금지가 여기서 나온다(§0). 예외적으로 vendoring된 `skills/fg-security/validate-findings.cjs`는 확장자 `.cjs`로 모듈 종류를 자기가 못 박는다(zero-dependency, exit 0/1).
- **포터블 규칙**: shebang은 `#!/usr/bin/env bash`(`/bin/bash` 금지), 호출은 `bash script.sh`(`./script.sh` 금지 — NTFS exec 비트 없음), `.gitattributes`가 `*.sh text eol=lf`로 LF 강제(루트 `.gitattributes` 확인).
- **판단은 스크립트로 옮기지 않는다** — 결정론적 survey/상태 전이만 스크립트화, LLM 판단(그릴링·회고 분류·divergence 평가)은 산문에 남김(ADR-0020/0031 분할).
- **훅 디스패치**: `hooks/run-hook.cmd`는 bash→node 순 polyglot 래퍼, 런타임 없으면 exit 0 침묵(superpowers 패턴 MIT 차용). `hooks/hooks.json`에 훅이 **둘**이다 — `SessionStart`(매처 `startup|resume|clear|compact`, 본체 `scripts/forge-hook-session-start.sh`/`.js`)와 `Stop`(매처 없음, 본체 `scripts/forge-hook-stop.sh`/`.js`). 둘 다 `"shell": "bash"` · `"async": false`이고 command는 **`"${CLAUDE_PLUGIN_ROOT:-${PLUGIN_ROOT}}/hooks/run-hook.cmd" <이름>`** — §1의 **셸 확장** 형식(호스트 자신의 변수 우선)이며 스킬 본문 형식과 **순서가 반대**다. `hooks/run-hook.test.sh`는 더 이상 이 문자열을 grep으로 단언하지 않는다 — command를 `JSON.parse`로 뽑아 **실제로 `/bin/sh -c`로 실행**해 래퍼로 확장되는지, 그리고 낚시용 `PLUGIN_ROOT=<decoy>`가 있어도 가로채이지 않는지를 확인한다(케이스 `hooks.json-command-resolves`·`hooks.json-command-decoy-immune`). 문자열 존재 단언은 "작성자가 자기 문자열을 아직 안 지웠다"만 증명하고 **틀렸을 때는 절대 실패하지 않는다**(PLAN-FORMAT 가드 (e)와 같은 실패형). 가로채기는 훅 **둘 다**를 죽이므로 — SessionStart의 잔여 통지와 무인 주행이 의존하는 Stop 훅 — 이 두 케이스가 계약이다.
- **래퍼는 exec 비트가 서 있어야 한다** — Claude Code는 `bash <wrapper>`가 아니라 command 문자열을 `/bin/sh`에 넘겨 **파일을 실행**하므로, exec 비트가 없으면 훅이 실패한다(`hooks/run-hook.test.sh`가 이 버그 때문에 존재한다는 헤더 주석). 아래 `scripts/*.sh`의 "exec 비트 없음·`bash script.sh`로 호출" 규약과 **상충하는 의도된 예외**이니 혼동하지 말 것.
- **Stop 훅의 안전 규약(신규)**: 모든 실패·모호 경로는 **정지 허용(exit 0, 침묵)**이고, 정지를 막는 `exit 2`는 marker 존재 + 양쪽 상한(30분·50회) 이내 + 세션 일치인 좁은 한 경우뿐이다. 하네스 쪽 루프 보호가 없으므로 이 상한이 유일한 폭주 가드다(`scripts/forge-hook-stop.test.sh` 헤더 주석).

## 4. 이중 언어 동기화

- `README.md`(영문) ↔ `README.ko.md`(한글)는 번역 쌍 — 한쪽 갱신 시 반드시 다른 쪽도(fg-doctor B13이 스킬 행 패리티를 warning으로 검사).
- **`docs/<name>.md`(한글, root locale) ↔ `docs/en/<name>.md`(영문)는 9쌍의 번역 쌍**(8 → 9: 신규 **config-modes**(fg-config의 여섯 키 — `simple`·`eco`·`tdd` 등) 추가. 전체: agenda·codex·**config-modes**·forge-vs-loop-engineering·git-workflow·index·skills·state-contract·team-workflow — 실측: 쌍 누락 0건). README 1쌍까지 합쳐 **10쌍**이므로 **번역문은 절 구조를 1:1로 유지**한다(`##` 헤딩 개수·순서, 표의 행·열 수 일치 → diff로 동기 확인 가능). 쌍 누락 확인은 `for f in docs/*.md; do [ -f "docs/en/$(basename "$f")" ] || echo "missing: ..."; done`. 영문판 링크는 영문판끼리 닫히되 예외 둘 — `README.ko.md` 절대 URL은 `README.md`로, `./examples/…`는 `../examples/…`로.
- **`docs/codex.md` 쌍만은 이제 기계가 지킨다(신규).** `release:check`가 두 파일 **모두**에 `core/HOST.md`의 capability 8키가 백틱으로 **이름 지어져** 있는지 error로 확인한다 — 즉 이 한 쌍은 "쌍이 존재하는가"를 넘어 "내용이 canonical 어휘를 덮는가"까지 검사받는 유일한 문서 쌍이다. 검사하는 것은 **키 이름의 등장**뿐이고 지원 등급 문구는 사람 리뷰로 남는다(스크립트 주석이 "does not claim more than it checks"로 스스로 범위를 한정한다 — 게이트가 자기 사정거리를 과대 진술하지 않는 좋은 본보기).
- `docs/index.html`은 한 파일에 `data-l="ko"`/`data-l="en"` span 병기(ADR-0027) — 한쪽 span 수정 시 짝 span도 함께.
- 버전은 **4곳 동기**: `.claude-plugin/plugin.json` `version`, `.claude-plugin/marketplace.json` `metadata.version`·`plugins[0].version`, `.codex-plugin/plugin.json` `version`. fg-doctor **B8**이 4-way로 error 검사하고, 배포 절차에 `npm run release:check`가 편입됐으며 이제 **CI(`release-check.yml`)에서도 돌아간다**(§5). 실측 현재값 **`0.8.6`** 4곳 일치.
- `CLAUDE.md` 스킬 목록 완전성은 fg-doctor B12(warning).

## 5. 에러 처리·안전 패턴 (스킬 계층)

- **게이트-우선-비파괴**: fg-done 봉인 스크립트(`scripts/forge-done.sh`/`.js`)는 검증 게이트(ADR-0009 — `verified:` 봉인가능 값) → 회고 게이트 순으로 확인하고 실패 시 아무것도 옮기지 않으며 exit code로 스킬이 라우팅(ADR-0030).
- **읽기 전용 계열**: fg-status·fg-doctor는 아무것도 쓰지 않는다. fg-doctor exit 0/1/2(clean/warning/error)로 CI 게이트 겸용.
- **불가역 액션 앞 확인 게이트**: fg-drop 하드 삭제 전 경고, fg-loop safety 벽(비가역 액션 클래스 정지).
- 매니페스트 편집 후 JSON 유효성 확인은 `CLAUDE.md`의 node 한 줄이 canonical(이제 `.codex-plugin/plugin.json`까지 **3개 매니페스트**를 파싱한다).
- **릴리스 게이트**: `npm run release:check`(= `scripts/release-check.{sh,js}`)가 배포 전 위반을 error로 잡는다. 네 가지에서 **일곱 갈래로 확장**됐다 — ① 매니페스트 버전 4곳 동기, ② Codex 매니페스트의 `skills`가 `"./skills/"`인지(공유 스킬 트리 이탈 방지), ③ `hooks/hooks.json` 존재, ④ `hosts/{claude,codex}/{interaction.md,execution.md,capabilities.json}` 6파일 완비, ⑤ **capability 어휘를 `core/HOST.md` 표에서 파싱해** 두 `capabilities.json`의 키 집합과 대조(missing·unknown 각각 별도 위반), ⑥ 두 파일이 불리언 평면 객체 형태인지, ⑦ `docs/codex.md`·`docs/en/codex.md`가 8키를 모두 이름 짓는지(§4). 계약은 **exit 0 = ok / 1 = 위반 1건 이상**이고 위반은 stderr에 한 줄씩·**여러 위반은 고정 순서**로 나온다(파일 부재 매니페스트만 즉시 exit 1로 단축). fg-doctor와 달리 warning 등급이 없다.
- **게이트는 canonical을 *파싱*하고 절대 하드코딩하지 않는다(신규 규약).** ⑤의 어휘는 `grep -oE '^\| `[a-z_]+`' core/HOST.md | sed …`로 **표에서 도출**한다 — 스크립트 주석이 이유를 스스로 적는다: "That table is the single definition; a second copy in this script would be the very drift this check exists to prevent." 단일 정의를 지키는 검사가 그 정의의 사본을 들고 있으면 자기모순이므로, 도출이 실패하면(표가 사라짐) **그 자체가 위반**이다(`cannot derive the capability vocabulary from core/HOST.md`). fg-doctor B17이 `scripts/explaining-forge.rule.txt`를 verbatim 대조하는 것과 같은 계열 — **검사기는 규칙을 재진술하지 않고 규칙 파일을 읽는다**.
- **CI 게이트는 지킬 파일 경로에 발동해야 한다(신규, `release-check.yml` 헤더가 명문화).** 이 게이트를 `docs.yml`에 스텝으로 넣지 않은 이유가 워크플로 주석에 박혀 있다 — `docs.yml`은 `docs/**`·`package.json`에만 발동하므로 정작 지켜야 할 `.codex-plugin/`·`hosts/`·`core/` 변경에는 **발동하지 않는 fail-open 게이트**가 된다("A gate that looks wired but cannot fire is worse than no gate"). 그래서 `release-check.yml`은 `.claude-plugin/**`·`.codex-plugin/**`·`core/**`·`hosts/**`·`hooks/**`·`scripts/release-check.*`·자기 자신·`docs/codex.md`·`docs/en/codex.md`에 발동하고, push와 **pull_request 양쪽**에 걸린다.
- **STATUS가 기록하는 경로는 전부 repo-relative여야 한다(신규 계약, `scripts/forge-done.test.sh`가 단언).** forge 루트는 git 리포 안에서 절대경로로 해석되고, 비-기본 브랜치의 루트는 통째로 git 추적되므로(ADR-0011) 절대경로를 적으면 **머신 경로가 커밋된다**. `retro:`·`reviewed:` 둘 다 대상이다(케이스 `n3-retro-path-relative`·`n6-reviewed-path-relative`).

## 7. 호스트-중립 규약 (신규, ADR `260903-080713`)

forge가 Claude Code 전용에서 **Claude Code + Codex** 두 호스트로 넓어지면서 생긴 규약 층이다(은퇴한 ADR-0025 "Claude Code only, defer Codex port"의 반대 결정 — `.forge/adr/retired/0025-*.md`). 핵심 원칙: **워크플로 의미와 `.forge/` 상태 의미는 공유 `skills/`·`scripts/`가 소유하고, 호스트 어댑터는 "어떻게 묻고·위임하고·에이전트를 로드하고·주행을 잇고·상태를 표시하는지"만 서술한다.** 스킬을 Codex용으로 두 벌 만들지 않는다(`core/HOST.md` 명문 금지 — "must not fork the state model or maintain a second Codex-specific copy of a skill").

- **어댑터 선택 순서**(`core/HOST.md`): ① 명시적 호스트 메타데이터 → ② `PLUGIN_ROOT` = Codex → ③ Codex 메타데이터 없는 `CLAUDE_PLUGIN_ROOT` = Claude Code → ④ **식별 불가 시 순차 폴백**(평문 질문·역할 위임 없음·호스트 UI 미변경). 두 환경변수 모두 *증거일 뿐 증명이 아님*을 계약이 스스로 명시한다(Codex도 호환성으로 `CLAUDE_PLUGIN_ROOT`를 줄 수 있고, `PLUGIN_ROOT`는 남이 export할 수 있는 흔한 이름). **모호할 때 추측하지 않고 폴백을 택하는 것**이 규약이고, 폴백 경로는 전부 정의되어 있어 안전하다.
- **capability 어휘는 단일 정의**: `core/HOST.md`의 표 8개 키(`structured_choice`·`spawn_parallel`·`spawn_role`·`plugin_root`·`session_start`·`prevent_stop`·`project_agents`·`status_display`)가 **유일한 어휘**이고 `hosts/<host>/capabilities.json`은 정확히 그 8개 키만 담는다(실측: 양쪽 파일 8/8, 여분 키 0) → 스킬이 capability 이름을 적어 기계적으로 조회할 수 있다. **이 계약은 더 이상 관례가 아니라 게이트다** — `release:check`가 표를 파싱해 두 파일과 대조하고 `docs/codex.md` 쌍까지 확인하며(§5), `release-check.yml`이 `core/**`·`hosts/**` 변경마다 CI에서 돌린다.
- **`core/HOST.md`가 57 → 73줄로 자랐고, 늘어난 대부분이 "왜 이 순서인가"의 근거다.** 플러그인 루트 해석 스니펫이 `${CLAUDE_PLUGIN_ROOT:-${PLUGIN_ROOT:-}}`로 **뒤집히면서** 두 메커니즘(셸 확장 vs 텍스트 치환)의 구분과 "한쪽을 다른 쪽에 맞춰 고치지 말라"는 명문 금지가 함께 들어왔다(§1의 정정 항목이 이 절의 상세다). **경로 해석 순서와 어댑터 선택 순서가 서로 다르다는 점**이 핵심이고, 계약이 그 둘을 "separate question"으로 명시 분리한다.
- **`true`는 관측, `false`는 기본값**: capability는 **그 호스트가 제공한다고 *관측된* 때만 `true`**다. 미확인은 `false`로 두는데, 모든 capability에 정의된 폴백(순차 실행·번호 텍스트 목록·명시적 정지)이 있고 **도는 폴백이 없는 도구 호출보다 항상 싸기** 때문이다. 실측 현재값 — `hosts/claude/capabilities.json`은 8개 전부 `true`, `hosts/codex/capabilities.json`은 `spawn_parallel`·`plugin_root`·`session_start` 셋만 `true`. **`false`→`true` 뒤집기는 관측이지 가정이 아니며, 같은 변경에서 `docs/codex.md`의 "현재 지원 범위" 표를 함께 갱신해야 한다**(같은 주장의 두 표현 — 그 표는 지원/제한적/미확인/미지원 4등급으로 서술하며 `structured_choice`가 "미확인 → 번호 텍스트 목록 fallback"에 해당).
- **기둥 1의 근거가 호스트-중립으로 복원됐다**: "그릴링은 실행 워크플로우 안에 넣지 않는다"에 이유가 다시 붙었다 — **위임 실행은 실행 중 사용자 입력을 못 받는다**. Claude Code Dynamic Workflow와 Codex collaboration/subagent를 나란히 들어 호스트가 늘어도 근거가 사라지지 않음을 명시하며, `CLAUDE.md` L114·`README.md` L194·`README.ko.md` L193·`docs/index.md` L53·`docs/en/index.md` L53 **다섯 곳이 같은 문장 구조**로 동기화되어 있다(이중언어 쌍 규약이 여기에도 적용된다).
- **위임 실행 계약**(`core/EXECUTION.md`, 9줄): 공유 스킬이 선택·승격·의존성 분류·결과 수집·UAT·`.forge/run.md`를 소유하고 어댑터는 **위임만** 소유한다. 의존 슬라이스는 직렬, 독립·한정 슬라이스는 병렬 가능, 통합과 상태 쓰기는 primary agent 책임, **위임 불가 시 의미를 바꾸지 않고 직렬 실행**.
- **대화 계약**(`core/INTERACTION.md`, 6줄): 한 번에 한 질문, 호스트의 structured-choice 도구가 있고 선택지 수가 맞으면 그것을, 아니면 번호 목록 + 안정 식별자 하나. **확인 게이트와 기본값은 호스트 간 동일**하다.
