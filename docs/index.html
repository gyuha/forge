작업 하나가 도는
네 단계의 사이클.One task through
a four-stage cycle.

한 스킬이 끝나면 다음으로 가는 길을 안내하고, 동의하면 그 자리에서 다음 스킬을 실행합니다. fg-done이 작업을 봉인하면 같은 작업은 두 번 돌지 않습니다.When one skill finishes, it states the way to the next; run fg-next to take that step. Once fg-done seals a task, the same task never runs twice.

Skill catalog

18개의 스킬.
하나의 흐름.Eighteen skills.
One flow.

루프를 이루는 4개The four that form the loop
fg-ask ① Ask·plan
대화형 계획 · grillingConversational planning · grilling

루프의 진입점. 도메인·용어·결정을 상대로 계획을 갈아 backlog와 CONTEXT/ADR로 남깁니다. "forge로 시작하자", "새 작업"으로 트리거.The loop's entry point. Grills the plan against domain, terms, and decisions, leaving it in the backlog and CONTEXT/ADR. Triggers on "start with forge", "new task".

fg-run ② Execute
Dynamic Workflow 실행Run as Dynamic Workflow

계획을 워크플로우로 실행. 미실행 계획이 하나면 즉시 실행, 여러 개면 선택 메뉴(마지막 옵션 "Run all")를 띄웁니다.Runs the plan as a workflow. One unexecuted plan runs immediately; several show a selection menu (last option "Run all").

fg-learn ③ Retro
회고 · 문서 승격Retro · promote to docs

run.md·plan·executed를 읽어 배움을 CONTEXT/ADR/retro로 승격하고 다음 탐구를 제안합니다.Reads run.md/plan/executed, promotes learnings to CONTEXT/ADR/retro, and suggests the next inquiry.

fg-done ④ Done
봉인 · 재실행 가드Seal · re-run guard

회고를 확인하고 STATUS를 done으로 닫아 아카이브. 활성 상태를 비우고 루프를 닫습니다. all 모드는 이미 실행된 작업을 일괄 봉인합니다.Confirms the retro, closes STATUS as done, and archives. Empties active state and closes the loop. all mode batch-seals already-executed tasks.

루프 밖의 유틸리티 14개14 utilities outside the loop
fg-map

코드베이스를 병렬 서브에이전트로 매핑해 .forge/codebase/에 저장. grilling이 코드를 다시 탐색하지 않게 합니다.Maps the codebase with parallel subagents into .forge/codebase/, so grilling reads a map instead of re-exploring.

fg-quick

사소한 작업 전용 경량 레인. 가볍게 grill 후 형식 산출물 없이 바로 실행. 커지면 fg-ask로 넘깁니다.Lightweight lane for trivial tasks. Grills lightly, then runs directly with no formal artifacts. Bails to fg-ask if it grows.

fg-status

읽기 전용 리포터. .forge/를 훑어 모든 작업의 현재 위치와 다음 한 걸음을 출력. 아무것도 쓰지 않습니다.Read-only reporter. Surveys .forge/ and prints where every task stands plus the single next step. Writes nothing.

fg-next

fg-status의 상태 머신으로 다음 한 걸음을 도출해 실제로 실행. all 모드는 백로그가 빌 때까지 몰아붙입니다.Derives the next step via fg-status's state machine and runs it. all mode drives until the backlog is empty.

fg-loop

goal 주도 한정 재계획 루프. 기계 검증 가능한 정지 조건이 통과할 때까지 run → UAT → 봉인을 자동 주행하고, 실패 체크는 상한 내에서 fix-forward로 재계획합니다.Goal-driven loop with bounded replan. Drives run → UAT → seal until machine-verifiable checks pass, auto-generating fix-forward work for failing checks within a cap.

fg-tdd

.forge/config.json에 TDD 모드를 on/off로 저장. 켜면 fg-ask는 test-first를 묻고 fg-run은 테스트 우선으로 실행.Stores TDD mode on/off in .forge/config.json. When on, fg-ask asks test-first and fg-run runs test-first.

fg-eco

eco 모드 토글. 켜면 위임 서브에이전트를 sonnet으로 캡하고, 임베드된 Eco laziness-first 규율(코드 단순성 + 출력 압축)을 fg-run·fg-ask에 주입합니다.Toggles eco mode. When on, caps delegated subagents at sonnet and injects the embedded Eco laziness-first discipline (code simplicity + terse output) into fg-run and fg-ask.

fg-merge

git merge 후 브랜치의 .forge/branch/<b>/를 .forge/로 통합. ADR 재번호·CONTEXT 병합·done 이력 접기. git은 실행하지 않음.After a git merge, folds a branch's .forge/branch/<b>/ into .forge/ — renumbers ADRs, merges CONTEXT, folds done history. Never runs git.

fg-cleanup

낡거나 대체된 ADR을 활성 집합에서 은퇴시켜 retired/로 이동. 번호는 그대로, 삭제는 없음. 승인은 사람이.Retires stale/superseded ADRs from the active set into retired/. Numbers stay, nothing is deleted. A human approves.

fg-adversarial-review

fg-run과 fg-learn 사이 선택적 적대적 검토. 결과가 틀렸다고 가정하고 6개 렌즈로 병렬 검증해, 수정이 필요하면 fix-forward 계획을 만듭니다.Optional hostile review between fg-run and fg-learn. Assumes the result is wrong and verifies across six lenses in parallel; fix-needed findings become a fix-forward plan.

fg-doctor

.forge/ 상태 계약과 문서·매니페스트 정합을 훑는 읽기 전용 무결성 검사. 고아 파일·깨진 STATUS·버전 드리프트를 심각도와 함께 보고합니다.Read-only integrity check of the .forge/ state contract and docs/manifest sync. Reports orphaned files, broken STATUS, and version drift with severity.

fg-drop

봉인되지 않은 미완 작업(백로그·활성·executed·멈춘 goal 루프)을 위험도와 함께 보여주고, 하드 삭제 또는 dropped/ 보관 중 선택하게 합니다.Shows unsealed, incomplete work (backlog/active/executed/halted goal loop) with a risk level, then lets you hard-delete or archive to dropped/.

fg-agents

대화형 그릴링으로 프로젝트에 반복되는 역할을 찾아 .claude/agents/<role>.md 카드를 생성합니다. 세션 재시작 후 fg-run이 매칭 role을 dispatch합니다.Finds recurring project roles by conversational grilling and generates .claude/agents/<role>.md cards. After a session restart, fg-run dispatches the matching role.

fg-statusline

forge 루프 진행 상태를 보여주는 statusline 조각을 설치. 기존 statusLine이 있으면 대체하지 않고 그 아래 별도 줄로 wrapping합니다.Installs a statusline fragment showing forge's loop progress. If a statusLine already exists, it wraps it as an extra line below instead of replacing it.

The two pillars

forge를 떠받치는
두 개의 기둥.The two pillars
forge stands on.

01
계획(grilling)은 대화다.Planning (grilling) is a conversation.

Dynamic Workflow는 실행 중 사용자 입력을 받을 수 없습니다. 그래서 질문-대-질문으로 계획을 갈아내는 grilling은 워크플로우 바깥, 대화 안에서만 일어납니다.A Dynamic Workflow cannot take user input mid-run, so question-by-question grilling happens only outside the workflow, in conversation.

02
문서는 부산물이 아니라 연료다.Docs are fuel, not a by-product.

계획에서 벼려진 용어는 실행의 기준이 되고, 회고의 배움은 다음 계획의 출발점이 됩니다. CONTEXT.md · ADR · retro log에 쌓입니다.Terms forged in planning become the standard for execution, and retro learnings become the starting point of the next plan. They accumulate in CONTEXT.md · ADRs · the retro log.

간단한 사용법How it works

말 한마디로
루프를 돌립니다.Drive the loop
with a single phrase.

01
루프 시작Start the loop

fg-ask를 부르거나 "forge로 시작하자", "새 작업"이라고 말하면 대화형 grilling이 계획을 갈아냅니다.Call fg-ask or say "start with forge" / "new task" — conversational grilling sharpens the plan.

02
실행Execute

fg-run이 계획을 Dynamic Workflow로 실행. 끝나면 계획의 목표에 대해 UAT를 돌려 STATUS.md에 검증 결과를 기록합니다.fg-run runs the plan as a Dynamic Workflow. When done, it runs a UAT against the plan's goal and records the result in STATUS.md.

03
회고Retro

fg-learn이 배움을 문서로 승격. 사소하고 편차가 작으면 회고를 건너뛸 수도 있습니다.fg-learn promotes learnings to docs. For a trivial, low-divergence task the retro may be skipped.

04
봉인Seal

"작업 완료"라고 하면 fg-done이 검증·회고를 확인하고 done/으로 아카이브 — 같은 작업은 다시 돌지 않습니다.Say "seal" and fg-done confirms verification and retro, then archives to done/ — the same task never runs again.

05
길 잃었을 때When you lose track

"forge status"로 지금 위치를, "forge next"로 다음 한 걸음을 바로 실행. "이거 빨리 해줘"엔 fg-quick."forge status" shows where you are; "forge next" runs the next step. For a quick one-off, fg-quick.

Shared state

상태는 파일로 흐른다.State flows through files.

모든 상태가 파일로 전달되어, 각 단계를 따로 불러도 흐름이 이어집니다. 단일 .forge/ 디렉터리가 휘발성 루프 상태와 git이 추적하는 영구 문서를 모두 담습니다.State is passed through files, so the flow continues even when stages are invoked separately. A single .forge/ directory holds both the volatile loop state and the git-tracked permanent docs.

repo/.forge/
.forge/
# 영구 문서 (git 추적)
├── CONTEXT.md        용어집
├── adr/0001-*.md      아키텍처 결정
├── retro/*.md         회고 로그
├── codebase/*.md      fg-map 맵
# 휘발성 상태 (gitignore)
├── backlog/<slug>.md  대기 중인 계획
├── plan.md           현재 사이클
├── run.md            계획 vs 실제
├── STATUS.md         실행/검증 상태
├── executed/         회고 대기
└── done/             봉인 아카이브.forge/
# permanent docs (git-tracked)
├── CONTEXT.md        glossary
├── adr/0001-*.md      architecture decisions
├── retro/*.md         retro log
├── codebase/*.md      fg-map maps
# volatile state (gitignored)
├── backlog/<slug>.md  waiting plans
├── plan.md           current cycle
├── run.md            plan vs actual
├── STATUS.md         execute/verify status
├── executed/         awaiting retro
└── done/             sealed archive
활성 슬롯은 언제나 하나Always exactly one active slot

하나의 plan.md = 하나의 run.md = 하나의 봉인. 백로그가 여러 개면 fg-run이 선택 메뉴를 띄웁니다.One plan.md = one run.md = one seal. With several in the backlog, fg-run shows a selection menu.

봉인 전 검증 게이트Verification gate before sealing

run → verify → learn → done. verified:가 통과 상태여야만 fg-done이 봉인합니다.run → verify → learn → done. fg-done seals only when verified: is a passing value.
