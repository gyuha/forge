The Loop

작업 하나가 도는
네 단계의 사이클.

한 스킬이 끝나면 다음으로 가는 길을 안내하고, 동의하면 그 자리에서 다음 스킬을 실행합니다. fg-done이 작업을 봉인하면 같은 작업은 두 번 돌지 않습니다.

fg-ask ①
Ask · plan
grill-with-docs로 도메인·용어·결정을 상대로 계획을 갈아냅니다.
fg-run ②
Execute
계획을 Dynamic Workflow로 실행합니다.
fg-learn ③
Retro
배움을 문서로 승격하고 다음 탐구를 드러냅니다.
fg-done ④
Done
사이클을 정리하고 작업을 봉인 — 재실행을 막습니다.

새 작업이면 fg-ask로 다시 시작 · 다른 결과가 나오면 재-grilling

Skill catalog

18개의 스킬.
하나의 흐름.

루프를 이루는 4개
fg-ask ① Ask·plan
대화형 계획 · grilling

루프의 진입점. 도메인·용어·결정을 상대로 계획을 갈아 backlog와 CONTEXT/ADR로 남깁니다. "forge로 시작하자", "새 작업"으로 트리거.

fg-run ② Execute
Dynamic Workflow 실행

계획을 워크플로우로 실행. 미실행 계획이 하나면 즉시 실행, 여러 개면 선택 메뉴(마지막 옵션 "Run all")를 띄웁니다.

fg-learn ③ Retro
회고 · 문서 승격

run.md·plan·executed를 읽어 배움을 CONTEXT/ADR/retro로 승격하고 다음 탐구를 제안합니다.

fg-done ④ Done
봉인 · 재실행 가드

회고를 확인하고 STATUS를 done으로 닫아 아카이브. 활성 상태를 비우고 루프를 닫습니다. all 모드는 이미 실행된 작업을 일괄 봉인합니다.

루프 밖의 유틸리티 14개
fg-map

코드베이스를 병렬 서브에이전트로 매핑해 .forge/codebase/에 저장. grilling이 코드를 다시 탐색하지 않게 합니다.

fg-quick

사소한 작업 전용 경량 레인. 가볍게 grill 후 형식 산출물 없이 바로 실행. 커지면 fg-ask로 넘깁니다.

fg-status

읽기 전용 리포터. .forge/를 훑어 모든 작업의 현재 위치와 다음 한 걸음을 출력. 아무것도 쓰지 않습니다.

fg-next

fg-status의 상태 머신으로 다음 한 걸음을 도출해 실제로 실행. all 모드는 백로그가 빌 때까지 몰아붙입니다.

fg-loop

goal 주도 한정 재계획 루프. 기계 검증 가능한 정지 조건이 통과할 때까지 run → UAT → 봉인을 자동 주행하고, 실패 체크는 상한 내에서 fix-forward로 재계획합니다.

fg-tdd

.forge/config.json에 TDD 모드를 on/off로 저장. 켜면 fg-ask는 test-first를 묻고 fg-run은 테스트 우선으로 실행.

fg-eco

eco 모드 토글. 켜면 위임 서브에이전트를 sonnet으로 캡하고, 임베드된 Eco laziness-first 규율(코드 단순성 + 출력 압축)을 fg-run·fg-ask에 주입합니다.

fg-merge

git merge 후 브랜치의 .forge/branch/<b>/를 .forge/로 통합. ADR 재번호·CONTEXT 병합·done 이력 접기. git은 실행하지 않음.

fg-cleanup

낡거나 대체된 ADR을 활성 집합에서 은퇴시켜 retired/로 이동. 번호는 그대로, 삭제는 없음. 승인은 사람이.

fg-adversarial-review

fg-run과 fg-learn 사이 선택적 적대적 검토. 결과가 틀렸다고 가정하고 6개 렌즈로 병렬 검증해, 수정이 필요하면 fix-forward 계획을 만듭니다.

fg-doctor

.forge/ 상태 계약과 문서·매니페스트 정합을 훑는 읽기 전용 무결성 검사. 고아 파일·깨진 STATUS·버전 드리프트를 심각도와 함께 보고합니다.

fg-drop

봉인되지 않은 미완 작업(백로그·활성·executed·멈춘 goal 루프)을 위험도와 함께 보여주고, 하드 삭제 또는 dropped/ 보관 중 선택하게 합니다.

fg-agents

대화형 그릴링으로 프로젝트에 반복되는 역할을 찾아 .claude/agents/<role>.md 카드를 생성합니다. 세션 재시작 후 fg-run이 매칭 role을 dispatch합니다.

fg-statusline

forge 루프 진행 상태를 보여주는 statusline 조각을 설치. 기존 statusLine이 있으면 대체하지 않고 그 아래 별도 줄로 wrapping합니다.

The two pillars

forge를 떠받치는
두 개의 기둥.

01
계획(grilling)은 대화다.

Dynamic Workflow는 실행 중 사용자 입력을 받을 수 없습니다. 그래서 질문-대-질문으로 계획을 갈아내는 grilling은 워크플로우 바깥, 대화 안에서만 일어납니다.

02
문서는 부산물이 아니라 연료다.

계획에서 벼려진 용어는 실행의 기준이 되고, 회고의 배움은 다음 계획의 출발점이 됩니다. CONTEXT.md · ADR · retro log에 쌓입니다.

Install

두 줄이면 끝.

Claude Code 세션에서 GitHub 마켓플레이스를 추가하고 플러그인을 설치합니다.

Claude Code
/plugin marketplace add gyuha/forge
/plugin install forge@forge
로컬 클론에서 설치
/plugin marketplace add /path/to/forge
/plugin install forge@forge
업데이트 · 제거
/plugin marketplace update forge
/plugin uninstall forge@forge

스킬은 skills/<name>/SKILL.md에서 자동 발견됩니다 — 별도 설정 없음. 설치 후엔 fg-ask를 부르거나 "forge로 시작하자"라고 말하면 루프가 시작됩니다.

간단한 사용법

말 한마디로
루프를 돌립니다.

01
루프 시작

fg-ask를 부르거나 "forge로 시작하자", "새 작업"이라고 말하면 대화형 grilling이 계획을 갈아냅니다.

02
실행

fg-run이 계획을 Dynamic Workflow로 실행. 끝나면 계획의 목표에 대해 UAT를 돌려 STATUS.md에 검증 결과를 기록합니다.

03
회고

fg-learn이 배움을 문서로 승격. 사소하고 편차가 작으면 회고를 건너뛸 수도 있습니다.

04
봉인

"작업 완료"라고 하면 fg-done이 검증·회고를 확인하고 done/으로 아카이브 — 같은 작업은 다시 돌지 않습니다.

05
길 잃었을 때

"forge status"로 지금 위치를, "forge next"로 다음 한 걸음을 바로 실행. "이거 빨리 해줘"엔 fg-quick.

Shared state

상태는 파일로 흐른다.

모든 상태가 파일로 전달되어, 각 단계를 따로 불러도 흐름이 이어집니다. 단일 .forge/ 디렉터리가 휘발성 루프 상태와 git이 추적하는 영구 문서를 모두 담습니다.

repo/.forge/
.forge/
# 영구 문서 (git 추적)
├── CONTEXT.md        용어집
├── adr/0001-*.md      아키텍처 결정
├── retro/*.md         회고 로그
├── codebase/*.md      fg-map 맵
# 휘발성 상태 (gitignore)
├── backlog/<slug>.md  대기 중인 계획
├── plan.md           현재 사이클
├── run.md            계획 vs 실제
├── STATUS.md         실행/검증 상태
├── executed/         회고 대기
└── done/             봉인 아카이브
활성 슬롯은 언제나 하나

하나의 plan.md = 하나의 run.md = 하나의 봉인. 백로그가 여러 개면 fg-run이 선택 메뉴를 띄웁니다.

봉인 전 검증 게이트

run → verify → learn → done. verified:가 통과 상태여야만 fg-done이 봉인합니다.

브랜치 격리

기본 외 브랜치는 .forge/branch/<branch>/에서 동작. merge 후 fg-merge가 통합합니다.
